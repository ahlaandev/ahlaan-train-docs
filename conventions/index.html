User-Facing Copy Conventions ​

Rules for any string a human eventually reads: emails, invoice line items and titles, manifest exports (XLSX / CSV), WhatsApp summaries, Telegram ops alerts, and API validation messages returned to a caller.

Internal strings — code comments, JSDoc, Logger output, and Swagger prose descriptions — are not covered here and may use whatever punctuation reads best.

Rule: no em dash (—, U+2014) in user-facing strings ​

Use the ASCII hyphen - as a separator, or rephrase into separate sentences.

Why ​

SurfaceFailure mode with —
Email (HTML + text)Clients that fall back to a legacy single-byte charset render a replacement glyph instead of the dash. Indonesian prose has no em-dash convention, so it reads as noise even when it renders.
XLSX / CSV exportThe placeholder is outside the legacy code pages some spreadsheet clients fall back to, and nobody filtering a sheet types an em dash.
Telegram (MarkdownV2)Not reserved, so it silently passes — but it is inconsistent with every other separator in the alert, which must use the escaped \-.
Invoice line items / titlesCopied into accounting systems and searched by finance. - is typeable; — is not.
Validation messagesEchoed verbatim into client-side toasts and logs of unknown encoding.

How ​

  • Separator between a label and a value → ASCII hyphen surrounded by spaces: Custom booking - SUB → MED.
  • Parenthetical clause in prose → split into two sentences, or use a semicolon. Do not swap an em dash for a hyphen mid-sentence; it reads as a typo.
  • Absent value in a tabular export → the shared placeholder constant, never a literal.

The → arrow (U+2192) inside route labels is deliberate and stays. It is a value, not punctuation, and every surface that renders it is UTF-8.

Shared placeholder for absent values ​

The manifest surfaces — the XLSX export, the CSV export, and the WhatsApp booking summary — render a missing value through one exported constant:

ts
// src/modules/custom-booking/utils/booking-summary-shared.util.ts
export const EMPTY_VALUE_PLACEHOLDER = '-';

Import it — do not re-type the literal. It backs formatPureDate, resolveSex, and formatNationalityName (which the XLSX and CSV exports both consume), plus the airline / PNR / ID-number cells in the XLSX export and the return-date line of the WhatsApp booking summary, so every empty cell across all three surfaces stays identical.

Rendered strings, for reference ​

SurfaceFormat
Invoice line item (per-pax){Cabin class} {Pax type} {origin} - {destination} — e.g. Economy Adult Surabaya - Madinah. Cabin class is omitted when unknown.
Invoice line item (fallback lump){Cabin class} Ticket {origin} - {destination} — e.g. Economy Ticket Surabaya - Madinah
Invoice purpose, custom bookingCustom booking - {origin} → {destination}
Invoice purpose, OTA bookingFlight booking - {origin} → {destination} (BlockSeat booking - … for the BlockSeat variant)
Invoice purpose, mitra registration{TIER} partner {deposit|registration} - {registrationNumber}
Telegram terminal-failure alert🚨 *Terminal OTA error \- booking auto\-FAILED*
Manifest empty cell-

Persisted vs derived. Changing a rendered format only takes effect retroactively where the string is derived on read. purpose.title is rebuilt per request, so it normalizes everywhere at once. lineItems[].description is written into a Json column at invoice generation and is not backfilled, so historical rows keep whatever separator shipped at the time. When you change a persisted string, say so in the Swagger description and the guide — and never let a consumer parse it.

See Admin Invoice for the full invoice payload shape.

Enforcement ​

There is no lint rule. The guard is test coverage on the surfaces that matter:

  • src/modules/email/templates/otp-email.template.spec.ts asserts no OTP email body contains —.
  • src/modules/custom-booking/utils/booking-summary-shared.util.spec.ts pins EMPTY_VALUE_PLACEHOLDER to the ASCII hyphen.
  • src/modules/telegram-bot/telegram-bot.service.spec.ts pins the alert heading, including its MarkdownV2 escaping.

When you add a new user-facing surface, add the equivalent assertion.
