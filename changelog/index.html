Changelog ​

One entry per week (Monday to Sunday), newest first. An entry lists what the week changed for a client of the API: the web frontend, the mobile app, the admin panel and API partners. From then on, the routes it names keep their shape; a breaking change to one of them is written here as Breaking: with its reason.

  • Paths leave out the /api/v1 prefix.
  • A line that ends with Staging only is on staging and not yet in production. The marker is removed when the release reaches production.
  • Internal work (tests, deployment, logging, refactors) is not listed.

19 to 25 October 2026 ​

  • New public POST /landing/search prices the routes an admin sets, for a search page that takes orders over WhatsApp. Admins manage those prices under /admin/landing-route-price; applyToReverse writes the return direction too. See Landing search and Landing route prices.
  • Breaking: POST /landing/search requires passengerQuantities ({ adults, children, infants }, the ota/search shape) and answers 400 without it. Each class now carries ptcFareBreakdown, and the response echoes passengers. Why: the search prices a passenger group instead of a single seat. See Landing search.
  • Admins set the child and infant share of the adult landing price under /admin/landing-pricing-config. With no setting, a child pays 70% and an infant 0%. See Landing route prices.
  • The landing configuration chooses where its SAR to IDR rate comes from: idrRateSource is BANK_RATE (with idrRateBankCode and idrRateType) or GLOBAL_RATE. The rate is rounded up to a whole rupiah.
  • New public GET /landing/exchange-rate returns the rate the landing search uses: currency, IDR, source, bankCode, rateType and asOf. See Landing search.
  • New admin GET /admin/bank-exchange-rates and GET /admin/bank-exchange-rates/series list the recorded bank rates. On GET /admin/bank-exchange-rates, from and to (ISO date-time with time zone) select the rates in effect in that window. See Bank exchange rates.
  • New POST /scraper/bank-exchange-rates (API key) records the bank rates pushed by the rate scraper.
  • The automatic SAR rate can follow a bank series: GET and PATCH /admin/exchange-rate/settings take bankCode and bankRateType, with the new source BANK_RATE. See Exchange rate.
  • PATCH /admin/exchange-rate/settings with an invalid timeZone now answers with code INPUT_VALIDATION instead of UNCODED, and saves nothing. See Exchange rate.
  • Search and availability results served from cache are priced at the current exchange rate.
  • POST /admin/ota/cache/refresh also clears cached availability. See Cache status.

12 to 18 October 2026 ​

  • The admin custom-booking list returns ticketUploadedAt, the time the first ticket file arrived, and accepts it as a sortBy value. See Custom booking (admin).
  • The admin custom-booking list filters by capitalPriceMissing and counts those rows in meta.summary.capitalPriceMissingCount. Both need the custom-bookings:read-capital-markup permission; without it the filter answers 403. See Custom booking (admin).
  • When the cache fails, cached rule reads fall back to the database and admin writes still succeed.
  • In forced manual exchange-rate mode, the scheduled bank-rate scrape no longer runs. See Exchange rate.

5 to 11 October 2026 ​

  • Once an invoice has a payment on it (totalPaid above 0), every customer payment on that invoice is refused with 400, available-gateways returns no gateway, and payment-options is empty. See Payment gateways by currency.
  • After 5 wrong OTP codes, the codes still open stop working; the user requests a new one. A repeated Mitra registration request sends a new code. See Register and login.
  • Admin reports cut days on the app time zone (Asia/Riyadh), so daily figures can differ from before: invoice, payment, refund, wallet, OTA booking and organization reports. See Reports.
  • Organization transaction and wallet reports return the right rows for an organization without a wallet. See Organization reports.
  • The OTA report applies route to the previous period too. See Reports.
  • GET /admin/custom-booking/:id and POST /admin/custom-booking/:id/ticket report ordered ticket totals: totalTicketsExpected, totalTicketsUploaded, totalTicketsMissing and the matching totalInfantTickets… fields. See Custom booking (admin).
  • Shortfall amounts round half-up. See Shortfall settlements.

28 September to 4 October 2026 ​

  • POST /invoice/:id/generate-payment runs its checks before it reuses an open link. A Xendit link is reused on every IDR invoice. Two clicks at the same time get one link, or 409 after 20 seconds. See Payment gateways by currency.
  • GET /invoice/:id/available-gateways returns displayText per gateway: a title and description in Indonesian, English and Arabic. Admins edit it with GET and PATCH /admin/payment-gateway/:code/display-text. See Payment gateway.
  • Breaking: POST /ota/book creates the invoice in IDR. Its currency field is still accepted but deprecated, and no longer sets the invoice currency; BlockSeat invoices are IDR too. Choosing the other gateway at payment cancels the old link: 400 if it was already paid, 409 if it was paid for a different amount, 503 if the cancel cannot be confirmed. Why: the customer picks the currency by picking the gateway, Xendit in IDR or Moyasar in SAR. See Payment gateways by currency.
  • Each availableGateways entry carries currency and amount. Optional ?currency=IDR|SAR|USD filters the list; any other value answers 400.

21 to 27 September 2026 ​

  • GET /ota/routes serves the last good list (up to 7 days old) when the carrier fails. With nothing cached and a carrier failure in the last 60 seconds, it fails fast with 502. See OTA.
  • New public GET /ota/carrier-health for uptime monitors: 200 or 503, with a verdict for each side (rest and ota). ?check=rest or ?check=ota checks one side; any other value answers 400. Limited to 30 calls a minute.
  • Xendit payments settle even when the webhook does not arrive. A payment that arrives after the carrier deadline leaves the booking EXPIRED.
  • New gateway Moyasar: a hosted payment page for SAR invoices, added switched off. It lists CARDS in supportedMethods. See Payment gateway.
  • Breaking: Xendit and Moyasar payments return paymentMethod: "HOSTED_CHECKOUT"; Xendit returned BANK_TRANSFER before. New paidMethod and paidChannel say what the customer used. BANK_TRANSFER (Xendit) and CARD (Moyasar) are still accepted as input on generate-payment and wallet top-up. Why: the customer picks how to pay on the gateway's own page, so the stored method was wrong for QRIS, e-wallets and the rest.
  • SAR and USD booking invoices convert at the right rate, and their exchangeRateId is null.
