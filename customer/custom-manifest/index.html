Custom Booking Manifests ​

This guide covers the manifest file management endpoints for custom bookings. Manifests are documents (PDFs, images, etc.) attached to a custom booking. Each booking can have multiple manifest files. Files are stored in Cloudflare R2 (S3-compatible storage).

Quick Overview ​

FeatureDescription
UploadPOST /api/v1/custom-booking/:bookingId/manifests — Upload a manifest file
ListGET /api/v1/custom-booking/:bookingId/manifests — List all manifest files
DownloadGET /api/v1/custom-booking/:bookingId/manifests/:fileId/download — Download a file
Presigned URLGET /api/v1/custom-booking/:bookingId/manifests/:fileId/url — Get a temporary download URL
DeleteDELETE /api/v1/custom-booking/:bookingId/manifests/:fileId — Delete a manifest file
AccessBooking owner or Admin; guests via email + phone for all but delete
AuthGuest (email + phone) on upload/list/download/url; JWT required only for delete

Authentication ​

Four of the five manifest endpoints use OptionalAuthGuard and accept guest verification (the same email + phone that identify a guest elsewhere in the custom-booking flow): Upload (POST), List (GET), Download (GET .../download), and Presigned URL (GET .../url). On those, an authenticated caller sends a bearer token and a guest passes email and phone as query params matching the booking's contactPerson.

Only Delete (DELETE .../:fileId) is JWT-only — there is no guest path for deleting a manifest file.

http
Authorization: Bearer <your-jwt-token>

Guest (the four non-delete endpoints):

?email=user@example.com&phone=628515001838

Base URL ​

/api/v1

Access Control ​

RoleAccess
Booking OwnerFull access (upload, list, download, presigned URL, delete)
AdminFull access to any booking's manifests
Guest (email + phone)Upload, list, download, presigned URL — but not delete (JWT-only)
Other UsersDenied (403 Forbidden)
Guest (no credentials)Denied (401 Unauthorized)

1. Upload Manifest ​

Upload a file as a manifest for a custom booking.

No status change on upload. Manifest file upload does not change the booking status. The PENDING → UPLOADED_MANIFEST transition is now triggered by the passenger upload endpoint (PATCH /custom-booking/:id/passengers) — see Custom Booking → Update Passenger Manifest. Non-admin callers may only upload while the booking is in PENDING or UPLOADED_MANIFEST; uploads at any later status are rejected with 400.

http
POST /custom-booking/:bookingId/manifests
Content-Type: multipart/form-data
Authorization: Bearer <token>

Request ​

FieldTypeRequiredDescription
fileFileYesThe file to upload (multipart form field)
bookingIdstring (path)YesThe custom booking ID

cURL ​

bash
curl -X POST /api/v1/custom-booking/booking-123/manifests \
  -H "Authorization: Bearer <token>" \
  -F "file=@manifest.pdf"

Response (201) ​

json
{
  "id": "file-uuid-1",
  "filename": "manifest.pdf",
  "mimeType": "application/pdf",
  "size": 1024,
  "visibility": "PRIVATE",
  "entityType": "custom_booking_manifest",
  "entityId": "booking-123",
  "uploadedAt": "2026-04-11T10:00:00.000Z",
  "createdAt": "2026-04-11T10:00:00.000Z"
}

Error Responses ​

StatusDescription
400No file provided, or booking status is past UPLOADED_MANIFEST (non-admin callers)
403Not the booking owner
404Booking not found

2. List Manifests ​

List all manifest files for a custom booking. Returns files ordered by most recent first.

http
GET /custom-booking/:bookingId/manifests
Authorization: Bearer <token>

cURL ​

bash
curl -X GET /api/v1/custom-booking/booking-123/manifests \
  -H "Authorization: Bearer <token>"

Response (200) ​

json
[
  {
    "id": "file-uuid-2",
    "filename": "passenger-list.pdf",
    "mimeType": "application/pdf",
    "size": 2048,
    "status": "UPLOADED",
    "entityType": "custom_booking_manifest",
    "entityId": "booking-123",
    "createdAt": "2026-04-11T11:00:00.000Z"
  },
  {
    "id": "file-uuid-1",
    "filename": "manifest.pdf",
    "mimeType": "application/pdf",
    "size": 1024,
    "status": "UPLOADED",
    "entityType": "custom_booking_manifest",
    "entityId": "booking-123",
    "createdAt": "2026-04-11T10:00:00.000Z"
  }
]

Note: Manifests are also included in the booking detail response (GET /custom-booking/:id) under the manifests field.

3. Download Manifest ​

Download a specific manifest file as a binary attachment.

http
GET /custom-booking/:bookingId/manifests/:fileId/download
Authorization: Bearer <token>

cURL ​

bash
curl -X GET /api/v1/custom-booking/booking-123/manifests/file-uuid-1/download \
  -H "Authorization: Bearer <token>" \
  -o manifest.pdf

Response (200) ​

Returns the file as a binary response with headers:

Content-Type: application/pdf
Content-Disposition: attachment; filename="manifest.pdf"

Error Responses ​

StatusDescription
403Not the booking owner
404File or booking not found

4. Get Presigned URL ​

Get a temporary presigned download URL for a manifest file. Useful for client-side downloads or previewing in a browser.

http
GET /custom-booking/:bookingId/manifests/:fileId/url?expiresIn=3600
Authorization: Bearer <token>

Query Parameters ​

ParameterTypeRequiredDefaultDescription
expiresInnumberNo3600URL expiration time in seconds (max 86400)

cURL ​

bash
curl -X GET "/api/v1/custom-booking/booking-123/manifests/file-uuid-1/url?expiresIn=7200" \
  -H "Authorization: Bearer <token>"

Response (200) ​

json
{
  "url": "https://r2.example.com/presigned-url?X-Amz-Expires=7200&..."
}

5. Delete Manifest ​

Soft-delete a manifest file. The file record is marked as deleted in the database and removed from R2 storage.

http
DELETE /custom-booking/:bookingId/manifests/:fileId
Authorization: Bearer <token>

cURL ​

bash
curl -X DELETE /api/v1/custom-booking/booking-123/manifests/file-uuid-1 \
  -H "Authorization: Bearer <token>"

Response (200) ​

json
{
  "message": "Manifest file deleted"
}

Error Responses ​

StatusDescription
400Booking status forbids manifest deletion (status guard)
403Not the booking owner
404File or booking not found

Rate Limits ​

EndpointLimitWindow

Download (GET .../download)50 requests60 seconds

File Storage ​

Files are stored in Cloudflare R2 (S3-compatible object storage) with the following characteristics:

PropertyValue
VisibilityPRIVATE — files are never publicly accessible
Key formatUUID-based (e.g., a1b2c3d4-e5f6-7890-abcd-ef1234567890.pdf)
Max file sizeConfigured via r2Storage.maxFileSize
Allowed MIME typesConfigured via r2Storage.allowedMimeTypes
Soft deleteFile record marked DELETED, R2 object removed
