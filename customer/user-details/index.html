User Details Guide ​

This guide explains how to manage user profile details including personal information, nationality, and address.

Overview ​

The User Details endpoint allows authenticated users to store and manage their profile information such as name, date of birth, document details, nationality, and address. This information is used for passenger profiles when creating bookings.

Base URL: /api/v1

Authentication: Required (JWT Bearer token)

Endpoints ​

Get My User Details ​

Retrieve the current user's details.

http
GET /user-details
Authorization: Bearer <access_token>

Code Examples ​

JavaScript/TypeScript ​

typescript
// Get user details
async function getUserDetails(accessToken: string) {
  const response = await fetch('/api/v1/user-details', {
    method: 'GET',
    headers: {
      'Authorization': `Bearer ${accessToken}`
    }
  });
  
  if (response.status === 404) {
    return null; // User details not created yet
  }
  
  return await response.json();
}

// Create user details
async function createUserDetails(accessToken: string, data: CreateUserDetailsDto) {
  const response = await fetch('/api/v1/user-details', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${accessToken}`
    },
    body: JSON.stringify(data)
  });
  
  return await response.json();
}

// Update user details
async function updateUserDetails(accessToken: string, data: UpdateUserDetailsDto) {
  const response = await fetch('/api/v1/user-details', {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${accessToken}`
    },
    body: JSON.stringify(data)
  });
  
  return await response.json();
}

Common Use Cases ​

Submitting Indonesian KTP (National ID Card) ​

To submit an Indonesian KTP (Kartu Tanda Penduduk), use nationality: "ID", idType: "NATIONAL_ID", and the 16-digit KTP number as idNumber:

http
POST /user-details
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "firstName": "John",
  "middleName": "Michael",
  "lastName": "Doe",
  "dateOfBirth": "1990-01-15",
  "idType": "NATIONAL_ID",
  "idNumber": "3201234567890123",
  "countryOfResidence": "ID",
  "nationality": "ID",
  "address": "Jl. Sudirman No. 123, Jakarta 10220, Indonesia",
  "contactPersonEmail": "emergency@example.com",
  "contactPersonPhone": "+62812345678"
}

KTP-specific fields:

FieldValueDescription
nationality"ID"Indonesian nationality
idType"NATIONAL_ID"KTP document type
idNumber"3201234567890123"16-digit KTP number

Notes ​

  • Nationality Default: If nationality is not provided when creating user details, it defaults to "ID" (Indonesia).
  • One-to-One: Each user can only have one set of user details.
  • Contact Person: The contactPersonEmail and contactPersonPhone fields are stored as provided. When these fields are null, the system uses the user's own email and phone as fallback during booking operations.
  • Partner PIC backfill: When a partner registration is approved (mitra or B2B), the partner's PIC (person-in-charge) is used to backfill this contact-person — firstName/middleName/lastName (split from the PIC name), contactPersonEmail, and contactPersonPhone. This is fill-if-blank only: any field you have already set is preserved and never overwritten. If your account has no name yet, User.name is also rebuilt from the split PIC name.
  • Profile Endpoint: User details are also returned as part of the GET /auth/profile response under the contactPerson field. See Registration & Login Guide for the full profile response shape.
  • Alternative Update: All user detail fields (except contactPersonEmail and contactPersonPhone) can also be updated via PATCH /auth/profile/contact-person. See Registration & Login Guide for details.
