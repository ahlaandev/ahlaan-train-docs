Tickets & Email ​

This guide explains how to download tickets and resend confirmation/cancellation emails for B2C bookings.

Quick Overview ​

FeatureDescription
Download Tickets (Auth)GET /api/v1/ota/bookings/:id/tickets - PDF for authenticated users
Download Single TicketGET /api/v1/ota/bookings/:id/ticket - Public endpoint
Download by OTA RefGET /api/v1/tickets/:otaRef/download - Public endpoint
Resend Cancellation EmailPOST /api/v1/ota/bookings/:id/resend-cancellation-email
Resend Confirmation EmailPOST /api/v1/ota/bookings/:id/resend-confirmation-email

Base URL ​

/api/v1

Download Tickets (Authenticated) ​

Download all tickets for a booking as a single PDF file. Requires authentication and booking ownership.

http
GET /ota/bookings/:id/tickets
Authorization: Bearer <access_token>

Request Format ​

Headers

Authorization: Bearer {token}

Request Parameters ​

ParameterTypeRequiredDescription
idstringYesInternal booking ID (UUID)

Response ​

Content-Type: application/pdf

Content-Disposition: attachment; filename=tickets-{bookingId}.pdf

The response is a PDF file containing QR codes for all passengers on the booking.

Requirements ​

  • Booking must be in TICKETED status
  • User must own the booking (or be an admin)

Download Specific Ticket (Public) ​

Download a specific ticket PDF by ticket number and coupon number. This is a public endpoint - no authentication required.

http
GET /ota/bookings/:id/ticket?ticketNumber={ticketNumber}&couponNumber={couponNumber}

Request Parameters ​

ParameterTypeRequiredDescription
idstringYesInternal booking ID (UUID)
ticketNumberstringYesTicket number from OTA response
couponNumberstringYesCoupon number (usually "1")

Response ​

Content-Type: application/pdf

Content-Disposition: attachment; filename=ticket-{ticketNumber}.pdf

Use Case ​

This endpoint is designed for email links. Users can download tickets directly from confirmation emails without logging in.

Request Example ​

bash
GET /api/v1/ota/bookings/019bfef1-61fd-731c-9a77-2da9417f6da8/ticket?ticketNumber=4471110041159&couponNumber=1

Download Tickets by OTA Reference (Public) ​

Download all tickets for a booking using the OTA booking reference. This is a public endpoint - no authentication required.

http
GET /ota/tickets/:otaRef/download

Request Parameters ​

ParameterTypeRequiredDescription
otaRefstringYesOTA booking reference (5-6 characters)

Response ​

Content-Type: application/pdf

Content-Disposition: attachment; filename=tickets-{otaRef}.pdf

OTA Booking Reference Format ​

  • 5-6 alphanumeric characters (e.g., JVSJC3, XVW3NR, ABC12)
  • Provided in booking confirmation and emails
  • Different from the 6-character bookingCode

Use Case ​

This endpoint is ideal for:

  • Email links that don't require user login
  • Sharing tickets with third parties
  • Customer support scenarios

Request Example ​

bash
GET /api/v1/tickets/XVW3NR/download

Resend Cancellation Email ​

Resend cancellation email to specified recipients for a cancelled booking.

http
POST /ota/bookings/:id/resend-cancellation-email
Authorization: Bearer <access_token>
Content-Type: application/json

Request Format ​

Headers

Content-Type: application/json
Authorization: Bearer {token}

Request Parameters ​

ParameterTypeRequiredDescription
idstringYesInternal booking ID (UUID)

Request Body ​

json
{
  "emails": ["passenger@example.com", "admin@company.com"],
  "ccEmails": ["finance@company.com"],
  "bccEmails": ["records@company.com"],
  "segments": [
    {
      "flightDesignator": "HHR0080",
      "departure": "MKX",
      "arrival": "DMX",
      "departureDate": "2026-02-01"
    }
  ]
}

Request Body Parameters ​

FieldTypeRequiredDescription
emailsarrayYesPrimary email recipients
ccEmailsarrayNoCC recipients
bccEmailsarrayNoBCC recipients
segmentsarrayNoSpecific cancelled segments to include (all if omitted)

Segment Object ​

FieldTypeRequiredDescription
flightDesignatorstringYesFlight designator (e.g., HHR0080)
departurestringYesDeparture station code
arrivalstringYesArrival station code
departureDatestringYesDeparture date (YYYY-MM-DD)

Response Format ​

json
{
  "message": "Cancellation email sent successfully"
}

Requirements ​

  • Booking must be in CANCELLED status
  • User must own the booking
  • All email addresses must be valid

Code Examples ​

JavaScript/TypeScript (fetch) ​

typescript
// Download tickets for a booking (authenticated)
async function downloadTickets(bookingId: string): Promise<Blob> {
  const response = await fetch(`/api/v1/ota/bookings/${bookingId}/tickets`, {
    method: 'GET',
    headers: {
      Authorization: `Bearer ${getAccessToken()}`,
    },
  });

  if (!response.ok) {
    throw new Error(`Failed to download tickets: ${response.statusText}`);
  }

  return await response.blob();
}

// Download specific ticket (public - no auth)
async function downloadSpecificTicket(
  bookingId: string,
  ticketNumber: string,
  couponNumber: string,
): Promise<Blob> {
  const params = new URLSearchParams({
    ticketNumber,
    couponNumber,
  });

  const response = await fetch(
    `/api/v1/ota/bookings/${bookingId}/ticket?${params}`,
    {
      method: 'GET',
    },
  );

  if (!response.ok) {
    throw new Error(`Failed to download ticket: ${response.statusText}`);
  }

  return await response.blob();
}

// Download tickets by OTA reference (public - no auth)
async function downloadTicketsByOtaRef(otaRef: string): Promise<Blob> {
  const response = await fetch(`/api/v1/tickets/${otaRef}/download`, {
    method: 'GET',
  });

  if (!response.ok) {
    throw new Error(`Failed to download tickets: ${response.statusText}`);
  }

  return await response.blob();
}

// Save PDF blob to file
function savePdfBlob(blob: Blob, filename: string) {
  const url = window.URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = url;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  window.URL.revokeObjectURL(url);
  document.body.removeChild(a);
}

// Example: Download and save tickets
async function downloadAndSaveTickets(bookingId: string) {
  try {
    const pdfBlob = await downloadTickets(bookingId);
    savePdfBlob(pdfBlob, `tickets-${bookingId}.pdf`);
  } catch (error) {
    console.error('Download failed:', error);
    alert('Failed to download tickets. Please try again.');
  }
}

// Resend cancellation email
async function resendCancellationEmail(
  bookingId: string,
  emails: string[],
  options?: {
    ccEmails?: string[];
    bccEmails?: string[];
    segments?: Array<{
      flightDesignator: string;
      departure: string;
      arrival: string;
      departureDate: string;
    }>;
  },
) {
  const response = await fetch(
    `/api/v1/ota/bookings/${bookingId}/resend-cancellation-email`,
    {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        Authorization: `Bearer ${getAccessToken()}`,
      },
      body: JSON.stringify({
        emails,
        ccEmails: options?.ccEmails || [],
        bccEmails: options?.bccEmails || [],
        segments: options?.segments || [],
      }),
    },
  );

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Failed to resend email');
  }

  return await response.json();
}

Error Responses ​

400 Bad Request - Booking Not Ticketed ​

json
{
  "statusCode": 400,
  "message": "Tickets are not available for this booking",
  "error": "Bad Request"
}

Solution: Tickets are only available after booking reaches TICKETED status.

400 Bad Request - Missing Parameters ​

json
{
  "statusCode": 400,
  "message": "ticketNumber and couponNumber query parameters are required",
  "error": "Bad Request"
}

Solution: Provide both ticketNumber and couponNumber query parameters.

400 Bad Request - Invalid Email ​

json
{
  "statusCode": 400,
  "message": ["Invalid email address: invalid-email"],
  "error": "Bad Request"
}

Solution: Ensure all email addresses are valid format.

401 Unauthorized ​

json
{
  "statusCode": 401,
  "message": "Unauthorized",
  "error": "Unauthorized"
}

Solution: Provide valid JWT access token (for authenticated endpoints).

403 Forbidden - Not Your Booking ​

json
{
  "statusCode": 403,
  "message": "You do not have permission to access this booking",
  "error": "Forbidden"
}

Solution: Users can only access their own bookings.

404 Not Found ​

json
{
  "statusCode": 404,
  "message": "Booking not found",
  "error": "Not Found"
}

Solution: Verify the booking ID is correct.

404 Not Found - OTA Reference ​

json
{
  "statusCode": 404,
  "message": "Tickets not available for this booking reference",
  "error": "Not Found"
}

Solution: Verify the OTA reference is correct and booking is ticketed.

Email Integration Tips ​

Email Template Variables ​

When integrating email links, use these patterns:

Authenticated Download:

https://yourdomain.com/api/v1/ota/bookings/{bookingId}/tickets

Requires user to be logged in.

Public Download (Specific Ticket):

https://yourdomain.com/api/v1/ota/bookings/{bookingId}/ticket?ticketNumber={ticketNumber}&couponNumber={couponNumber}

No login required - use in emails.

Public Download (By OTA Ref):

https://yourdomain.com/api/v1/tickets/{otaRef}/download

No login required - simplest for email links.

CC/BCC Best Practices ​

javascript
// Good: Separate business logic from email routing
const emailData = {
  emails: ['passenger@example.com'], // Primary recipient
  ccEmails: ['travel-agent@company.com'], // Keep travel agent informed
  bccEmails: ['archive@company.com'], // Internal record keeping
};

// Avoid: Sending customer emails to BCC
// BCC recipients should not be visible to the customer

Batch Email Sending ​

javascript
// For multiple bookings, send emails in parallel
async function resendEmailsForBookings(bookingIds: string[]) {
  await Promise.all(
    bookingIds.map(id =>
      resendConfirmationEmail(id, ['admin@company.com'])
    )
  );
}

Custom Booking Ticket Email ​

For custom bookings (separate from the OTA flow above), the customer receives a one-off email when an admin uploads the issued ticket via POST /admin/custom-booking/:id/ticket.

PropertyValue
SubjectTiket Pemesanan Anda Telah Tersedia - {bookingCode}
TriggerAdmin uploads ticket; booking transitions WAITING_FOR_TICKET → COMPLETED in the same operation
RecipientcontactPerson.email on the custom booking
AttachmentThe uploaded ticket file (presigned R2 URL)
Body contentBooking code, route, departure date, passenger count, total price (SAR)
RetriesNone — the email provider guarantees delivery, and the queue job is submitted with attempts: 1.

Once this email is sent the booking is already COMPLETED; no customer action is required. If the email does not arrive within a few minutes, check spam first, then contact support with your booking code. Support can trigger a manual resend via the admin POST /admin/custom-booking/:id/resend-ticket-email endpoint, which re-queues the same ticket file without changing the booking status.
