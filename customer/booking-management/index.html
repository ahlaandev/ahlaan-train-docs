Booking Management ​

This guide explains how to view, cancel, and modify existing train bookings for B2C customers.

Booking Types ​

REGULAR Bookings ​

Standard bookings created with complete passenger information from the start.

  • Created with individual passenger details (names, documents, etc.)
  • Can be ticketed immediately after payment confirmation
  • Passenger data remains consistent throughout booking lifecycle

GROUP Bookings ​

Special bookings designed for B2B users who need to reserve capacity before collecting passenger details.

  • Created with passenger quantities only (no individual names)
  • Passenger names must be added later via modification type 4
  • Can only be ticketed after all passenger data is complete
  • Includes completion tracking to monitor progress

Payment Expiry & Time Limits ​

When a booking is created with paymentMethod: "BANK", a payment link is generated with a strict time limit. Understanding payment expiry is critical for customer UX.

How Payment Expiry Works ​

  1. Dynamic Calculation: Payment expiry (expiresAt) is calculated from OTA ticketTimeLimit minus a 2-minute buffer
  2. Default Fallback: 24 hours if no OTA time limits are available
  3. Auto-Cancellation: Unpaid bookings are automatically cancelled when payment expires

Payment Response Format ​

The payment response includes enhanced expiry information:

Countdown Timer Implementation (React Example) ​

tsx
import { useState, useEffect } from 'react';

export function PaymentCountdown({ expiresAt }: { expiresAt: string }) {
  const [timeLeft, setTimeLeft] = useState(0);

  useEffect(() => {
    const update = () => {
      const now = new Date().getTime();
      const expiry = new Date(expiresAt).getTime();
      setTimeLeft(Math.max(0, expiry - now));
    };

    update();
    const interval = setInterval(update, 1000);
    return () => clearInterval(interval);
  }, [expiresAt]);

  const minutes = Math.floor(timeLeft / 60000);
  const seconds = Math.floor((timeLeft % 60000) / 1000);

  const getColor = () => {
    if (minutes >= 10) return 'green';
    if (minutes >= 5) return 'orange';
    return 'red';
  };

  if (timeLeft === 0) {
    return <div style={{ color: 'red' }}>⛔ Payment expired</div>;
  }

  return (
    <div style={{ color: getColor() }}>
      ⏰ Complete payment within {minutes}:{seconds.toString().padStart(2, '0')}
    </div>
  );
}

Expiry Enforcement ​

The system uses two mechanisms to enforce payment expiry:

  1. BullMQ Scheduled Jobs: Each booking gets a delayed job that auto-cancels at expiry time
  2. Xendit Webhooks: Payment gateway sends expiry notifications as backup

This ensures bookings are cancelled even if webhooks are delayed or missed.

Handling Expired Payments ​

When a payment expires:

  • Booking status changes to CANCELLED
  • Payment status changes to EXPIRED
  • Customer cannot complete payment for that booking
  • Customer must create a new booking

Best Practices ​

  1. Always show countdown timer - Don't hide the urgency from customers
  2. Update every second - Smooth countdown creates urgency
  3. Use color coding - Green → Orange → Red progression
  4. Handle expired state - Show clear message when time runs out
  5. Auto-refresh status - Poll every 30 seconds to catch early expiry
  6. Multiple browser tabs - Use localStorage to sync countdown across tabs

GROUP Booking Management ​

GROUP bookings allow B2B users to reserve capacity before collecting passenger details. They have special handling requirements.

Creating a GROUP Booking ​

GROUP bookings are created via the booking creation endpoint with bookingType: "GROUP":

json
{
  "bookingType": "GROUP",
  "passengerQuantities": {
    "adults": 20,
    "children": 5,
    "infants": 2
  },
  "contactPerson": {
    "firstName": "Ahmed",
    "lastName": "Agent",
    "email": "ahmed@travelagency.com",
    "phone": "+966501234567"
  }
  // ... other booking fields
}

Response for GROUP Booking:

json
{
  "bookingCode": "GRP789X",
  "bookingType": "GROUP",
  "status": "PENDING",
  "passengerCount": 27,
  "passengers": {
    "type": "GROUP",
    "quantities": { "adults": 20, "children": 5, "infants": 2 }
  },
  "completionStatus": {
    "status": "INCOMPLETE",
    "completedCount": 0,
    "requiredCount": 27,
    "percentage": 0,
    "requiredAction": "ADD_PASSENGER_NAMES"
  },
  "actions": {
    "requiredAction": "PAY",
    "availableActions": ["PAY", "CANCEL"]
  }
}

Adding Passenger Names (Type 4) ​

After payment confirmation, use modification type 4 to add passenger names.

CRITICAL: You MUST provide exactly adults + children + infants passengers.

bash
PATCH /ota/bookings/:id/modify
Content-Type: application/json

{
  "modificationType": "4",
  "passengers": [
    {
      "title": "MR",
      "firstName": "Mohammed",
      "lastName": "Al-Ahmad",
      "passengerTypeCode": "ADT",
      "idType": "Passport",
      "idNumber": "A1234567",
      "idExpirationDate": "2030-01-01",
      "nationality": "SA",
      "dateOfBirth": "1985-05-15",
      "gender": "Male"
    }
    // ... 26 more passengers (exact count required: 20 + 5 + 2 = 27)
  ]
}

Response After Adding All Passengers:

json
{
  "success": true,
  "message": "Booking modified successfully",
  "booking": {
    "bookingCode": "GRP789X",
    "status": "TICKETING_IN_PROGRESS",
    "passengerCompletionCount": 27,
    "passengerCompletionPercentage": 100,
    "isPassengerDataComplete": true
  }
}

Auto-Ticketing: Once all passengers are added (isPassengerDataComplete: true), ticketing is triggered automatically. No separate ticketing request is needed.

Completion Tracking ​

Monitor GROUP booking completion via the API response:

List View - Partial Completion:

json
{
  "bookingCode": "GRP789X",
  "bookingType": "GROUP",
  "status": "CONFIRMED",
  "completionStatus": {
    "status": "PARTIAL",
    "completedCount": 15,
    "requiredCount": 27,
    "percentage": 56,
    "requiredAction": "ADD_PASSENGER_NAMES"

Detail View - Full Progress:

json
{
  "passengers": {
    "type": "GROUP",
    "quantities": { "adults": 20, "children": 5, "infants": 2 },
    "names": [ /* 15 passengers */ ],
    "progress": {
      "total": 27,
      "completed": 15,

    }
  }
}

GROUP Booking Rules ​

RuleDescription
Passenger CountMust provide exactly adults + children + infants passengers
All-or-NothingCannot add partial names - must add ALL at once
Auto-TicketingTriggered automatically when all names are added
ExpiryUncompleted GROUP bookings expire after 72 hours
ModificationOnly type 4 (Add Names) is relevant for GROUP bookings

Error: Passenger Count Mismatch ​

If you provide an incorrect number of passengers:

json
{
  "statusCode": 400,
  "message": "An error occurred"
}

Solution: Ensure the passengers array length equals adults + children + infants from the original booking.

// List user bookings with pagination
async function getUserBookings(
  page = 1,
  limit = 10,
  filters?: {
    status?: string;
    departureDateFrom?: string;
    departureDateTo?: string;
    bookingCode?: string;
    sortBy?: string;
    sortOrder?: 'asc' | 'desc';
  },
): Promise<PaginatedBookingsResponse> {
  const params = new URLSearchParams({
    page: String(page),
    limit: String(limit),
    ...(filters?.status && { status: filters.status }),
    ...(filters?.departureDateFrom && {
      departureDateFrom: filters.departureDateFrom,
    }),
    ...(filters?.departureDateTo && {
      departureDateTo: filters.departureDateTo,
    }),
    ...(filters?.bookingCode && { bookingCode: filters.bookingCode }),
    ...(filters?.sortBy && { sortBy: filters.sortBy }),
    ...(filters?.sortOrder && { sortOrder: filters.sortOrder }),
  });

  const response = await fetch(`/api/v1/ota/bookings?${params}`, {
    method: 'GET',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getAccessToken()}`,
    },
  });

  if (!response.ok) {
    throw new Error(`Failed to fetch bookings: ${response.statusText}`);
  }

  return await response.json();
}

// Cancel booking
async function cancelBooking(bookingId: string) {
  const response = await fetch(`/api/v1/ota/bookings/${bookingId}/cancel`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getAccessToken()}`,
    },
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Failed to cancel booking');
  }

  return await response.json();
}

// Modify booking (Type 4: Add passenger names)
async function addPassengerNames(
  bookingId: string,
  passengers: PassengerDto[],
) {
  const response = await fetch(`/api/v1/ota/bookings/${bookingId}/modify`, {
    method: 'PATCH',
    headers: {
      'Content-Type': 'application/json',
      Authorization: `Bearer ${getAccessToken()}`,
    },
    body: JSON.stringify({
      modificationType: '4',
      passengers,
    }),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Failed to modify booking');
  }

  return await response.json();
}

// Example: Display bookings list (using new nested structure)
async function displayBookings() {
  const { data, meta } = await getUserBookings(1, 10, {
    sortBy: 'departureDate',
    sortOrder: 'asc',
  });

  console.log(`Showing ${data.length} of ${meta.total} bookings (Page ${meta.page} of ${meta.totalPages})`);

  // Use pagination convenience flags
  if (meta.hasNext) {
    console.log('Load more available →');
  }

  data.forEach((booking) => {
    // Access nested trip structure
    const originName = booking.trip.origin.name || booking.trip.origin.code;
    const destName = booking.trip.destination.name || booking.trip.destination.code;

    console.log(`
      ${booking.bookingCode} - ${booking.status} ${booking.serviceClassName ? `(${booking.serviceClassName})` : ''}
      ${originName} → ${destName}
      Departure: ${new Date(booking.trip.departureDateTime).toLocaleString()}
      Passengers: ${booking.passengers.count}
      Total: ${booking.pricing.SAR.total.amount} SAR
      Next Action: ${booking.actions.requiredAction || 'None'}
    `);
  });
}

Validation Rules ​

RuleDescription
OwnershipUsers can only view/modify their own bookings
Admin AccessAdmins can view any booking using the same endpoints
CancellationOnly CONFIRMED and TICKETED bookings can be cancelled
RefundableCheck fare's isRefundable property before cancelling
ModificationType 4 (Add Names) requires GROUP booking status
Date FormatAll dates must be in YYYY-MM-DD format

Error Responses ​

401 Unauthorized ​

json
{
  "statusCode": 401,
  "message": "Unauthorized",
  "error": "Unauthorized"
}

Solution: Provide valid JWT access token.

403 Forbidden - Not Your Booking ​

json
{
  "statusCode": 403,
  "message": "You do not have permission to access this booking",
  "error": "Forbidden"
}

Solution: Users can only access their own bookings.

404 Not Found ​

json
{
  "statusCode": 404,
  "message": "Booking not found",
  "error": "Not Found"
}

Solution: Verify the booking ID or code is correct.

400 Bad Request - Cannot Cancel ​

json
{
  "statusCode": 400,
  "message": "Booking cannot be cancelled in current status",
  "error": "Bad Request"
}

Solution: Only CONFIRMED and TICKETED bookings can be cancelled.

400 Bad Request - Non-Refundable Fare ​

json
{
  "statusCode": 400,
  "message": "This fare type cannot be cancelled (SAVER fares are non-refundable)",
  "error": "Bad Request"
}

Solution: Check isRefundable before allowing cancellation in the UI.

400 Bad Request - Invalid Modification ​

json
{
  "statusCode": 400,
  "message": "Invalid modification type for current booking status",
  "error": "Bad Request"
}

Solution: Check the modification rules table for allowed types per status.
