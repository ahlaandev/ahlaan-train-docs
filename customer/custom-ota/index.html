Custom OTA Guide ​

This guide covers the Custom OTA endpoints. Custom-OTA and custom-booking run a decoupled pricing path that is independent of /v1/ota/search, /v1/ota/book/calculate and /v1/ota/book: they call the supplier directly and use only two inputs — the supplier's raw per-passenger totalFare.amount (from each ptcfareBreakdowns item, keyed by passengerTypeQuantity.code) and the route's CustomRoutePrice.priceReducer. No HHR markup, no HHR tax, and no B2B/customer pricing rules ever influence a custom price.

supplierPerPax_T = ptcfareBreakdowns[T].totalFare.amount      (raw supplier fare; 1/1/1 probe ⇒ qty 1 ⇒ per-pax)  → PAYABLE basis
retailPerPax_T   = perPassenger.totalPrice                    (raw supplier + HHR markup + HHR tax)            → STRIKETHROUGH basis

adult  payable = floor( supplierPerPax_ADT − priceReducer )                                  (whole riyal, per pax)
child  payable = floor( supplierPerPax_CHD − priceReducer × (supplierPerPax_CHD / supplierPerPax_ADT) )
infant payable = floor( supplierPerPax_INF − priceReducer × (supplierPerPax_INF / supplierPerPax_ADT) )
finalPrice     = Σ legs Σ pax  payable × realCount            (exact sum of integer per-pax shares)
strikethrough  = Σ retailPerPax × realCount    (retail price incl HHR markup + HHR tax, BEFORE the reducer)   (originalFinalPrice)

The priceReducer is an adult discount, allocated across passengers by their per-pax fare ratio so the quote, the booking and the invoice all agree on the same numbers. Each per-pax payable is floored to a whole riyal (owner rule: the integer floor is applied at the per-pax level, so a sub-1-riyal fare floors to 0). finalPrice is the exact integer sum of those shares, so Σ(payable × realCount) equals finalPrice with no sub-riyal residual. The reducer is resolved per leg (each leg keyed by its own route + cabin class). Even a route with no active priceReducer is priced at the raw supplier fare and floored per passenger, so the quote still matches its booking.

Tax model. The payable is the supplier totalFare.amount minus the reducer — free of HHR markup AND HHR tax. The supplier's own VAT stays inside totalFare (it is part of what we pay the supplier, not a tax our system levies, so there is no double tax). The strikethrough is a separate, larger number: the retail price of the same probe fare — supplier totalFare plus HHR markup plus HHR tax (perPassenger.totalPrice) × the real counts, before the reducer. It is not the raw supplier total. (Because the probe is 1/1/1 under the regular credential, this retail strikethrough need not equal a real /ota/search quote, which for 11+ seated passengers prices under the wholesale credential.)

Business class (owner 2026-06-15) ​

The model above applies to ECONOMY (and any non-business) class. BUSINESS class is the exception: it is priced with the Custom Markup + Custom Tax rules instead of the reducer, and it carries no strikethrough.

base_T   = supplierPerPax_T                                  (raw supplier fare, markup-free)
marked_T = base_T + customMarkup        (PERCENTAGE: base × value/100 ; FIXED: amount in SAR, IDR÷sellRate)
taxable  = taxBasis === 'BASE_PRICE' ? base_T : marked_T
tax_T    = customTax    (PERCENTAGE: taxable × rate/100 ; FIXED: SAR amount)
payable_T = floor(marked_T) + floor(tax_T)                   (subtotal + tax, each whole riyal → exact)
finalPrice    = Σ legs Σ pax  payable_T × realCount
originalPrice = 0                                            (no strikethrough)
fare type     = "STANDARD"                                   (not "PROMO")
  • No reducer is applied to business class. If no custom-markup / custom-tax rule matches the route, the component is 0, so a business fare with no rules sells at the raw supplier fare (still type: STANDARD, originalFinalPrice = 0).
  • A zero-base passenger is markup-AND-tax-free (owner 2026-06-15): any passenger whose supplier base fare is 0 (e.g. a free infant) is charged 0 — no custom markup or tax is levied, including a FIXED amount.
  • The custom tax is broken out on the invoice (subtotal + tax = total, ZATCA), even though the API response collapses to a single finalPrice (totalTax = 0 in the response block).
  • Mixed-class round trips are priced per leg: a business leg uses markup + tax with no strikethrough, an economy leg uses the reducer with a retail strikethrough; the overall originalFinalPrice is the sum of the per-leg strikethroughs (a business leg contributes 0).

Supplier probe & seat availability ​

The supplier drops any low-fare search whose adult + children count is >= 11 when the departure is <= 3 days away (it returns no result). To stay independent of the group rules and return a result for every size and date, custom-OTA / custom-booking always send the supplier a fixed 1 adult / 1 child / 1 infant probe body under the regular (retail) credential, then apply the real requested counts in our own layer:

  • Pricing reads each passenger type's raw totalFare.amount from the probe (qty 1 ⇒ per-pax). The real adultCount / childCount / infantCount multiply those per-pax fares (finalPrice = Σ payable × real count). Per-adult prices are independent of the count.
  • Credential is always regular/retail (1/1/1 is below the group threshold) — the same supplier fare for every passenger combination.
  • Seat availability is enforced by us, because the 1/1/1 probe stops the supplier rejecting an over-capacity request:
    • Search marks each cabin bookable: false when its remaining availableSeats cannot fit the requested seated passengers (adults + children; infants are lap and take no seat).
    • POST /custom-ota/book/calculate and POST /custom-booking reject an over-capacity request with HTTP 400 and code INSUFFICIENT_SEATS (context: { requested, available, leg }).

A cabin with an unknown/zero availableSeats is treated as bookable (a present fare implies availability) — only a credible positive seat count that is exceeded blocks.

Passenger counts in the response ​

The supplier is always probed with 1/1/1, but the response is scaled to the real requested counts. Do not expect the probe numbers to surface in the breakdown:

  • metadata.passengers echoes the fixed 1/1/1 probe counts ({ adults: 1, children: 1, infants: 1 }), not the requested counts. The real requested counts surface only in ptcFareBreakdown[].quantity (below) — do not read the requested passenger mix from metadata.passengers.
  • metadata.farePreferences is always present as { preferences: [] } (no fare-preference filtering is applied on the custom path).
  • ptcFareBreakdown[].quantity is the real requested count per passenger type (e.g. 10 for a 10-adult search), not the probe's 1. The per-pax fare comes from the 1/1/1 probe; subtotal = perPassenger × quantity and finalPrice = Σ subtotal then use the real counts.
  • Passenger types the request did not ask for are dropped from the breakdown (the probe always returns ADT + CHD + INF rows; only requested types are charged and shown).
  • This is exactly how a search for >= 11 seated passengers (adults + children) within 3 days of departure returns a result at all: a direct supplier call at the real count would be dropped (see above), so the 1/1/1 probe fetches the fare and the breakdown is scaled up afterwards. A breakdown quantity larger than any single-search group limit is therefore expected, not a bug.

  • Search: for each (route, cabin class) the reducer is allocated across the fare's passengers (ptcFareBreakdown[]) by per-pax fare ratio; each per-pax share is floored to a whole riyal and finalPrice becomes their exact integer sum, the fare becomes type: "PROMO", and the retail price (raw supplier + HHR markup + HHR tax, pre-reducer) is preserved in originalFinalPrice (the strikethrough). pricePerAdult and the ptcFareBreakdown lines are reduced in lock-step so they re-sum to the reduced total.
  • Calculate: the reducer is resolved per leg (outbound + return, see below) and allocated per passenger; the pricing.* block collapses to the reduced payable — baseFare == totalPrice and totalTax = 0 — and the ptcFareBreakdown lines are reduced to match, so the per-passenger breakdown does re-sum to the reduced totalPrice.

No meanPricePerAdult formula. Earlier versions of custom-ota priced from scraper means (effectivePrice = max(0, meanPricePerAdult − priceReducer)) with a synthetic child = adult × 0.5 / infant = free rule. That model no longer applies — pricing comes from the raw supplier ptcfareBreakdowns. Child/infant fares follow the supplier breakdown; the only per-pax adjustment is the reducer's fare-ratio allocation (and a CHD 0.5 / INF 0 fallback when a leg carries no adult).

Pricing Rules ​

Pricing is the OTA-pipeline result with the priceReducer allocated per passenger by fare ratio. The payable is the supplier cost (HHR markup + HHR tax excluded; the supplier's own VAT is kept, as it is cost) minus that allocation.

  • Markup / tax: the per-pax fare is taken from perPassenger.totalFare (supplier cost + HHR markup, no HHR tax) and the HHR markup is stripped via factor = otaTotalFare / Σ subtotal.totalFare, leaving the bare supplier cost. So the payable carries neither HHR markup nor HHR tax. The pricing.* block collapses to totalTax = 0 and baseFare == totalPrice (no HHR tax line). The supplier's VAT stays inside the cost — it is what we pay the supplier, not a tax our system levies, so there is no double tax.
  • Adult vs child / infant: the reducer is an adult discount. Each adult pays ppFare − reducer; each child / infant pays ppFare − reducer × (ppFare / ppFareAdult). There is no custom × 0.5 child discount — the ratio comes from the OTA fares themselves. When a leg has no adult, the ratio falls back to CHD 0.5 / INF 0.
  • Reducer scope: resolved per leg and allocated per passenger. Even a 0 reducer still prices at supplier cost and floors the total to a whole riyal, so a no-reducer quote still matches its booking.

Per-leg reducer ​

The reducer is resolved independently for each leg and allocated within that leg:

outbound: reducer(origin → destination, outboundClass)
return:   reducer(destination → origin, returnClass)   // ROUND_TRIP only
  • The return leg reverses origin/destination and uses the return cabin class.
  • Each leg's cabin class comes from the OTA-priced result (trip.outboundFlight.className / trip.returnFlight.className). A leg with no resolvable class contributes 0.
  • ONE_WAY uses the outbound leg only.

Per-currency derivation ​

The per-pax payable is computed in SAR; the grand total is floored to a whole riyal and the other currencies are derived from it:

CurrencyDerivation
SARfloor( Σ legs Σ pax (ppFare − reducer × ratio) × qty )
IDRfloor( finalSAR × sellRate )
USDfinalSAR ÷ 3.75

child payable:    10 − (20 × 0.10)   =   8  ×1 =   8
──────────────────────────────────────────────────
finalPrice.SAR = floor(160 + 8)      = 168

Each adult is shaved by the full reducer; the child is shaved by the reducer scaled to its fare share (10% of an adult). The per-passenger lines (80, 8) re-sum to the floored total 168.

Business class (custom markup + custom tax) ​

A BUSINESS-class leg does not use the reducer. It is priced from the Custom Markup + Custom Tax rules resolved for that (origin, destination, BUSINESS, tripType) — most-specific rule wins, ties broken by priority. Per passenger:

payable = floor(base + customMarkup) + floor(customTax)
  • base is the supplier cost (HHR markup stripped, same as ECONOMY).
  • customMarkup = PERCENTAGE of base, or a FIXED amount (converted to SAR if the rule currency is IDR).
  • customTax is applied on BASE_PRICE (base only) or FINAL_AMOUNT (base + markup), per the tax rule's taxBasis.
  • There is no strikethrough (originalFinalPrice = 0, pricePerAdult.originalAmount = 0) and the tax is broken out in ptcFareBreakdown so the invoice can show subtotal + tax = total (ZATCA).
  • A zero-base passenger (e.g. a free infant, supplier base 0) is markup- and tax-free and charged 0, even under a FIXED rule.

Worked example (BUSINESS, 1 adult, markup 10%, tax 15% on FINAL_AMOUNT):

supplier base per adult:            524 SAR
+ custom markup 10%:                524 × 1.10        = 576.4
+ custom tax 15% (FINAL_AMOUNT):    576.4 × 1.15      = 662.86
──────────────────────────────────────────────────
payable per adult = floor(662.86)                     = 662
  → ptcFareBreakdown: totalFare 576 (base+markup), totalTax 86, totalPrice 662

A round trip may mix classes — each leg is priced by its own class (a BUSINESS outbound + ECONOMY return sums a markup+tax leg with a reducer leg). ONE_WAY prices the outbound leg only.

Exchange Rate ​

Prices are provided in three currencies:

CurrencyConversion
SARBase currency
IDRSAR × sellRate (from ExchangeRateService)
USDSAR ÷ 3.75 (fixed peg)

The exchange rate is the live system rate (same source as regular OTA). If no rate is available, search returns the raw OTA result without applying the reducer (it cannot convert the reducer into IDR/USD).

Error Responses ​

Both endpoints return the unified OTA error envelope (same contract as /v1/ota/book/calculate): a stable machine-readable code, a category, a retryable hint, and a context object.

400 Bad Request — Validation ​

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": [
    "fareId must be a string",
    "origin must be a string",
    "destination must be a string",
    "departureDate must be a valid ISO 8601 date string"
  ],
  "code": "INPUT_VALIDATION",
  "category": "VALIDATION",
  "retryable": false,
  "context": {
    "fields": [
      { "path": "fareId", "constraint": "isString", "message": "fareId must be a string" }
    ]
  }
}

400 Bad Request — Fare No Longer Available ​

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "FareId \"SAB2MINECO\" not found in search results. The flight may no longer be available. Please search again.",
  "code": "FARE_UNAVAILABLE",
  "category": "INVENTORY_MISMATCH",
  "retryable": true,
  "cause": "likely_inventory_change",
  "context": { "fareId": "SAB2MINECO", "leg": "OUTBOUND" }
}

retryable: true with category: "INVENTORY_MISMATCH" means the client should re-run /custom-ota/search and retry with a fresh fare.

Returned when book/calculate is called without a valid token.

json
