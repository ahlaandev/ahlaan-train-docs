Custom OTA Guide ​

This guide covers the Custom OTA endpoints. Search results, seat availability, and pricing all come from the live OTA pipeline — identical to /v1/ota/search and /v1/ota/book/calculate. The divergence is the per-passenger reducer alignment: the route's CustomRoutePrice.priceReducer is an adult discount, allocated across passengers by their per-pax fare ratio so the quote, the booking and the invoice all agree on the same numbers.

factor   = otaTotalFare / Σ subtotal.totalFare       (strip HHR markup)
ppFare_T = perPassenger.totalFare_T × factor         (supplier cost: no HHR markup/tax)

adult  payable = floor( ppFare_ADT − priceReducer )                          (whole riyal, per pax)
child  payable = floor( ppFare_CHD − priceReducer × (ppFare_CHD / ppFare_ADT) )  (whole riyal, per pax)
infant payable = floor( ppFare_INF − priceReducer × (ppFare_INF / ppFare_ADT) )  (whole riyal, per pax)
finalPrice     = Σ legs Σ pax  payable × qty            (exact sum of integer per-pax shares)
strikethrough  = full OTA grand total (incl HHR markup + HHR tax)   (originalFinalPrice)

Each passenger is reduced from the bare supplier cost — perPassenger.totalFare (supplier cost + HHR markup, no HHR tax) with the HHR markup stripped via the factor — and the resulting per-pax payable is floored to a whole riyal (owner rule: the integer floor is applied at the per-pax level, so a sub-1-riyal fare floors to 0). finalPrice is then the exact integer sum of those shares — Σ(payable × qty) equals finalPrice with no sub-riyal residual. The reducer is resolved per leg (each leg keyed by its own route + cabin class). Even a route with no active priceReducer is priced at supplier cost and floored per passenger, so the quote still matches its booking.

Tax model. The payable is free of HHR markup AND HHR tax. It is the supplier cost minus the reducer. The supplier's own VAT is kept — it is part of what we pay the supplier (cost), not a tax our system levies, so there is no double tax. The full OTA price (with HHR markup + HHR tax) remains the strikethrough.

Data Flow ​

                ┌──────────────────────┐
   request ────▶│   OTA pipeline       │  same fares / seats / tax
                │  (/v1/ota/* logic)   │  as regular OTA
                └──────────┬───────────┘
                           │ per-pax supplier cost (perPassenger.totalFare × factor)
                           ▼
                ┌──────────────────────┐     ┌────────────────────┐
                │  CustomRoutePrice    │────▶│ allocateReducerPer │
                │  .priceReducer (SAR) │     │ Pax (per leg)      │
                └──────────────────────┘     └─────────┬──────────┘
                                                        │ adult: floor(ppFare − reducer)
                                                        │ child/inf: floor(− reducer × ratio)
                                                        ▼
                                  finalPrice.SAR = Σ (integer per-pax × qty)
                                  IDR = floor(finalSAR × sellRate)
                                  USD = finalSAR ÷ 3.75
                              (no HHR tax line: totalTax = 0, baseFare == totalPrice)
  • Search: for each (route, cabin class) the reducer is allocated across the fare's passengers (ptcFareBreakdown[]) by per-pax fare ratio; each per-pax share is floored to a whole riyal and finalPrice becomes their exact integer sum, the fare becomes type: "PROMO", and the raw tax-inclusive OTA total is preserved in originalFinalPrice (the strikethrough). pricePerAdult and the ptcFareBreakdown lines are reduced in lock-step so they re-sum to the reduced total.
  • Calculate: the reducer is resolved per leg (outbound + return, see below) and allocated per passenger; the pricing.* block collapses to the reduced payable — baseFare == totalPrice and totalTax = 0 — and the ptcFareBreakdown lines are reduced to match, so the per-passenger breakdown does re-sum to the reduced totalPrice.

No meanPricePerAdult formula. Earlier versions of custom-ota priced from scraper means (effectivePrice = max(0, meanPricePerAdult − priceReducer)) with a synthetic child = adult × 0.5 / infant = free rule. That model no longer applies — pricing comes from the OTA pipeline. Child/infant fares follow the OTA breakdown; the only per-pax adjustment is the reducer's fare-ratio allocation (and a CHD 0.5 / INF 0 fallback when a leg carries no adult).

1. Search Trains ​

Search for available trains via the OTA pipeline. Returns flights grouped by cabin class, with the route's priceReducer overlaid on each fare.

http
POST /custom-ota/search
Content-Type: application/json

{
  "origin": "DMX",
  "destination": "JXD",
  "departureDate": "2026-06-15",
  "tripType": "ONE_WAY",
  "passengerQuantities": {
    "adults": 1,
    "children": 0,
    "infants": 0
  }
}

Pricing Rules ​

Pricing is the OTA-pipeline result with the priceReducer allocated per passenger by fare ratio. The payable is the supplier cost (HHR markup + HHR tax excluded; the supplier's own VAT is kept, as it is cost) minus that allocation.

  • Markup / tax: the per-pax fare is taken from perPassenger.totalFare (supplier cost + HHR markup, no HHR tax) and the HHR markup is stripped via factor = otaTotalFare / Σ subtotal.totalFare, leaving the bare supplier cost. So the payable carries neither HHR markup nor HHR tax. The pricing.* block collapses to totalTax = 0 and baseFare == totalPrice (no HHR tax line). The supplier's VAT stays inside the cost — it is what we pay the supplier, not a tax our system levies, so there is no double tax.
  • Adult vs child / infant: the reducer is an adult discount. Each adult pays ppFare − reducer; each child / infant pays ppFare − reducer × (ppFare / ppFareAdult). There is no custom × 0.5 child discount — the ratio comes from the OTA fares themselves. When a leg has no adult, the ratio falls back to CHD 0.5 / INF 0.
  • Reducer scope: resolved per leg and allocated per passenger. Even a 0 reducer still prices at supplier cost and floors the total to a whole riyal, so a no-reducer quote still matches its booking.

Per-leg reducer ​

The reducer is resolved independently for each leg and allocated within that leg:

outbound: reducer(origin → destination, outboundClass)
return:   reducer(destination → origin, returnClass)   // ROUND_TRIP only
  • The return leg reverses origin/destination and uses the return cabin class.
  • Each leg's cabin class comes from the OTA-priced result (trip.outboundFlight.className / trip.returnFlight.className). A leg with no resolvable class contributes 0.
  • ONE_WAY uses the outbound leg only.

Per-currency derivation ​

The per-pax payable is computed in SAR; the grand total is floored to a whole riyal and the other currencies are derived from it:

CurrencyDerivation
SARfloor( Σ legs Σ pax (ppFare − reducer × ratio) × qty )
IDRfloor( finalSAR × sellRate )
USDfinalSAR ÷ 3.75

Worked example (ECONOMY, 2 adults + 1 child, reducer 20 SAR) ​

Supplier cost per adult (HHR markup + HHR tax excl): 100 SAR
Supplier cost per child  (HHR markup + HHR tax excl):  10 SAR
CHD:ADT per-pax ratio:                              10 / 100 = 0.10
──────────────────────────────────────────────────
adult payable:   100 − 20            =  80  ×2 = 160
child payable:    10 − (20 × 0.10)   =   8  ×1 =   8
──────────────────────────────────────────────────
finalPrice.SAR = floor(160 + 8)      = 168

Each adult is shaved by the full reducer; the child is shaved by the reducer scaled to its fare share (10% of an adult). The per-passenger lines (80, 8) re-sum to the floored total 168.

Exchange Rate ​

Prices are provided in three currencies:

CurrencyConversion
SARBase currency
IDRSAR × sellRate (from ExchangeRateService)
USDSAR ÷ 3.75 (fixed peg)

The exchange rate is the live system rate (same source as regular OTA). If no rate is available, search returns the raw OTA result without applying the reducer (it cannot convert the reducer into IDR/USD).

Error Responses ​

Both endpoints return the unified OTA error envelope (same contract as /v1/ota/book/calculate): a stable machine-readable code, a category, a retryable hint, and a context object.

400 Bad Request — Validation ​

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": [
    "fareId must be a string",
    "origin must be a string",
    "destination must be a string",
    "departureDate must be a valid ISO 8601 date string"
  ],
  "code": "INPUT_VALIDATION",
  "category": "VALIDATION",
  "retryable": false,
  "context": {
    "fields": [
      { "path": "fareId", "constraint": "isString", "message": "fareId must be a string" }
    ]
  }
}

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "FareId \"SAB2MINECO\" not found in search results. The flight may no longer be available. Please search again.",
