Booking Types ​

Booking types are automatically determined based on passenger count:

Booking TypePassenger CountDescription
REGULAR≤10 passengers (adults + children)Standard bookings with complete passenger details
GROUP>10 passengers (adults + children)Bookings with passenger quantities only

REGULAR Bookings ​

Standard bookings with complete passenger information from the start.

  • Individual passenger details (names, documents, etc.) required at creation
  • Can be ticketed immediately after payment confirmation
  • Suitable for bookings with up to 10 passengers

GROUP Bookings ​

Bookings with passenger quantities only (no individual names required at creation).

  • Passenger names added later via modification
  • Suitable for bookings with more than 10 passengers
  • Uses B2B pricing with tariff consideration

Note: The bookingType field is required on POST /api/v1/ota/book and must be REGULAR or GROUP (a missing or invalid value returns 400 Bad Request). The server then re-derives the effective type from the passenger count, so the stored value may differ from what you sent (e.g. a 10-passenger request sent as GROUP is stored as REGULAR).

Booking Status Flow ​

┌─────────────┐    Payment     ┌─────────────┐   Ticketing    ┌─────────────┐
│   PENDING   │ ──────────────→ │  CONFIRMED  │ ─────────────→ │   TICKETED  │
│ (Awaiting   │    Received     │  (Reserved  │    Processed   │  (Tickets   │
│  Payment)   │                  │   & Paid)   │                 │   Issued)   │
└─────────────┘                  └─────────────┘                └─────────────┘
      │                               │                              │
      │                               │ Cancel                       │
      └───────────────────────────────┴──────────────────────────────┘
                                      │
                                      ▼
                               ┌──────────────┐
                               │  CANCELLED   │
                               └──────────────┘
StatusDescriptionCan CancelCan Modify
PENDINGAwaiting paymentYesLimited
CONFIRMEDPayment confirmed, seats reservedYesYes
TICKETING_IN_PROGRESSTickets being generatedYesLimited
TICKETEDTickets issuedYesLimited
CANCELLEDBooking cancelledNoNo
FAILEDBooking failedNoNo

Departed trips: Once a flight has departed, the booking response sets actions.canCancel = false, drops CANCEL from actions.availableActions, and sets actions.cancelDeniedReason = "Cancellation not allowed: departure has already passed" — for any status above. Hide the Cancel action for departed trips.

Search Trains ​

Search for available trains with real-time pricing.

http
POST /ota/search
Content-Type: application/json
Authorization: Bearer <token>

Request Body ​

json
{
  "origin": "DMX",
  "destination": "MKX",
  "departureDate": "2026-02-15",
  "tripType": "ONE_WAY",
  "passengerQuantities": {
    "adults": 2,
    "children": 1,
    "infants": 0
  }
}

Passenger Limits ​

  • REGULAR bookings: Maximum 10 passengers (adults + children)
  • GROUP bookings: More than 10 passengers (adults + children)
  • Infants don't count toward the limit for booking type determination
  • Booking type is automatically determined based on passenger count

Response ​

See Guest OTA Guide for detailed response structure.

Passenger completion is exposed via passengers.quantities (and passengers.progress for GROUP), and issued tickets live under the tickets object. See Booking Management for the full field reference.

Cancel Booking ​

Cancel a booking and queue refund processing. Allowed for bookings in PENDING, CONFIRMED, TICKETING_IN_PROGRESS, or TICKETED status. Already-CANCELLED bookings are rejected.

http
POST /ota/bookings/:id/cancel
Authorization: Bearer <token>

Response ​

json
{
  "id": "019bfef1-61fd-731c-9a77-2da9417f6da8",
  "bookingCode": "XGZXHXR",
  "otaBookingRef": "XVW3NR",
  "status": "CANCELLED",
  "refundable": true,
  "message": "Booking cancelled. Refund is being processed and may take 5-7 business days."
}

Note: Refunds are processed asynchronously after cancellation. The response does not carry a refund amount or refund status — refundable only indicates whether a refund job was queued. Final refund status is delivered out-of-band (cancellation email / booking status history).

Response Fields:

idstringBooking unique identifier (UUID)
bookingCodestringHuman-readable booking code (6 chars)
otaBookingRefstring|nullOTA booking reference (Record Locator), null if none
statusstringBooking status after cancellation (CANCELLED)
refundablebooleanWhether a refund job was queued for this cancellation
messagestringUser-friendly result message

The 72-Hour Rule ​

Passenger information modifications (Type 40) for TICKETED bookings must be completed more than 72 hours before departure.

Key Points:

  • Check timeLimits.updateTravellersTimeLimit in booking response
  • If no time limit specified, default is 72 hours before departure
  • Modifications within 72 hours return 400 error

}

Countdown Implementation (React) ​

tsx
import { useState, useEffect } from 'react';

export function PaymentCountdown({ expiresAt }: { expiresAt: string }) {
  const [timeLeft, setTimeLeft] = useState(0);

  useEffect(() => {
    const update = () => {
      const now = new Date().getTime();
      const expiry = new Date(expiresAt).getTime();
      setTimeLeft(Math.max(0, expiry - now));
    };

    update();
    const interval = setInterval(update, 1000);
    return () => clearInterval(interval);
  }, [expiresAt]);

  const minutes = Math.floor(timeLeft / 60000);
  const seconds = Math.floor((timeLeft % 60000) / 1000);

  if (timeLeft === 0) {
    return <div style={{ color: 'red' }}>⛔ Payment expired</div>;
  }

  return (
    <div style={{ color: minutes < 5 ? 'red' : 'green' }}>
      ⏰ Complete payment within {minutes}:{seconds.toString().padStart(2, '0')}
    </div>
  );
}

// API client
class BookingAPI {
  private baseUrl = '/api/v1';
  private token: string;

  constructor(token: string) {
    this.token = token;
  }

  private async fetch(endpoint: string, options: RequestInit = {}) {
    const response = await fetch(`${this.baseUrl}${endpoint}`, {
      ...options,
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${this.token}`,
        ...options.headers,
      },
    });

    if (!response.ok) {
      throw new Error(`API Error: ${response.statusText}`);
    }

    return response.json();
  }

  async getBookings(params?: { page?: number; limit?: number; status?: string }) {
    const query = new URLSearchParams(params as Record<string, string>);
    return this.fetch(`/ota/bookings?${query}`);
  }

  async getBooking(id: string): Promise<Booking> {
    return this.fetch(`/ota/bookings/${id}`);
  }

  async getBookingByCode(code: string): Promise<Booking> {
    return this.fetch(`/ota/bookings/code/${code}`);
  }

  async cancelBooking(id: string) {
    return this.fetch(`/ota/bookings/${id}/cancel`, { method: 'POST' });
  }

  async downloadTickets(id: string): Promise<Blob> {
    const response = await fetch(`${this.baseUrl}/ota/bookings/${id}/tickets`, {
      headers: { 'Authorization': `Bearer ${this.token}` },
    });
    return response.blob();
  }
}
