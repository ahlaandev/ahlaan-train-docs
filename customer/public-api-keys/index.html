Partner Public API Keys ​

This guide explains how an approved B2B partner mints, lists, updates, and revokes their own public API keys. Keys authenticate calls to the partner-facing endpoints (/api/v1/public/ota/*).

Quick Overview ​

ItemDescription
AudienceApproved B2B users (role = B2B, b2bApplicationStatus = APPROVED — or legacy users with no recorded status)
AuthenticationJWT in Authorization: Bearer … header
Base path/api/v1/partner/api-keys
Key formatahlaan_live_<random> — shown once on creation, server stores only its SHA-256 hash
Per-org scopeThe organizationId is taken from your JWT — you can never act on another org's keys

Prerequisites ​

  1. Your B2B application is APPROVED by an admin.
  2. An admin has enabled public API access for your organization (Organization.publicApiEnabled = true). Without this, POST /partner/api-keys returns 409 Conflict. Contact support if you need access.

0. Discover available scopes ​

http
GET /api/v1/partner/api-keys/scopes
Authorization: Bearer <jwt>

Returns the catalog of scopes your organization can request when issuing or updating a key, with a human-readable description for each. Use this to populate scope selectors in your dashboard and to discover newly added scopes (e.g. ota:routes) without redeploying client UIs.

Response (200):

json
[
  {
    "scope": "ota:search",
    "description": "Search for available trains via POST /public/ota/search."
  },
  {
    "scope": "ota:calculate",
    "description": "Calculate booking price for a selected train via POST /public/ota/calculate."
  },
  {
    "scope": "ota:routes",
    "description": "List the OTA origin–destination route catalog via GET /public/ota/routes."
  }
]

The response is the single source of truth for scope validation: POST /partner/api-keys and PATCH /partner/api-keys/:keyId both reject any scope not in this list.

1. Issue a key ​

http
POST /api/v1/partner/api-keys
Authorization: Bearer <jwt>
Content-Type: application/json

Body (CreateApiKeyDto):

FieldTypeRequiredNotes
namestring (1–120)yesHuman-readable label, e.g. "production-server"
scopesstring[]yesOne or more of: ota:search, ota:calculate, ota:routes. Call GET /partner/api-keys/scopes for the live catalog.
expiresAtISO-8601noOmit for no expiry
rateLimitPerMinuteint (1–100000)noPer-key rate limit; omit for unlimited

Response (201):

json
{
  "id": "0193…",
  "prefix": "ahlaan_live_a1b2c",
  "key": "ahlaan_live_<full-plaintext>",
  "warning": "Store this key securely — it will not be shown again. Only its hash is retained on the server."
}

Capture key immediately. It cannot be retrieved later.

Errors:

StatusReason
400DTO validation failed
401JWT missing/invalid
403Caller is not an approved B2B user
409Public API access not enabled for your organization (ask admin)
429Throttled — limit is 5 issuances per hour

2. List your keys ​

http
GET /api/v1/partner/api-keys?page=1&limit=20
Authorization: Bearer <jwt>

Returns paginated metadata for every key issued to your organization (active and revoked). The plaintext is never returned.

json
{
  "data": [
    {
      "id": "0193…",
      "name": "production-server",
      "prefix": "ahlaan_live_a1b2c",
      "scopes": ["ota:search"],
      "rateLimitPerMinute": null,
      "lastUsedAt": "2026-04-25T12:34:56.000Z",
      "expiresAt": null,
      "revokedAt": null,
      "createdBy": "<userId>",
      "createdAt": "2026-04-20T08:00:00.000Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}

3. Update a key ​

http
PATCH /api/v1/partner/api-keys/:keyId
Authorization: Bearer <jwt>
Content-Type: application/json

Update mutable fields on an existing key without rotating the secret — the plaintext is unchanged. Use this to grant a newly added scope (e.g. ota:routes) to existing keys instead of revoking and re-issuing.

Body (UpdateApiKeyDto) — all fields optional, at least one required:

FieldTypeNotes
namestring (1–120)Rename the key
scopesstring[]Replacement set (not additive). Must be from the GET /scopes catalog and contain ≥ 1 entry.
expiresAtISO-8601 | nullNew expiry. Pass null to clear an existing expiry.
rateLimitPerMinuteint (1–100000) | nullNew per-key rate limit. Pass null to clear (unlimited).

Response (200): the same projection as the list endpoint — the updated key without hashedKey or plaintext.

The cache is invalidated immediately on update, so the change takes effect on the very next public-API call (no 60s wait).

Errors:

StatusReason
400Body validation failed (including scopes containing an unknown value such as ota:teleport), or no fields provided
401JWT missing/invalid
403Caller is not an approved B2B user
404keyId not found in your organization (also returned for cross-org IDs — never 403)
429Throttled — limit is 20 updates per hour per JWT

Example — grant ota:routes to an existing key:

bash
curl -X PATCH \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{"scopes":["ota:search","ota:calculate","ota:routes"]}' \
  https://api.<your-host>/api/v1/partner/api-keys/<KEY_ID>

Each update that changes at least one field writes an UPDATE_API_KEY row to the audit log capturing oldValue and newValue for only the fields that actually changed, plus metadata.organizationId for context, attributed to the caller's userId. Scopes are compared as a set (re-ordering is not a change). A no-op PATCH (every requested value already matches the current value) returns 200 without writing an audit row. Already-revoked keys are not patchable — the endpoint returns 404 the same as a cross-org or unknown ID.

4. Revoke a key ​

http
DELETE /api/v1/partner/api-keys/:keyId
Authorization: Bearer <jwt>

204 No Content on success. The key is rejected on the next public-API call (cache TTL up to 60 seconds).

If the keyId belongs to another organization the response is 404 Not Found — never 403 — so the existence of other orgs' keys is not leaked.

5. Use the key against the public API ​

http
POST /api/v1/public/ota/search
X-API-Key: ahlaan_live_<full-plaintext>
Content-Type: application/json

{ "origin": "...", "destination": "...", "date": "..." }

To list available routes (requires the ota:routes scope on the key):

http
GET /api/v1/public/ota/routes
X-API-Key: ahlaan_live_<full-plaintext>

Returns an array of "ORIGIN-DESTINATION" strings (e.g. ["RUH-JED", "JED-MED"]), cached server-side for 15 minutes. Use these to populate origin/destination selectors and validate inputs before calling /public/ota/search.

The full request and response shapes for the public endpoints live in the Scalar reference, served at https://docs.<your-api-host>/.

Security checklist ​

  • Store the plaintext in a secrets manager — never commit it to git.
  • Use one key per environment / per server — easier to revoke a leaked key without taking down everything.
  • Set expiresAt for short-lived integrations (CI runs, contractors).
  • Use rateLimitPerMinute to cap blast radius on a leak.
  • Revoke immediately on suspicion — the change propagates within ~60 seconds.
