Update GROUP Booking Passengers ​

This guide explains how to update passenger data for GROUP bookings using the dedicated passengers endpoint.

Overview ​

The PATCH /ota/bookings/:id/passengers endpoint provides a simplified way to update passenger information for GROUP bookings without requiring ticketing.

When to Use This Endpoint ​

Use CaseEndpointNotes
Update passengers before ticketing (GROUP bookings)PATCH /ota/bookings/:id/passengers✅ Recommended - no passenger count restrictions
Add passenger names to GROUP bookingPATCH /ota/bookings/:id/modify (Type 4)Requires ALL passengers at once
Update passenger info for TICKETED bookingsPATCH /ota/bookings/:id/modify (Type 40)Limited to document fields only

Key Differences: /passengers vs /modify ​

Feature/passengers/modify (Type 4)
Passenger CountPartial updates allowedMust provide ALL passengers
Booking TypeGROUP onlyAll types
StatusCONFIRMED, TICKETEDPENDING, CONFIRMED
Partial Updates✅ Yes❌ No
Document Updates (TICKETED)✅ Yes✅ Yes

Endpoint ​

http
PATCH /ota/bookings/:id/passengers
Authorization: Bearer <access_token>
Content-Type: application/json

Request Format ​

Headers ​

Content-Type: application/json
Authorization: Bearer {token}

Request Body ​

json
{
  "passengers": [
    {
      "rph": 1,
      "firstName": "Ahmad",
      "lastName": "Al-Saud",
      "gender": "M",
      "idType": "Passport",
      "idNumber": "A12345678",
      "idExpirationDate": "2030-12-31",
      "nationality": "SA",
      "dateOfBirth": "1990-01-15"
    }
  ],
  "rememberPassengers": false
}

Request Fields ​

FieldTypeRequiredDescription
passengersarrayYesArray of passenger objects
passengers[].rphnumberYes*Passenger reference number (required for TICKETED bookings)
passengers[].firstNamestringConditionalFirst name
passengers[].lastNamestringConditionalLast name
passengers[].genderstringConditionalGender: "M" or "F"
passengers[].idTypestringConditionalDocument type: Passport, NATIONAL_ID, etc.
passengers[].idNumberstringConditionalDocument number
passengers[].idExpirationDatestringConditionalDocument expiry (YYYY-MM-DD)
passengers[].nationalitystringConditionalCountry code (e.g., "SA", "ID")
passengers[].dateOfBirthstringConditionalDate of birth (YYYY-MM-DD)
rememberPassengersbooleanNoSave passengers for future bookings

Note: For CONFIRMED bookings, rph is optional - new passengers can be added. For TICKETED bookings, rph is required to identify existing passengers.

Behavior by Booking Status ​

CONFIRMED Status ​

When booking is in CONFIRMED status:

  • All fields can be updated: firstName, lastName, gender, idType, idNumber, idExpirationDate, nationality, dateOfBirth
  • New passengers can be added (no rph required)
  • Existing passengers can be updated (by matching rph)
  • Passengers are merged: same rph = replace, new rph = append

TICKETED Status ​

When booking is in TICKETED status:

  • Only document fields can be updated: idType, idNumber, idExpirationDate, nationality, dateOfBirth
  • Name fields (firstName, lastName, gender) cannot be changed
  • New passengers cannot be added - only existing passengers can be modified
  • rph is required for each passenger to identify the existing record

Getting the Updated Passengers List ​

After updating passengers, you can retrieve the latest passenger list using the booking detail endpoint:

bash
GET /ota/bookings/:id

The response will include the updated passengers in the passengers.names array:

json
{
  "passengers": {
    "type": "GROUP",
    "quantities": { "adults": 20, "children": 5, "infants": 2 },
    "names": [
      {
        "rph": 1,
        "firstName": "Ahmad",
        "lastName": "Al-Saud",
        ...
      }
    ]
  }
}

Alternatively, use the booking code lookup:

bash
GET /ota/bookings/code/:bookingCode

Use Cases ​

1. Partial Passenger Update (CONFIRMED) ​

Update only some passengers without providing all:

bash
curl -X PATCH "/api/v1/ota/bookings/019bfef1-61fd-731c-9a77-2da9417f6da8/passengers" \
  -H "Authorization: Bearer eyJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "passengers": [
      {
        "firstName": "Ahmad",
        "lastName": "Al-Saud",
        "gender": "M",
        "idType": "Passport",
        "idNumber": "A12345678",
        "idExpirationDate": "2030-12-31",
        "nationality": "SA",
        "dateOfBirth": "1990-01-15"
      }
    ]
  }'

2. Update by RPH (TICKED) ​

Update existing passenger document info:

bash
curl -X PATCH "/api/v1/ota/bookings/019bfef1-61fd-731c-9a77-2da9417f6da8/passengers" \
  -H "Authorization: Bearer eyJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "passengers": [
      {
        "rph": 1,
        "idType": "NATIONAL_ID",
        "idNumber": "1234567890",
        "idExpirationDate": "2035-06-15",
        "nationality": "ID",
        "dateOfBirth": "1990-01-15"
      }
    ]
  }'

3. Add New Passenger Without RPH ​

bash
curl -X PATCH "/api/v1/ota/bookings/019bfef1-61fd-731c-9a77-2da9417f6da8/passengers" \
  -H "Authorization: Bearer eyJhbGc..." \
  -H "Content-Type: application/json" \
  -d '{
    "passengers": [
      {
        "firstName": "New",
        "lastName": "Passenger",
        "gender": "M",
        "idType": "Passport",
        "idNumber": "NEW123456",
        "idExpirationDate": "2031-01-01",
        "nationality": "SA",
        "dateOfBirth": "1995-05-20"
      }
    ]
  }'

Comparison: When to Use Which Endpoint ​

Use /passengers when: ​

  • ✅ You want to update passengers incrementally (not all at once)
  • ✅ You have a GROUP booking in CONFIRMED status
  • ✅ You need to update document fields only for TICKETED bookings
  • ✅ You want a simpler API that handles merge logic automatically

Use /modify (Type 4) when: ​

  • ✅ You need to add all passenger names at once to trigger auto-ticketing
  • ✅ You're working with REGULAR bookings (not GROUP)
  • ✅ You need the full modification response with success message

Use /modify (Type 40) when: ​

  • ✅ You need to update passenger info for TICKETED bookings within 72-hour limit
  • ✅ You want to update contact info (email, phone) via Type 9
  • ✅ You need to cancel a segment (Type 10) for round-trip bookings
