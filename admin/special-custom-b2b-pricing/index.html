Special Custom B2B Pricing ​

Selected B2B organizations can receive discounted custom-OTA / custom-booking prices through the Special Custom B2B Pricing feature. Pricing rules are shared across all enrolled organizations (no per-org overrides for now).

Overview ​

FeatureDetails
ScopeCustom-OTA search, calculate, and custom-booking only (not standard OTA or BlockSeat)
SelectionAdmin manually enables per organization — customers cannot self-enroll
Shared rulesAll enrolled orgs use the same route-price table and exchange-rate reducer
Pricing levers(1) Per-route priceReducer (SAR, ECONOMY only); (2) exchangeRateReducer (IDR sell rate)
FallbackIf no route rule exists, priceReducer = 0; exchange rate reducer still applies
ClassesECONOMY legs use the special reducer; BUSINESS legs use standard markup+tax

Pricing Flow ​

When a user whose organization has specialCustomPricingEnabled = true calls a custom-OTA or custom-booking endpoint:

  1. exchangeRateReducer is subtracted from the live IDR sell rate: effectiveSellRate = max(0, liveSellRate − exchangeRateReducer). This reduced rate is used for the IDR payable conversion of the whole booking — including BUSINESS legs. The SAR price and USD price are unaffected by this lever. The strikethrough ("before discount") IDR keeps using the full live rate, so the discount is visible as the gap between strikethrough and payable.
  2. For each ECONOMY leg, the SpecialCustomB2BRoutePrice.priceReducer (in SAR) is used instead of the standard CustomRoutePrice.priceReducer. This SAR route reducer is ECONOMY-only.
  3. If no active SpecialCustomB2BRoutePrice matches the route, priceReducer = 0 (leg prices at raw supplier cost), but the exchangeRateReducer still applies.

Worked example ​

DMX→MKX ECONOMY, 1 adult, live sellRate = 4850, supplier retail (strikethrough) = 224.25 SAR:

Stateroute priceReducerexchangeRateReducerPayable SARPayable IDRStrikethrough IDR
Not enrolled (standard)——2191,062,150 (×4850)1,087,612 (×4850)
Enrolled10250floor(224.25−10)=214984,400 (×4600)1,087,612 (×4850)
Enrolled, no active route rule0250floor(224.25−0)=2241,030,400 (×4600)1,087,612 (×4850)

Payable IDR uses effectiveSellRate = 4850 − 250 = 4600; the strikethrough IDR stays at the full 4850. USD is unaffected by exchangeRateReducer.

Enroll / Unenroll an Organization ​

Toggle special custom B2B pricing for a specific organization:

http
PATCH /api/v1/admin/organizations/:id/special-custom-b2b-pricing
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "enabled": true
}

Response:

json
{
  "id": "org-uuid",
  "specialCustomPricingEnabled": true
}

Global Config — Exchange Rate Reducer ​

Get current config ​

http
GET /api/v1/admin/special-custom-b2b-pricing/config
Authorization: Bearer <admin-token>

Response:

json
{
  "exchangeRateReducer": 250,
  "updatedBy": "admin-uuid",
  "updatedAt": "2026-06-27T10:00:00.000Z"
}

Update exchange rate reducer ​

http
PATCH /api/v1/admin/special-custom-b2b-pricing/config
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "exchangeRateReducer": 250
}

Sets how much (in IDR) is subtracted from the live sell rate for all special custom B2B organizations. Set to 0 to disable the exchange rate discount while keeping route rules. Maximum value is 1000.

Route Price Rules ​

Create a route price rule ​

http
POST /api/v1/admin/special-custom-b2b-pricing/route-prices
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "originCode": "DMX",
  "destinationCode": "MKX",
  "tripClass": "ECONOMY",
  "priceReducer": 50,
  "isActive": true
}

Response (201):

json
{
  "id": "019f0846-5fa5-77c8-a744-1540f30d74c2",
  "originCode": "DMX",
  "originName": "Madinah",
  "destinationCode": "MKX",
  "destinationName": "Makkah",
  "tripClass": "ECONOMY",
  "priceReducer": 50,
  "isActive": true,
  "createdBy": "019c9105-311a-732f-a1c5-da44758a7e5b",
  "updatedBy": "019c9105-311a-732f-a1c5-da44758a7e5b",
  "createdAt": "2026-06-27T08:50:57.558Z",
  "updatedAt": "2026-06-27T08:50:57.558Z"
}
  • priceReducer: SAR amount subtracted per adult passenger on ECONOMY legs.
  • Route lookup is symmetric: a DMX→MKX rule matches both DMX→MKX and MKX→DMX search directions. Creating the reverse direction of an existing rule returns 409 Conflict.
  • Rules cover both ONE_WAY and ROUND_TRIP (no separate rules needed per trip type).
  • Origin/destination codes must exist as Location rows, else 404. priceReducer must be >= 0, else 400.

http
GET /api/v1/admin/special-custom-b2b-pricing/route-prices
Authorization: Bearer <admin-token>

Query params: page, limit, isActive (boolean), originCode, destinationCode, tripClass. Origin/destination filters are symmetric (match the route stored in either direction).

Get single rule ​

http
GET /api/v1/admin/special-custom-b2b-pricing/route-prices/:id

Update a rule ​

http
PATCH /api/v1/admin/special-custom-b2b-pricing/route-prices/:id
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "priceReducer": 75,
  "isActive": false
}

Only priceReducer and isActive can be updated. Identity fields (route, class) are immutable — create a new rule to change them.

Deactivate (soft-delete) a rule ​

http
DELETE /api/v1/admin/special-custom-b2b-pricing/route-prices/:id
Authorization: Bearer <admin-token>

Response (200):

json
{ "success": true }

Sets isActive = false. The row is retained for audit purposes (no hard delete; re-create the route to re-enable, or PATCH isActive: true).

Cache Invalidation ​

  • Route price lookups are cached in Redis per route+class (TTL 300s). Cache is invalidated on create / update / delete.
  • Exchange rate reducer is cached per singleton key (TTL 300s). Cache is invalidated on update.
  • Organization enrollment status is cached per org (TTL 300s). Cache is invalidated when specialCustomPricingEnabled changes.

Notes ​

  • Only ECONOMY legs receive a special route reducer; BUSINESS legs keep their standard custom markup + custom tax SAR price. Note the exchangeRateReducer still lowers the BUSINESS IDR payable (it is a booking-wide IDR rate lever), so an enrolled org pays fewer rupiah for the same BUSINESS SAR fare.
  • Setting a priceReducer larger than the supplier fare results in a 0 SAR payable for that leg (floor at 0).
  • To stop all special discounts immediately: set exchangeRateReducer = 0 and deactivate all route rules (or unenroll all orgs).
