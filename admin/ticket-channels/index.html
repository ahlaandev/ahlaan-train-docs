Ticket Channel Management ​

This guide explains how administrators manage ticket channels — the companies that issue physical tickets for custom bookings (e.g. HHR). Every custom booking transitioned to CONFIRMED must be assigned to a ticket channel.

Route prices — deleteDELETE /api/v1/admin/ticket-channels/:channelId/route-prices/:idAdmin
Public list (active only)GET /api/v1/ticket-channelsOptional auth

Permission-gated (Access Roles). The admin routes above (channels and their route prices) require the ADMIN role plus a fine permission: reads (list, get) need ticket-channels:read, and create/update/delete need ticket-channels:update. The public list is not gated. See Access Roles.

Authentication ​

All admin/ticket-channels endpoints require:

  • JWT Token in the Authorization header
  • ADMIN role on the user account
http
Authorization: Bearer <admin-jwt-token>

The public GET /ticket-channels endpoint accepts an optional bearer token but does not require one.

Base URL ​

/api/v1

Authorization: Bearer <admin-token>

5. Delete Ticket Channel ​

http
DELETE /admin/ticket-channels/:id
Authorization: Bearer <admin-token>

Behaviour depends on whether the channel is referenced by any booking:

  • Channel in use (CustomBooking.ticketChannelId referenced by one or more rows) → soft delete: isActive is set to false. The channel is preserved for historical bookings.
  • Channel unused → hard delete: row is permanently removed.

cURL ​

bash
curl -X DELETE /api/v1/admin/ticket-channels/0190abc1-... \
  -H "Authorization: Bearer <admin-token>"

Response (200) — Soft delete ​

json
{
  "message": "Channel 'HHR' deactivated (used in 14 bookings)",
  "deactivated": true,
  "usageCount": 14
}

Response (200) — Hard delete ​

json
{
  "message": "Channel 'HHR' permanently deleted",
  "deleted": true
}

7. Channel Route Prices (capital-price basis) ​

Per-channel capital price rows keyed by (ticketChannelId, originId, destinationId, tripClass, tripType). A single row defines what one adult ticket on this channel actually costs the business for a given route + class + trip type. Used at the PENDING → CONFIRMED booking transition to populate CustomBooking.capitalPriceTotalSAR and per-leg pricingSnapshot.outbound.capitalPriceSAR / pricingSnapshot.return.capitalPriceSAR. See the Custom Booking admin guide for how the snapshot is consumed.

Lookup semantics at CONFIRMED:

  • The booking's tripType is passed through as-is (so ROUND_TRIP bookings look up tripType: ROUND_TRIP rows on both legs; ONE_WAY bookings look up tripType: ONE_WAY).
  • tripClass is taken per leg from the booking's outbound/return flight payload.
  • For the return leg of a ROUND_TRIP booking, originId and destinationId are looked up swapped — the row must exist for the reversed direction.
  • Only rows with isActive: true participate in the lookup.
  • Missing rows are non-fatal: capital stays 0 / null and an admin can correct it later via PATCH /admin/custom-booking/:id/capital-price.

Each create/update/delete writes an AuditLog entry under entity = "TicketChannelRoutePrice" with action one of TICKET_CHANNEL_ROUTE_PRICE_CREATE / _UPDATE / _DELETE.

7.1 Create a Route Price ​

http
POST /admin/ticket-channels/:channelId/route-prices
Authorization: Bearer <admin-token>
Content-Type: application/json

Request Body ​

FieldTypeRequiredRules
originIdUUIDYesMust reference an existing Location.
destinationIdUUIDYesMust reference an existing Location.
tripClassenumYesECONOMY or BUSINESS.
tripTypeenumYesONE_WAY or ROUND_TRIP.
capitalPricenumberYesSAR per adult, ≥ 0, max 2 decimals.
isActivebooleanNoDefaults to true.

The combination (channelId, originId, destinationId, tripClass, tripType) is unique; duplicates return 409 Conflict.

cURL ​

bash
curl -X POST '/api/v1/admin/ticket-channels/0190abc1-.../route-prices' \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "loc-origin-1",
    "destinationId": "loc-dest-1",
    "tripClass": "ECONOMY",
    "tripType": "ONE_WAY",
    "capitalPrice": 300.00
  }'

Response (201) ​

json
{
  "id": "tcrp-1",
  "ticketChannelId": "0190abc1-...",
  "originId": "loc-origin-1",
  "originCode": "MECCA",
  "originName": "Mecca",
  "destinationId": "loc-dest-1",
  "destinationCode": "MEDINA",
  "destinationName": "Medina",
  "tripClass": "ECONOMY",
  "tripType": "ONE_WAY",
  "capitalPrice": 300.00,
  "isActive": true,
  "createdBy": "admin-1",
  "updatedBy": "admin-1",
  "createdAt": "2026-05-04T10:00:00.000Z",
  "updatedAt": "2026-05-04T10:00:00.000Z"
}

Every route-price response embeds the resolved origin/destination Location — originCode / originName and destinationCode / destinationName — alongside the raw originId / destinationId, so callers can render the route without a second lookup.

Errors ​

  • 404 Not Found — channel or origin/destination location does not exist.
  • 409 Conflict — a row already exists for this combination.

7.3 Get One Route Price ​

http
GET /admin/ticket-channels/:channelId/route-prices/:id

Returns the row scoped to the channel. 404 Not Found if the row does not exist or belongs to a different channel.

7.4 Update a Route Price ​

http
PATCH /admin/ticket-channels/:channelId/route-prices/:id
Authorization: Bearer <admin-token>
Content-Type: application/json

Request Body ​

FieldTypeRequiredRules
capitalPricenumberNoSAR per adult, ≥ 0, max 2 decimals.
isActivebooleanNoToggle row availability.

Identifying fields (originId / destinationId / tripClass / tripType) are immutable — delete and recreate to change them.

Response (200) ​

Same shape as 7.1 with updatedAt advanced.

7.5 Delete a Route Price ​

http
DELETE /admin/ticket-channels/:channelId/route-prices/:id

Hard-delete. The row is removed and an audit entry is written.

Response (200) ​

json
{ "deleted": true, "id": "tcrp-1" }

Errors ​

  • 404 Not Found — row does not exist or belongs to a different channel.

Historical bookings are unaffected. capitalPrice snapshots are frozen on the booking at CONFIRMED time — deleting or editing the source row never rewrites past bookings. Use PATCH /admin/custom-booking/:id/capital-price to correct an already-confirmed booking.
