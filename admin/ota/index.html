Get Booking Details (Admin) ​

Retrieve the full detail of any booking by ID. Bypasses the ownership check used by the customer endpoint and adds an _admin block with internal metadata.

http
GET /admin/ota/bookings/:id
Authorization: Bearer <admin-token>

Path Parameters ​

ParameterTypeRequiredDescription
idstringYesBooking ID (UUID)

Query Parameters ​

ParameterTypeDefaultDescription

Only the admin-specific portion is shown below — see the customer guide for the full base shape (trip, passengers, pricing, payment, flights, tickets, actions, statusHistory, etc.). Comparison Metrics ​

The previousPeriodComparison field shows growth compared to the equivalent previous period:

  • If period is Jan 1-31, comparison is against Dec 1-31
  • Positive values indicate growth, negative values indicate decline
  • Useful for identifying trends and anomalies

Caveat: the previous-period query applies the organizationId and status filters but does not apply the route filter. A route-filtered report therefore compares this period's filtered bookings against the previous period across all routes. Treat the comparison values as directional rather than strictly route-scoped when route is set.

Retry Ticketing ​

Manually trigger ticketing for bookings stuck in CONFIRMED or TICKETING_IN_PROGRESS status.

http
POST /admin/ota/bookings/:id/retry-ticketing
Authorization: Bearer <admin-token>

Use Cases ​

ScenarioAction
Booking stuck in TICKETING_IN_PROGRESSRetry to recover stuck job
Booking in CONFIRMED but not ticketedQueue async ticketing job
OTA service temporary failureRetry after service recovery
Manual intervention neededTrigger after fixing data issues

Response ​

json
{
  "success": true,
  "message": "Ticketing retry queued successfully",
  "jobId": "bull:booking-ticketing:12345",
  "bookingId": "01920a3b-7c4d-7e8f-9a0b-1c2d3e4f5a6b",
  "bookingCode": "ABC1234",
  "previousStatus": "TICKETING_IN_PROGRESS"
}

When to Use ​

Do use retry ticketing when:

  • Customer reports booking is paid but no tickets received
  • Booking has been in TICKETING_IN_PROGRESS for > 30 minutes
  • OTA service experienced temporary outage
  • Previous ticketing job failed due to network issues

Don't use retry ticketing when:

  • Booking is in PENDING status (needs payment first)
  • Booking is already TICKETED
  • Booking is CANCELLED or FAILED
  • Passenger data is incomplete for GROUP bookings

Trail side effect: A successful retry automatically appends a MANUAL_RETRY entry to the booking's admin follow-up trail. You do not need to record it manually.

Cancel Booking ​

Cancel a CONFIRMED or TICKETED booking on behalf of a user and process any applicable refund. This endpoint bypasses ownership restrictions, so admins can action customer cancellation requests, fraud cases, or policy violations.

http
POST /admin/ota/bookings/:id/cancel
Content-Type: application/json
Authorization: Bearer <admin-token>

Request Body ​

json
{
  "reason": "Customer requested cancellation via support ticket #12345",
  "skipRefund": false,
  "notifyUser": true
}
FieldTypeRequiredDefaultDescription
reasonstringYes—Cancellation reason, recorded in the audit trail. Max 1000 characters.
skipRefundbooleanNofalseSkip automatic refund queuing (use for manual/offline refund handling).
notifyUserbooleanNotrueSend cancellation email(s) to the booking contact.

Response ​

json
{
  "bookingId": "01920a3b-7c4d-7e8f-9a0b-1c2d3e4f5a6b",
  "status": "CANCELLED",
  "refundStatus": "QUEUED",
  "cancelledBy": "ADMIN",
  "cancelledAt": "2026-01-30T10:00:00.000Z"
}
FieldTypeDescription
bookingIdstringCancelled booking ID
statusstringAlways CANCELLED on success
refundStatusstringQUEUED when a refund job is queued, QUEUE_FAILED if queuing failed (needs manual refund). Omitted when no refund applies or skipRefund is set.
cancelledBystringAlways ADMIN
cancelledAtstringISO 8601 cancellation timestamp

Allowed Statuses ​

Only CONFIRMED and TICKETED bookings can be cancelled through this endpoint.

Current StatusResult
CONFIRMEDCancelled; held funds released, refund queued if already charged
TICKETEDCancelled; refund queued per policy (may be partial)
CANCELLED400 — "Booking already cancelled"
PENDING / TICKETING_IN_PROGRESS / FAILED / EXPIRED400 — only CONFIRMED or TICKETED bookings can be cancelled

Time-limit override: Cancellation deadlines (the OTA-provided cancellationTimeLimit, or the fallback rule of 7 days before departure) are enforced for customers but bypassed for admins. The override is logged for audit.

Refund Behavior ​

PaymentBehavior
Wallet — funds only HELDReleased back to the wallet automatically (no refund job)
Wallet — already charged (DEBIT)Refund job queued (refundStatus: QUEUED)
Bank / QRIS / CardRefund job queued only when the invoice is PAID

skipRefund: true suppresses all refund queuing. Held wallet funds are still released.

OTA Cancellation Outcomes ​

If the booking has an OTA reference, the cancellation is forwarded to GO7 (Worldticket):

CaseBehavior
OTA accepts (or booking already cancelled on OTA)Booking cancelled locally
Non-ticketed booking + OTA 4xx hard reject (e.g. bad booking state)Cancelled locally anyway — no tickets were issued
Ticketed booking + any OTA error, or any OTA 5xxCancellation blocked — error passed through with error: "Cancellation Rejected". Retry once OTA recovers.

Error Responses ​

StatusDescription
400 Bad RequestBooking status not cancellable / already cancelled
401 UnauthorizedMissing or invalid token
403 ForbiddenAdmin role required
404 Not FoundBooking not found
4xx / 5xxOTA rejected the cancellation (error: "Cancellation Rejected")

cURL Example ​

bash
curl -X POST "https://api.example.com/api/v1/admin/ota/bookings/01920a3b-7c4d-7e8f-9a0b-1c2d3e4f5a6b/cancel" \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Customer requested cancellation via support ticket #12345",
    "skipRefund": false,
    "notifyUser": true
  }'

Customer Support Workflows ​

Scenario 1: Customer Didn't Receive Tickets ​

Symptoms:

  • Booking status is TICKETED
  • Customer reports no email received
  • Payment was successful

Resolution Steps:

  1. Find the booking:
bash
curl -X GET "/api/v1/admin/ota/bookings?search=customer@example.com" \
  -H "Authorization: Bearer <admin-token>"
  1. Verify booking status is TICKETED:
json
{
  "status": "TICKETED",
  "bookingCode": "ABC1234"
}
  1. Download tickets for verification:
bash
curl -X GET "/api/v1/admin/ota/bookings/{id}/tickets" \
  -H "Authorization: Bearer <admin-token>" \
  -o tickets-ABC1234.zip
  1. Resend confirmation email:
bash
curl -X POST "/api/v1/admin/ota/bookings/{id}/resend-ticket-confirmation-email" \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"emails":["customer@example.com"],"ccEmails":["support@hhr.com"]}'
  1. If email still fails, send tickets manually:
    • Download the ZIP file
    • Email to customer via your email client
    • Document in support ticket

Scenario 2: Booking Stuck in TICKETING_IN_PROGRESS ​

Symptoms:

  • Booking status is TICKETING_IN_PROGRESS for > 30 minutes
  • Payment was successful
  • No tickets generated

Resolution Steps:

  1. Check booking details:
bash
curl -X GET "/api/v1/admin/ota/bookings?status=TICKETING_IN_PROGRESS" \
  -H "Authorization: Bearer <admin-token>"

  1. Verify OTA service status:

    • Check if GO7 API is operational
    • Look for any service alerts

  2. Retry ticketing:

bash
curl -X POST "/api/v1/admin/ota/bookings/{id}/retry-ticketing" \
  -H "Authorization: Bearer <admin-token>"

  1. Monitor for status change:

    • Poll the booking endpoint every 30 seconds
    • Status should change to TICKETED or FAILED

  2. If retry fails:

    • Check error logs for specific error
    • Contact GO7 support if OTA issue
    • Consider manual ticketing as last resort

Scenario 3: Customer Didn't Receive Cancellation Email ​

Symptoms:

  • Booking status is CANCELLED
  • Customer reports no cancellation email
  • Refund processed or pending

Resolution Steps:

  1. Verify booking is cancelled:
bash
curl -X GET "/api/v1/admin/ota/bookings?status=CANCELLED&search=ABC1234" \
  -H "Authorization: Bearer <admin-token>"
  1. Resend cancellation email:
bash
curl -X POST "/api/v1/admin/ota/bookings/{id}/resend-cancellation-email" \
  -H "Authorization: Bearer <admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"emails":["customer@example.com"],"ccEmails":["support@hhr.com"]}'
  1. Verify refund status:
    • Check payment system for refund record
    • Inform customer of refund timeline (5-7 business days)

Code Examples ​

TypeScript Admin Client ​

typescript
interface AdminBookingAPIConfig {
  baseUrl: string;
  token: string;
}

class AdminBookingAPI {
  private baseUrl: string;
  private token: string;

  constructor(config: AdminBookingAPIConfig) {
    this.baseUrl = config.baseUrl;
    this.token = config.token;
  }

  private async fetch(endpoint: string, options: RequestInit = {}) {
    const response = await fetch(`${this.baseUrl}${endpoint}`, {
      ...options,
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${this.token}`,
        ...options.headers,
      },
    });

    if (!response.ok) {
      const error = await response.json().catch(() => ({}));
      throw new Error(error.message || `API Error: ${response.statusText}`);
    }

    return response.json();
  }

  async getAllBookings(filters?: {
    page?: number;
    limit?: number;
    search?: string;
    status?: string;
    userId?: string;
    organizationId?: string;
    createdDateFrom?: string;
    createdDateTo?: string;
    departureDateFrom?: string;
    departureDateTo?: string;
    sortBy?: string;
    sortOrder?: 'asc' | 'desc';
  }) {
    const params = new URLSearchParams();
    Object.entries(filters || {}).forEach(([key, value]) => {
      if (value !== undefined) params.append(key, String(value));
    });
    return this.fetch(`/admin/ota/bookings?${params}`);
  }

  async getBooking(
    bookingId: string,
    options?: { forceSync?: boolean },
  ) {
    const qs = options?.forceSync ? '?forceSync=true' : '';
    return this.fetch(`/admin/ota/bookings/${bookingId}${qs}`);
  }

  async retryTicketing(bookingId: string): Promise<{
    success: boolean;
    message: string;
    jobId: string;
    bookingId: string;
    bookingCode: string;
    previousStatus?: string;
  }> {
    return this.fetch(`/admin/ota/bookings/${bookingId}/retry-ticketing`, {
      method: 'POST',
    });
  }

  async resendCancellationEmail(
    bookingId: string,
    request?: {
      emails?: string[];
      ccEmails?: string[];
      bccEmails?: string[];
    }
  ): Promise<{ success: boolean; message: string }> {
    return this.fetch(`/admin/ota/bookings/${bookingId}/resend-cancellation-email`, {
      method: 'POST',
      body: JSON.stringify(request || {}),
    });
  }

  async resendTicketConfirmationEmail(
    bookingId: string,
    request?: {
      emails?: string[];
      ccEmails?: string[];
      bccEmails?: string[];
      passengers?: Array<{
        firstName: string;
        middleName?: string;
        lastName: string;
      }>;
    }
  ): Promise<{ success: boolean; message: string }> {
    return this.fetch(`/admin/ota/bookings/${bookingId}/resend-ticket-confirmation-email`, {
      method: 'POST',
      body: JSON.stringify(request || {}),
    });
  }

  async downloadTickets(bookingId: string): Promise<Blob> {
    const response = await fetch(`${this.baseUrl}/admin/ota/bookings/${bookingId}/tickets`, {
      headers: { 'Authorization': `Bearer ${this.token}` },
    });
    return response.blob();
  }
}

// Example usage
async function customerSupportWorkflow(api: AdminBookingAPI) {
  // Customer reports no tickets received
  const customerEmail = 'john@example.com';
  
  // 1. Find booking
  const { bookings } = await api.getAllBookings({
    search: customerEmail,
    status: 'TICKETED',
  });
  
  if (bookings.length === 0) {
    console.log('No ticketed bookings found');
    return;
  }
  
  const booking = bookings[0];
  console.log(`Found booking: ${booking.bookingCode}`);
  
  // 2. Download tickets for verification
  const ticketsBlob = await api.downloadTickets(booking.id);
  console.log(`Downloaded tickets: ${ticketsBlob.size} bytes`);
  
  // 3. Resend confirmation email
  const result = await api.resendTicketConfirmationEmail(booking.id, {
    emails: [customerEmail],
    ccEmails: ['support@hhr.com'],
  });
  
  console.log(result.message);
}

Error Handling ​

401 Unauthorized ​

json
{
  "statusCode": 401,
  "message": "Unauthorized",
  "error": "Unauthorized"
}

Solution: Provide valid admin JWT token.

403 Forbidden ​

json
{
  "statusCode": 403,
  "message": "Admin access required",
  "error": "Forbidden"
}

Solution: User must have ADMIN role.

404 Booking Not Found ​

json
{
  "statusCode": 404,
  "message": "Booking not found",
  "error": "Not Found"
}

Solution: Verify booking ID is correct.

400 Invalid Status for Ticketing Retry ​

json
{
  "statusCode": 400,
  "message": "Booking is not in a valid state for ticketing retry",
  "error": "Bad Request"
}

Solution: Booking must be in CONFIRMED or TICKETING_IN_PROGRESS status.

400 Booking Not Cancelled ​

json
{
  "statusCode": 400,
  "message": "Booking is not cancelled",
  "error": "Bad Request"
}

Solution: Resend cancellation email only works for CANCELLED bookings.

400 Booking Not Ticketed ​

json
{
  "statusCode": 400,
  "message": "Booking is not ticketed",
  "error": "Bad Request"
}

Solution: Resend confirmation email only works for TICKETED bookings.

502 Bad Gateway ​

json
{
  "statusCode": 502,
  "message": "GO7 API error",
  "error": "Bad Gateway"
}

Solution: GO7 OTA service is unavailable. Try again later.
