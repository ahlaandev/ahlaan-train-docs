Admin Roles & Permissions Guide ​

This guide explains how administrators can manage admin roles, permissions, and user assignments.

Quick Overview ​

FeatureDescription
PurposeManage admin roles and fine-grained permissions
AccessAdmin only
ScopeAll admin users and their permissions

Base URL ​

All roles endpoints use:

/api/v1

Authentication ​

All roles endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. Create Admin Role ​

Endpoint: POST /admin/roles

Create a new admin role with specific permissions.

Request Body:

json
{
  "name": "Finance Manager",
  "description": "Can manage invoices and payments",
  "permissions": [
    "invoices:create",
    "invoices:read",
    "invoices:update",
    "wallets:read"
  ],
  "isActive": true
}

Permissions use the format <resource>:<action> (colon-separated). Wildcards are supported: * (super admin), <resource>:* (all actions on a resource, e.g. invoices:*), and *:read (read access to all resources).

Response: 201 Created

json
{
  "id": "role-uuid",
  "name": "Finance Manager",
  "description": "Can manage invoices and payments",
  "permissions": [
    "invoices:create",
    "invoices:read",
    "invoices:update",
    "wallets:read"
  ],
  "isActive": true,
  "createdAt": "2026-01-31T10:00:00Z"
}

2. List All Admin Roles ​

Endpoint: GET /admin/roles

Get all admin roles with optional filtering.

Query Parameters:

ParameterTypeDescription
isActivebooleanFilter by active status
pagenumberPage number (default: 1)
limitnumberItems per page (default: 20)

Example:

bash
GET /admin/roles?isActive=true

Response: 200 OK

json
{
  "data": [
    {
      "id": "role-uuid",
      "name": "Finance Manager",
      "description": "Can manage invoices and payments",
      "permissions": ["invoices:create", "invoices:read"],
      "isActive": true,
      "createdBy": "admin-uuid",
      "createdAt": "2026-01-31T10:00:00Z",
      "updatedAt": "2026-01-31T10:00:00Z",
      "_count": { "userRoles": 5 }
    }
  ],
  "meta": {
    "total": 10,
    "page": 1,
    "limit": 20,
    "totalPages": 1
  }
}

Endpoint: GET /admin/roles/:id

Get details of a specific role.

Response: 200 OK

json
{

  "name": "Finance Manager",
  "description": "Can manage invoices and payments",

  ],

    }
  ],
  "createdAt": "2026-01-31T10:00:00Z",
  "updatedAt": "2026-01-31T10:00:00Z"

5. Update Admin Role ​

Endpoint: PATCH /admin/roles/:id

Update an existing role.

Request Body: (all fields optional)

json
{
  "name": "Senior Finance Manager",
  "description": "Can manage all finance operations",
  "permissions": [
    "invoices:*",
    "wallets:*",
    "pricing:*",
    "bookings:refund"
  ],
  "isActive": true
}

Response: 200 OK

json
{
  "id": "role-uuid",
  "name": "Senior Finance Manager",
  "description": "Can manage all finance operations",
  "permissions": ["invoices:*", "wallets:*", "pricing:*", "bookings:refund"],
  "isActive": true,
  "updatedAt": "2026-01-31T11:00:00Z"
}

6. Deactivate Admin Role ​

Endpoint: DELETE /admin/roles/:id

Soft delete a role by setting isActive to false.

Response: 200 OK

json
{
  "success": true,
  "message": "Role deactivated successfully"
}

User Role Assignment ​

7. Assign Role to User ​

Endpoint: POST /admin/roles/users/:userId/roles

Assign a role to a user.

Request Body:

json
{
  "roleId": "role-uuid"
}

Response: 200 OK

json
{
  "userId": "user-uuid",
  "roleId": "role-uuid",
  "assignedAt": "2026-01-31T12:00:00Z",
  "assignedBy": "admin-uuid"
}

8. Revoke Role from User ​

Endpoint: DELETE /admin/roles/users/:userId/roles/:roleId

Remove a role assignment from a user.

Response: 200 OK

json
{
  "success": true,
  "message": "Role revoked successfully"
}

9. Get User Roles ​

Endpoint: GET /admin/roles/users/:userId/roles

Get all roles assigned to a user. Returns a bare array of full role objects (only roles whose isActive is true are included).

Response: 200 OK

json
[
  {
    "id": "role-uuid",
    "name": "Finance Manager",
    "description": "Can manage invoices and payments",
    "permissions": ["invoices:create", "invoices:read", "wallets:read"],
    "isActive": true,
    "createdBy": "admin-uuid",
    "createdAt": "2026-01-01T00:00:00Z",
    "updatedAt": "2026-01-01T00:00:00Z"
  }
]

10. Get User Effective Permissions ​

Endpoint: GET /admin/roles/users/:userId/permissions

Get all effective permissions for a user (merged from all assigned roles).

Response: 200 OK

json
{
  "permissions": [
    "invoices:create",
    "invoices:read",
    "invoices:update",
    "invoices:void",
    "wallets:read",
    "bookings:refund"
  ]
}

11. Get Current Admin Permissions ​

Endpoint: GET /admin/roles/users/me/permissions

Get the current logged-in admin's permissions.

Response: 200 OK

json
{
  "permissions": ["*"]
}

Available Permissions ​

Permissions follow the format <resource>:<action>. Wildcards: <resource>:* grants all actions on a resource, *:read grants read access to every resource, and * grants everything (super admin).

Predefined Role Templates ​

Super Admin ​

Full system access - can perform all administrative operations.

Permissions: *

Best for: System owners, CTO, technical founders

User Manager ​

Manage users and organizations.

Permissions:

  • users:*
  • organizations:*
  • audit-logs:read

Best for: Account/operations managers handling users and organizations

Finance Admin ​

Manage financial operations including wallets, invoices, and pricing.

Permissions:

  • wallets:*
  • invoices:*
  • pricing:*
  • bookings:refund
  • exchange-rates:*
  • audit-logs:read

Best for: Finance team leads, accountants

Support Agent ​

Customer support operations - view and cancel bookings.

Permissions:

  • users:read
  • organizations:read
  • bookings:read
  • bookings:cancel
  • wallets:read
  • invoices:read

Best for: Customer support agents

Reports Viewer ​

Read-only access for reporting and analytics.

Permissions:

  • *:read
  • users:stats
  • organizations:stats
  • bookings:stats
  • invoices:stats
  • audit-logs:read

Best for: Analysts, reporting/finance reviewers

Booking Manager ​

Manage bookings and related operations.

Permissions:

  • bookings:*
  • users:read
  • organizations:read
  • invoices:read
  • audit-logs:read

Best for: Operations team leads, booking desk managers

Permission Merging ​

When a user has multiple roles, permissions are merged:

User: John Admin
Roles: [Finance Admin, Support Agent]

Finance Admin permissions:
  - invoices:*
  - wallets:*

Support Agent permissions:
  - bookings:read
  - users:read

Effective permissions (union):
  - invoices:*
  - wallets:*
  - bookings:read
  - users:read

Need Help? ​

For questions or issues:

  1. Use predefined templates for common roles
  2. Assign minimum required permissions (principle of least privilege)
  3. Regularly review and audit role assignments
  4. Test new roles with a test user first
