Booking Management ​

Admin tools for managing customer bookings across the platform.

Overview ​

The booking management APIs allow administrators to:

  • List All Bookings - View all bookings with advanced filtering and pagination
  • Download Tickets - Download ticket PDFs for any booking by booking code
  • Resend Cancellation Email - Resend cancellation emails for cancelled bookings
  • Resend Ticket Confirmation Email - Resend ticket confirmation emails for ticketed bookings

List All Bookings ​

Get a paginated list of all bookings across the platform with comprehensive filtering options. Admins can see all users' bookings.

http
GET /api/v1/admin/ota/bookings
Authorization: Bearer <your-admin-jwt-token>

Query Parameters ​

ParameterTypeDefaultDescription
pagenumber1Page number (minimum: 1)
limitnumber20Items per page (1-100)
searchstring-Search by booking code, user name, user email, organization name, or organization code
statusstring-Filter by booking status: PENDING, CONFIRMED, TICKETING_IN_PROGRESS, TICKETED, CANCELLED, FAILED
bookingCodestring-Filter by booking code (partial match, case-insensitive)
userIdstring-Filter by user ID
organizationIdstring-Filter by organization ID
createdDateFromstring-Filter by creation date from (YYYY-MM-DD)
createdDateTostring-Filter by creation date to (YYYY-MM-DD)
departureDateFromstring-Filter by departure date from (YYYY-MM-DD)
departureDateTostring-Filter by departure date to (YYYY-MM-DD)
sortBystringcreatedAtSort by: createdAt, departureDate, totalAmount
sortOrderstringdescSort order: asc, desc

Download Tickets (Admin) ​

Download ticket PDFs for any booking by booking code. This is useful for helping users who didn't receive their tickets.

http
GET /api/v1/ota/admin/bookings/code/:bookingCode/tickets
Authorization: Bearer <your-admin-jwt-token>

Path Parameters ​

ParameterTypeRequiredDescription
bookingCodestringYesThe booking code (7-character alphanumeric)

Response ​

Success (200 OK): Returns a PDF file with QR codes for each passenger

Content-Type: application/pdf
Content-Disposition: attachment; filename=tickets-ABC1234.pdf

Error Responses:

StatusDescription
401 UnauthorizedAdmin access required
403 ForbiddenUser is not an admin
404 Not FoundBooking not found

Usage Example ​

bash
curl -X GET "https://api.example.com/api/v1/ota/admin/bookings/code/ABC1234/tickets" \
  -H "Authorization: Bearer <your-admin-jwt-token>" \
  -o tickets.pdf

Resend Cancellation Email ​

Resend a cancellation email for a cancelled booking. This is useful when customers report not receiving the original cancellation email from GO7 (Worldticket).

http
POST /api/v1/admin/ota/bookings/:id/resend-cancellation-email
Authorization: Bearer <your-admin-jwt-token>
Content-Type: application/json

Path Parameters ​

ParameterTypeRequiredDescription
idstringYesThe booking ID (UUID)

Request Body ​

All fields are optional. If not provided, defaults will be used.

json
{
  "emails": ["customer@example.com"],
  "ccEmails": ["admin@example.com"],
  "bccEmails": ["audit@example.com"]
}
FieldTypeRequiredDescription
emailsstring[]NoOverride recipient email addresses. If not provided, uses the booking user's email.
ccEmailsstring[]NoCC email addresses
bccEmailsstring[]NoBCC email addresses

Response ​

Success (200 OK):

json
{
  "success": true,
  "message": "Cancellation email sent to customer@example.com"
}

Error Responses:

StatusDescription
404 Not FoundBooking does not exist
400 Bad RequestBooking is not cancelled
400 Bad RequestBooking does not have an OTA reference
502 Bad GatewayGO7 API error

Resend Ticket Confirmation Email ​

Resend a ticket confirmation email for a ticketed booking. This is useful when customers report not receiving the original ticket confirmation email from GO7 (Worldticket).

http
POST /api/v1/admin/ota/bookings/:id/resend-ticket-confirmation-email
Authorization: Bearer <your-admin-jwt-token>
Content-Type: application/json

Path Parameters ​

ParameterTypeRequiredDescription
idstringYesThe booking ID (UUID)

Request Body ​

All fields are optional. If not provided, defaults will be used.

json
{
  "emails": ["customer@example.com"],
  "ccEmails": ["admin@example.com"],
  "bccEmails": ["audit@example.com"],
  "passengers": [
    {
      "firstName": "John",
      "middleName": "Michael",
      "lastName": "Doe"
    }
  ]
}
FieldTypeRequiredDescription
emailsstring[]NoOverride recipient email addresses. If not provided, uses the booking user's email.
ccEmailsstring[]NoCC email addresses
bccEmailsstring[]NoBCC email addresses
passengersPassengerNameDto[]NoOverride passenger names. If not provided, extracts from booking data.

Response ​

Success (200 OK):

json
{
  "success": true,
  "message": "Ticket confirmation email sent to customer@example.com"
}

Error Responses:

StatusDescription
404 Not FoundBooking does not exist
400 Bad RequestBooking is not ticketed
400 Bad RequestBooking does not have an OTA reference
400 Bad RequestNo passenger data available
400 Bad RequestNo recipient email available
502 Bad GatewayGO7 API error

How It Works ​

List All Bookings ​

  1. Query Building: Constructs database query based on provided filters
  2. Search: If search is provided, searches across booking code, user name, user email, organization name, and organization code
  3. Pagination: Applies page and limit for efficient data retrieval
  4. Sorting: Sorts results by specified field and order

Download Tickets (Admin) ​

  1. Authorization: Verifies the user has ADMIN role
  2. Booking Lookup: Finds the booking by booking code
  3. OTA Reference Check: Ensures the booking has an OTA booking reference
  4. Download: Fetches tickets from GO7 API and returns as PDF

Resend Cancellation Email ​

  1. Fetch Booking: Retrieves booking with user and organization details
  2. Validate Status: Verifies the booking is in CANCELLED status
  3. Check OTA Reference: Ensures the booking has an OTA booking reference (GO7 record locator)
  4. Determine Recipients: Uses provided emails or defaults to the booking user's email
  5. Call GO7 API: Sends the request to GO7's /notifications/cancellation-email endpoint
  6. Create Audit Log: Records the action with admin user details and email recipients

Resend Ticket Confirmation Email ​

  1. Fetch Booking: Retrieves booking with user and organization details
  2. Validate Status: Verifies the booking is in TICKETED status
  3. Check OTA Reference: Ensures the booking has an OTA booking reference (GO7 record locator)
  4. Extract Passengers: Extracts passenger names from booking data (REGULAR or GROUP booking structure) if not provided in request
  5. Determine Recipients: Uses provided emails or defaults to the booking user's email
  6. Call GO7 API: Sends the request to GO7's /notifications/email endpoint with passenger data
  7. Create Audit Log: Records the action with admin user details, email recipients, and passenger count

Common Use Cases ​

Customer Support: Ticket Recovery ​

When a customer contacts support because they can't access their tickets:

  1. Use the "List All Bookings" endpoint with search=<customer_email> to find their booking
  2. Note the bookingCode from the response
  3. Use the "Download Tickets" endpoint to get the PDF
  4. Email the PDF to the customer

Email Delivery Issues ​

When a customer reports they didn't receive their cancellation email:

  1. Find the booking using the "List All Bookings" endpoint
  2. Verify the booking status is CANCELLED
  3. Use the "Resend Cancellation Email" endpoint
  4. Optionally add your email as CC to verify delivery

Changed Email Address ​

When a customer changed their email and needs the cancellation email resent:

bash
curl -X POST "/api/v1/admin/ota/bookings/:id/resend-cancellation-email" \
  -H "Authorization: Bearer <token>" \
  -d '{"emails": ["newemail@example.com"]}'

Reporting: Cancelled Bookings Report ​

Generate a report of all cancelled bookings for a specific period:

bash
curl -X GET "/api/v1/admin/ota/bookings?status=CANCELLED&createdDateFrom=2025-01-01&createdDateTo=2025-01-31&limit=100" \
  -H "Authorization: Bearer <token>"

Ticket Confirmation Email Issues ​

When a customer reports they didn't receive their ticket confirmation email:

  1. Find the booking using the "List All Bookings" endpoint
  2. Verify the booking status is TICKETED
  3. Use the "Resend Ticket Confirmation Email" endpoint
  4. Optionally add your email as CC to verify delivery

Resend Confirmation to New Email ​

When a customer changed their email and needs the ticket confirmation email resent:

bash
curl -X POST "/api/v1/admin/ota/bookings/:id/resend-ticket-confirmation-email" \
  -H "Authorization: Bearer <token>" \
  -d '{"emails": ["newemail@example.com"]}'
