BlockSeat Bookings Guide (Admin) ​

Admin management of BlockSeat (wholesale) bookings. These endpoints reuse the Admin OTA Booking service verbatim — list, detail, modify, cancel + refund, retry-ticketing, follow-ups, and status history all behave identically — scoped to bookingVariant = BLOCKSEAT.

BlockSeat rides the standard OTA booking flow (real supplier GROUP reservation, async ticketing). There is no manifest, no auto-confirm, and no ticket-channel / capital-price machinery — that was the custom-booking model and does not apply here.

ECONOMY-only (new bookings). BlockSeat is an ECONOMY-only product (policy 2026-06-20): new wholesale search/calculate/book reject BUSINESS class. The rule is forward-only — any BlockSeat BUSINESS booking taken before the rule remains fully manageable here (list, detail, modify, cancel + refund, retry-ticketing).

All require admin JWT (@Roles(ADMIN)).

MethodPathDescription
GET/api/v1/admin/blockseat-bookings/bookingsList BlockSeat bookings (filters + pagination + sort). Scoped to BLOCKSEAT.
GET/api/v1/admin/blockseat-bookings/bookings/:idFull detail (_admin section). Scoped to BLOCKSEAT (404 for a standard OTA row).
PATCH/api/v1/admin/blockseat-bookings/bookings/:id/modifyModify (Type 4 names, Type 9 contact, Type 40 info, Type 10 cancel segment).
POST/api/v1/admin/blockseat-bookings/bookings/:id/cancelCancel + refund (reason required; auto-records follow-up).
POST/api/v1/admin/blockseat-bookings/bookings/:id/retry-ticketingRe-queue ticketing for a CONFIRMED / stuck booking.
GET/api/v1/admin/blockseat-bookings/bookings/:id/ticketsDownload tickets (ZIP).
POST/api/v1/admin/blockseat-bookings/bookings/:id/follow-upRecord an admin follow-up (outreach / note).
GET/api/v1/admin/blockseat-bookings/bookings/:id/follow-upsList the follow-up trail.
GET/api/v1/admin/blockseat-bookings/bookings/:id/status-historyLifecycle/ticketing trail (newest first).

Example — list BlockSeat bookings ​

GET /api/v1/admin/blockseat-bookings/bookings?limit=2 (admin JWT). Scoped to bookingVariant = BLOCKSEAT — a standard OTA booking never appears here.

Payment, ticketing, expiry, and refund behaviour are shared with standard OTA bookings — see Admin OTA Booking for full field-level detail of each operation. Wholesale route reducers are configured under Custom Route Pricing — BlockSeat shares the same CustomRoutePrice reducer (per (origin, destination, tripClass)) as the promo/custom-OTA flow; the reducer applies to every cabin class for BlockSeat (including BUSINESS).

Payment gateways. BlockSeat invoices may only be settled through the gateways listed in the BLOCKSEAT_ALLOWED_PAYMENT_GATEWAYS env (comma-separated; default XENDIT,WALLET). Only XENDIT (IDR online) and WALLET (instant balance hold) can settle a BlockSeat invoice — MANUAL_TRANSFER / MIDTRANS / STRIPE are rejected at startup if listed. Set it to XENDIT to lock BlockSeat to online Xendit payment only. Enforcement is authoritative server-side (at generate-payment), mirrored at the book entry, and reflected in the invoice's available-gateways listing.
