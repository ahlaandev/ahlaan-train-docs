B2B Applications Management Guide ​

This guide explains how administrators can review, approve, and reject B2B partner applications.

Quick Overview ​

FeatureDescription
PurposeManage B2B partner application workflow
AccessAdmin only
ScopeAll B2B partner applications

Base URL ​

All B2B application endpoints use:

/api/v1

Authentication ​

All B2B application endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Application Workflow ​

┌─────────────────────────────────────────────────────────────────┐
│                    B2B APPLICATION WORKFLOW                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. User submits B2B application                                 │
│     Status: PENDING                                             │
│                        ↓                                         │
│  2. Admin reviews application                                    │
│     Status: UNDER_REVIEW                                        │
│                        ↓                                         │
│  3. Admin decision:                                              │
│     ├─ APPROVE → Creates organization, wallet, updates role     │
│     └─ REJECT → Application closed with reason                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Endpoints ​

1. List All B2B Applications ​

Endpoint: GET /admin/b2b-applications

Get all B2B applications with optional filtering. Returns a simplified view with essential information only. Use the detail endpoint (GET /admin/b2b-applications/:id) for complete information.

Query Parameters:

ParameterTypeDescription
statusenumFilter: PENDING, UNDER_REVIEW, APPROVED, REJECTED
searchstringSearch by company name, NIB, NPWP, or company email
pagenumberPage number (default: 1)
limitnumberItems per page (default: 10)

Example:

bash
GET /admin/b2b-applications?status=PENDING&page=1&limit=10

3. Mark Application as Under Review ​

Endpoint: POST /admin/b2b-applications/:id/review

Change application status to UNDER_REVIEW when admin starts reviewing it.

Response: 200 OK

json
{
  "id": "app-uuid",
  "status": "UNDER_REVIEW",
  "updatedAt": "2026-01-31T11:00:00Z"
}

4. Approve B2B Application ​

Endpoint: POST /admin/b2b-applications/:id/approve

Approve a B2B application. This creates:

  • Organization with unique code
  • Wallet for the organization
  • Updates user role to B2B

5. Reject B2B Application ​

Endpoint: POST /admin/b2b-applications/:id/reject

Reject a B2B application with a reason.

Request Body:

json
{
  "reason": "Business license expired. Please provide valid license."
}

Response: 200 OK

json
{
  "id": "app-uuid",
  "status": "REJECTED",
  "rejectedAt": "2026-01-31T12:00:00Z",
  "rejectedBy": "admin-uuid",
  "rejectionReason": "Business license expired. Please provide valid license.",
  "adminNote": null
}

Approval Workflow ​

Step 1: Review Application ​

bash
# Get application details
GET /admin/b2b-applications/:id

# Mark as under review
POST /admin/b2b-applications/:id/review

Step 2: Verify Documents ​

Check the following:

  • Business license is valid and not expired
  • Tax ID matches company records
  • Address is complete and verifiable
  • Contact information is valid

Step 3: Approve with Organization Details ​

bash
POST /admin/b2b-applications/:id/approve
{
  "organizationName": "Company Name",
  "organizationCode": "UNIQUE_CODE",
  "creditLimit": 50000.00,
  "adminNote": "Verification notes"
}

What happens on approval:

  1. Organization is created with provided details
  2. Wallet is automatically created for the organization
  3. User role is changed from B2C to B2B
  4. User is linked to the organization
  5. Application status is set to APPROVED

Rejection Workflow ​

When rejecting an application, always provide a clear reason:

bash
POST /admin/b2b-applications/:id/reject
{
  "reason": "Clear explanation of why application is rejected"
}

Common rejection reasons:

  • Invalid or expired business license
  • Incomplete documentation
  • Suspicious business information
  • Duplicate application from same user/company

Organization Code Guidelines ​

When approving an application, provide a unique organization code:

  • Length: 3-20 characters
  • Characters: Letters, numbers, underscores
  • Format: Typically uppercase abbreviation + numbers
  • Examples: HAJAR01, TRAVEL_UMRAH, MAKKAH123

Need Help? ​

For questions or issues:

  1. Verify all documents before approving
  2. Ensure organization code is unique
  3. Set appropriate credit limits based on business size
  4. Keep clear admin notes for audit trail
