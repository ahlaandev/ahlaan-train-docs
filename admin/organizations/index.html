Organizations Management Guide ​

This guide explains how administrators manage B2B organizations — the records that back approved B2B partners. Organizations are normally created automatically when a B2B application is approved, but admins can also create, update, deactivate, and audit them directly through this API surface. Wallets, public API access, pricing, and tax rules all key off these records.

Quick Overview ​

FeatureDescription
PurposeManage the B2B organizations referenced by users, wallets, bookings, and API keys
AccessADMIN role plus Access Role permissions: reads need organizations:read, stats need organizations:stats, create needs organizations:create, edits (update, activate, pricing-tier, promo-access, special-custom-b2b-pricing) need organizations:update, and deactivate plus orphan cleanup need organizations:delete. See Access Roles
ScopeList/search organizations, view stats, manage members, audit and clean up orphans
Soft vs hard deleteDELETE /:id only deactivates (isActive=false) and demotes B2B members to B2C. Hard deletion happens only via the orphan cleanup endpoint, and only for organizations with zero related records.
ReactivationPATCH /:id/activate reactivates the org and restores its auto-demoted members to B2B.
B2C ignores org rulesA user with role B2C ignores every organization-scoped rule (pricing, tax, special-B2B, org wallet, org ticket access, org attribution, and org-inherited promo-host access) even if an organizationId is still attached. A B2C promo customer must carry an explicit per-user promoAccessEnabled = true.

Base URL ​

All organization endpoints use:

/api/v1

Authentication ​

All endpoints in this guide require:

  • JWT Token in the Authorization header
  • ADMIN role in the user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. List Organizations ​

Endpoint: GET /admin/organizations

Returns a paginated list of organizations with member and active-API-key counts.

Query Parameters:

ParameterTypeRequiredDescription
isActivebooleanNoFilter by active flag
publicApiEnabledbooleanNoFilter by public-API allow-list flag (true = allowed to mint public API keys, false = disabled). See Public API Access.
specialCustomPricingEnabledbooleanNoFilter by the special custom B2B pricing flag.
promoAccessEnabledbooleanNoFilter by the promo-host access bulk-grant flag.
searchstringNoCase-insensitive partial match on the organization name, code, phone, or email. Blank/whitespace is ignored. Composes with the filters above (AND).
pagenumberNoPage number (default: 1)
limitnumberNoItems per page (default: 20)

Example:

bash
curl -X GET "/api/v1/admin/organizations?publicApiEnabled=true&page=1&limit=20" \
  -H "Authorization: Bearer <admin-jwt>"

Response: 200 OK

json
{
  "data": [
    {
      "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e5f",
      "name": "Hajar Travel Umrah & Haji",
      "code": "HTUH01",
      "address": "Jl. Sudirman No. 123, Jakarta",
      "phone": "628123456789",
      "email": "info@hajartravel.com",
      "picName": "Budi Santoso",
      "picEmail": "budi@hajartravel.com",
      "picPhone": "628111111111",
      "isActive": true,
      "publicApiEnabled": true,
      "specialCustomPricingEnabled": false,
      "promoAccessEnabled": false,
      "pricingTier": "SILVER",
      "userCount": 4,
      "activeApiKeyCount": 2,
      "createdAt": "2026-01-31T10:00:00Z",
      "partner": { "registrationNumber": "MG.010", "name": "Hajar Travel Umrah & Haji" }
    }
  ],
  "meta": {
    "total": 12,
    "page": 1,
    "limit": 20,
    "totalPages": 1
  }
}

activeApiKeyCount only counts keys that have not been revoked and are not expired.

Host-gated (Option A). specialCustomPricingEnabled, promoAccessEnabled, and pricingTier are returned only on the mitra host (mitra.ahlaan.co.id and subdomains); on every other host they are stripped from the list, the detail (GET /admin/organizations/:id), and the org-users (GET /admin/organizations/:id/users) responses. The partner field ({ registrationNumber, name }, or null when no numbered registration resolves) is likewise emitted only on the mitra host. partner is MEMBER-complete: it resolves an org that hosts a member numbered on its targetOrganizationId link, not only a NEW_ORG registration. Write endpoints (create / update) are not host-gated and do not carry partner.

specialCustomPricingEnabled distinguishes special custom-ota/custom-booking B2B pricing organizations from regular ones. The flag is effective only on the promo host — when true and the request arrives on promo.ahlaan.co.id (or a subdomain; configurable via PROMO_BASE_DOMAIN), the organization's users are priced through the special pipeline: an ECONOMY-only per-route SAR priceReducer, an exchangeRateReducer applied to the SAR→IDR conversion of both ECONOMY and BUSINESS legs, and an opt-in ECONOMY price cap. On any other host (tiket, blockseat, localhost) the org is priced as normal even when the flag is true. Toggle it via the Special Custom B2B Pricing enroll endpoint.

pricingTier (SILVER default, or GOLD) is the organization's pricing tier and the source of truth for special pricing: GOLD unlocks the special levers, SILVER is promo-eligible non-special. specialCustomPricingEnabled is now a deprecated mirror of this field (GOLD ⇔ true), kept in lockstep so existing readers keep working. Set the tier via the Pricing Tier endpoint below (preferred) — the legacy special-pricing toggle still works but is deprecated.

promoAccessEnabled (default false) is the organization-level bulk grant for promo-host access. A user's effective promo access is their per-user promoAccessEnabled override (true/false) coalesced with this org flag when the override is null — so enabling it grants promo access to every member who has not been individually overridden. Promo access does not require an organization (a user can be granted directly); see Promo Customer Onboarding. It is orthogonal to specialCustomPricingEnabled, which unlocks the special B2B pricing levers; an org can have promo access without special pricing. Toggle it via the promo-access endpoint below.

2. Get Organization Statistics ​

Endpoint: GET /admin/organizations/stats

Returns aggregate B2B counts and revenue. Revenue sums totalAmountSAR across TICKETED bookings tied to any organization.

Response: 200 OK

json
{
  "total": 12,
  "active": 10,
  "inactive": 2,
  "totalB2BBookings": 348,
  "totalB2BRevenue": 95420.5
}
FieldTypeDescription
totalnumberAll organizations
activenumberOrganizations with isActive=true
inactivenumberSoft-deactivated organizations
totalB2BBookingsnumberAll bookings linked to any organization
totalB2BRevenuenumberSum of totalAmountSAR on TICKETED B2B bookings

3. List Orphan Organizations ​

Endpoint: GET /admin/organizations/orphans

Returns organizations that have no users (members), along with counts of every related record type so admins can decide whether they're safe to remove.

Response: 200 OK

json
{
  "count": 2,
  "organizations": [
    {
      "id": "01h6abandoned",
      "name": "Stale Tour Co",
      "code": "STC07",
      "isActive": false,
      "createdAt": "2025-09-12T03:21:00Z",
      "relatedRecords": {
        "bookings": 0,
        "invoices": 0,
        "files": 0,
        "pricingRules": 0,
        "taxRules": 0,
        "refunds": 0,
        "notifications": 0,
        "wallet": false,
        "application": false
      },
      "canBeDeleted": true
    }
  ]
}

canBeDeleted is true only when every counter is 0 and both wallet and application are false.

4. Remove Orphan Organizations ​

Endpoint: DELETE /admin/organizations/orphans

Bulk-removes organizations with no users and no related records. Organizations that have any related data are skipped, not force-deleted.

Response: 200 OK

json
{
  "deletedCount": 1,
  "deletedIds": ["01h6abandoned"],
  "skippedIds": ["01h6hasbookings"]
}
FieldDescription
deletedCountNumber of organizations actually removed
deletedIdsIDs that were hard-deleted
skippedIdsOrphans that still have related records (bookings, invoices, files, pricing rules, tax rules, refunds, notifications, a wallet, or a B2B application)

Hard deletion

This is the only endpoint in this guide that hard-deletes organization rows. It is intentionally conservative — anything with downstream data is left in place. Use the orphan list endpoint first to preview what would happen.

6. List Users in an Organization ​

Endpoint: GET /admin/organizations/:id/users

Paginated list of users linked to the organization.

Query Parameters:

ParameterTypeRequiredDescription
pagenumberNoPage number (default: 1)
limitnumberNoItems per page (default: 20)

Response: 200 OK

json
{
  "organization": {
    "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e5f",
    "name": "Hajar Travel Umrah & Haji",
    "specialCustomPricingEnabled": false,
    "promoAccessEnabled": false,
    "pricingTier": "SILVER",
    "partner": { "registrationNumber": "MG.010", "name": "Hajar Travel Umrah & Haji" }
  },
  "data": [
    {
      "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e61",
      "email": "ahmad@hajartravel.com",
      "name": "Ahmad Abdullah",
      "role": "B2B",
      "isActive": true,
      "promoAccessLevel": "PARTNER",
      "impersonationEligible": true
    }
  ],
  "meta": {
    "total": 4,
    "page": 1,
    "limit": 20,
    "totalPages": 1
  }
}

The top-level organization block carries the parent organization's promo flags (specialCustomPricingEnabled, promoAccessEnabled, pricingTier) plus its partner identity so admins can see, while browsing an organization's members, whether those users belong to a special-pricing / partner organization. Each member row additionally carries promoAccessLevel (the 4-state mitra access level) and impersonationEligible (whether an admin may "act as" that member — the same predicate POST /admin/impersonation/start enforces). All of these — the org promo flags, partner, and the per-member promoAccessLevel / impersonationEligible — are returned only on the mitra host (Option A); off it they are stripped and each member row is just id / email / name / role / isActive.

Errors:

StatusMessage
404Organization not found

7. Create Organization ​

Endpoint: POST /admin/organizations

Creates a new organization and automatically provisions an organization wallet (SAR currency).

Request Body:

json
{
  "name": "PT Teknologi Maju Bersama",
  "code": "PTMB-001",
  "address": "Jl. Sudirman No. 123, Jakarta Pusat",
  "phone": "628123456789",
  "email": "info@teknologimaju.com"
}
FieldTypeRequiredConstraints
namestringYesMax 200 characters
codestringYesMax 50 characters; must be unique across organizations
addressstringNoMax 1000 characters
phonestringNoInternational format without + (e.g. 628… for Indonesia, 966… for Saudi Arabia). Validated by IsInternationalPhone.
emailstringNoValid email, max 254 characters; trimmed and lowercased before storage

Response: 201 Created

Returns the canonical organization detail shape, identical to GET /admin/organizations/:id. New organizations start with publicApiEnabled: false and zero counts.

  "publicApiEnabled": false,
  "userCount": 0,
  "activeApiKeyCount": 0,
  "bookingCount": 0,
  "createdAt": "2026-04-28T09:00:00Z",
  "updatedAt": "2026-04-28T09:00:00Z"

publicApiEnabled is not writable from this endpoint — toggle it via PATCH /admin/organizations/:organizationId/public-api/access.

Wallet provisioning

The endpoint creates the organization wallet in the same flow. If wallet creation fails, the failure is logged but the organization is still created — you can retry wallet provisioning separately via Wallet Management without recreating the organization.

8. Update Organization ​

Endpoint: PATCH /admin/organizations/:id

Updates any subset of the organization fields.

Do not reactivate via isActive on this endpoint

Writing { "isActive": true } here only flips the flag — it does not restore the members that were demoted to B2C when the org was deactivated. To fully reactivate an organization and restore its auto-demoted members to B2B, use the dedicated Activate Organization endpoint (PATCH /admin/organizations/:id/activate) instead.

Request Body: (all fields optional)

json
{
  "name": "PT Teknologi Maju Bersama (HQ)",
  "address": "Jl. Sudirman No. 456, Jakarta Pusat",
  "phone": "628123456780",
  "email": "ops@teknologimaju.com",
  "code": "PTMB-002",
  "isActive": true
}

Field constraints match the create endpoint. code is still uniqueness-checked when changed.

Response: 200 OK

Returns the canonical organization detail shape with refreshed counts and updatedAt, identical to GET /admin/organizations/:id.

{
  "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e5f",
  "name": "PT Teknologi Maju Bersama (HQ)",
  "code": "PTMB-002",
  "address": "Jl. Sudirman No. 456, Jakarta Pusat",

publicApiEnabled is not writable from this endpoint — toggle it via PATCH /admin/organizations/:organizationId/public-api/access.

9. Deactivate Organization ​

Endpoint: DELETE /admin/organizations/:id

Soft delete only

This endpoint does not remove the organization. It sets isActive = false, preserving every related record (users, wallets, bookings, invoices, API keys, etc.). To fully remove an organization, you must first detach all members and related records, then use the orphan cleanup endpoint.

Members are demoted to B2C

Deactivation also demotes every current B2B member of the organization to B2C, keeping their organization link attached. A B2C user ignores all organization-scoped rules — ORGANIZATION-target pricing and tax rules, special custom-B2B pricing, org-wallet routing, org ticket access, and org booking/revenue attribution no longer apply to them. Each demoted member is provisioned a personal wallet. Demoted members are marked internally so Activate Organization can restore exactly them. Members that an admin had set to B2C manually while the org was active are left as B2C.

Promo-host access is affected via the same B2C rule: a demoted (now B2C) member no longer inherits promo access from the organization's promoAccessEnabled flag. They keep promo access only if they carry an explicit per-user promoAccessEnabled = true override. To keep a specific demoted member on the promo host, set that override via PATCH /admin/users/:id/promo-access.

Response: 200 OK

json
{
  "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e5f",
  "name": "PT Teknologi Maju Bersama",
  "code": "PTMB-002",
  "isActive": false,
  "demotedMemberCount": 4,
  "success": true,
  "message": "Organization deactivated"
}

Errors:

StatusMessage
404Organization not found

Public API keys are not auto-revoked

Deactivating an organization does not revoke its existing public API keys. To cut off API access during an incident, also revoke the keys via Public API Access.

10. Activate Organization ​

Endpoint: PATCH /admin/organizations/:id/activate

Reactivates a soft-deactivated organization: sets isActive = true and restores to B2B only the members that were auto-demoted by a prior deactivation. Members an admin set to B2C manually while the org was active stay B2C.

Prefer this over PATCH /:id with isActive

PATCH /admin/organizations/:id with { "isActive": true } flips the flag but leaves demoted members as B2C. This endpoint is the correct way to reverse a deactivation.

Request Body: none.

Response: 200 OK

json
{
  "id": "0190f2a1-8b3c-7d4e-9f50-6a1b2c3d4e5f",
  "name": "PT Teknologi Maju Bersama",
  "code": "PTMB-002",
  "isActive": true,
  "restoredMemberCount": 4,
  "success": true,
  "message": "Organization activated"
}

Restored members regain org pricing/access via their organization wallet. Any personal wallet provisioned during demotion is left in place (unused for B2B); balances are not migrated.

Errors:

StatusMessage
404Organization not found

Cleanup Workflow ​

To safely remove an unused organization:

1. Confirm there are no members
   GET /admin/organizations/:id/users

2. Preview related-record counts
   GET /admin/organizations/orphans
   (locate the org and check `relatedRecords` + `canBeDeleted`)

3. Detach or migrate any blocking records
   (bookings, invoices, files, pricing rules, tax rules, refunds, notifications, wallet, application)

4. Run the orphan cleanup
   DELETE /admin/organizations/orphans
   (only orgs with zero related records will be deleted; others are returned in `skippedIds`)

Pricing Tier ​

Set the organization's pricing tier — the source of truth for special pricing. This is the preferred endpoint; it supersedes the deprecated special-pricing toggle below.

http
PATCH /api/v1/admin/organizations/:id/pricing-tier
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "tier": "GOLD"
}

Body: tier is "SILVER" (promo-eligible, non-special) or "GOLD" (special pricing: ECONOMY per-route reducer, IDR exchangeRateReducer, 3.75 USD rate, ECONOMY cap). HOLDER is not assignable.

Setting a tier writes the deprecated specialCustomPricingEnabled mirror (GOLD ⇔ true) in lockstep and auto-grants promo access (promoAccessEnabled = true) so the tier is reachable. Revoke access later via the promo-access endpoint if needed.

Response:

json
{
  "id": "org-uuid",
  "pricingTier": "GOLD",
  "specialCustomPricingEnabled": true,
  "promoAccessEnabled": true
}

See Special Custom B2B Pricing for full configuration (route rules, exchange rate reducer) and the tier model.

Special Custom B2B Pricing Enrollment ​

Deprecated — prefer the Pricing Tier endpoint. This boolean toggle now funnels through the tier setter (enabled → GOLD, disabled → SILVER) and, unlike the tier endpoint, does not change promo access.

Enable or disable the Special Custom B2B Pricing feature for a specific organization. When enabled and the request is on the promo host (promo.ahlaan.co.id or a subdomain), the organization's users receive discounted custom-OTA / custom-booking prices: an ECONOMY-only per-route SAR reducer plus a lower IDR exchange rate applied to the SAR→IDR conversion of both ECONOMY and BUSINESS legs (and an opt-in ECONOMY price cap). Does not apply to standard OTA or BlockSeat, nor on any non-promo host.

http
PATCH /api/v1/admin/organizations/:id/special-custom-b2b-pricing
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "enabled": true
}

Response:

json
{
  "id": "org-uuid",
  "pricingTier": "GOLD",
  "specialCustomPricingEnabled": true,
  "promoAccessEnabled": false
}

See Special Custom B2B Pricing for full configuration (route rules, exchange rate reducer).

Promo-Host Access Enrollment ​

Enable or disable promo-host access for a specific organization. When enabled, users belonging to the organization ("promo customers") can log in and book on the promo frontend (promo.ahlaan.co.id and subdomains) — promo login/booking is closed to everyone else (see the closed-registration behavior on the promo host). Orthogonal to Special Custom B2B Pricing, which additionally unlocks the special pricing levers.

http
PATCH /api/v1/admin/organizations/:id/promo-access
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "enabled": true
}

Response:

json
{
  "id": "org-uuid",
  "promoAccessEnabled": true
}

Errors:

StatusMessage
404Organization not found

Throttled to 30 requests per minute. Every toggle is audit-logged as PROMO_ACCESS_ENABLED / PROMO_ACCESS_DISABLED.

Onboarding a promo customer

  1. Create the organization (POST /admin/organizations) — or reuse an existing one.
  2. Enable the flag: PATCH /admin/organizations/:id/promo-access with { "enabled": true }.
  3. Create users attached to that organization via POST /admin/users with organizationId, or assign an existing user via PATCH /admin/users/:id. B2B/B2C users are passwordless — the promo customer then logs in on the promo host via OTP or Google/Apple.

For the full end-to-end workflow (new vs existing customer, verification, downgrade), see the Promo Customer Onboarding guide.

Revoking access does not strand in-flight bookings

Disabling the flag closes promo login and new promo bookings (create / calculate) for the org's users, but booking lifecycle endpoints (list/detail, passenger updates, ticket download, cancel) are not promo-gated — existing bookings remain fully manageable.

Need Help? ​

For questions or issues:

  1. Use GET /admin/organizations/stats to sanity-check overall counts before debugging individual records.
  2. When an organization seems "stuck", call GET /admin/organizations/orphans to see exactly which related records are blocking removal.
  3. Remember that DELETE /:id is a soft deactivate — to fully reactivate (and restore auto-demoted members to B2B) use PATCH /:id/activate, not PATCH /:id with { "isActive": true } (that flips the flag only and leaves members as B2C). Never recreate the organization.
  4. To fully cut off an organization's external access, deactivate it and revoke its public API keys via Public API Access.
