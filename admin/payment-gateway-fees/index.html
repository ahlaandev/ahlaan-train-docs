Payment Gateway Fee Configuration Guide ​

This guide explains how administrators can configure payment gateway fees for different payment methods.

Quick Overview ​

FeatureDescription
PurposeConfigure transaction fees for payment gateway methods
Applied ToWallet top-ups and booking payments
Fee TypesPercentage-based, Fixed amount, or Combo (percentage + fixed)

Seeded Fee Rules ​

The system comes with pre-configured fee rules for Xendit:

GatewayMethodFee TypeFee ValueFixed FeeMin FeeCurrency
XENDITQRISPERCENTAGE0.65%-0IDR
XENDITBANK_TRANSFERCOMBO0%4,0000IDR
XENDITEWALLETPERCENTAGE1.5%-1,500IDR

Fee Rule Descriptions ​

QRIS (0.65%)

  • Standard QRIS payment fee
  • No minimum fee
  • Most cost-effective for customers

Bank Transfer (Fixed 4,000 IDR)

  • Flat fee regardless of amount
  • Good for large transactions
  • No percentage fee

E-Wallet (1.5% min 1,500 IDR)

  • Percentage fee with minimum
  • Minimum ensures cost coverage for small transactions
  • Applies to GoPay, OVO, Dana, etc.

Base URL ​

All payment gateway fee endpoints use:

/api/v1

Authentication ​

All payment gateway fee endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. List All Fee Rules ​

Endpoint: GET /admin/payment-gateway-fees

Get all configured fee rules.

Query Parameters:

ParameterTypeDescription
gatewayCodestringFilter by gateway (XENDIT, MIDTRANS, STRIPE)
paymentMethodstringFilter by method (QRIS, BANK_TRANSFER, EWALLET, CARD)
isActivebooleanFilter by active status

Response: 200 OK

The response is wrapped in { data, meta }. Rows omit fixedFeeValue when it is unset.

json
{
  "data": [
    {
      "id": "fee-123",
      "gatewayCode": "XENDIT",
      "paymentMethod": "QRIS",
      "feeType": "PERCENTAGE",
      "feeValue": 0.65,
      "applyTo": "CUSTOMER",
      "currency": "IDR",
      "minFee": 0,
      "priority": 0,
      "isActive": true,
      "createdBy": "admin-uuid",
      "createdAt": "2026-01-28T10:00:00Z",
      "updatedAt": "2026-01-28T10:00:00Z"
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "limit": 20,
    "totalPages": 1
  }
}

1a. Get Fee Rule by ID ​

Endpoint: GET /admin/payment-gateway-fees/:id

Fetch a single fee rule by its ID. Returns the same row shape as the list (minus the meta wrapper).

1b. Calculate Fee ​

Endpoint: POST /admin/payment-gateway-fees/calculate

Preview the fee that would be applied for a given gateway/method/amount, using CalculateFeeDto. Useful for showing the customer-facing fee before a payment is created.

2. Create Fee Rule ​

Endpoint: POST /admin/payment-gateway-fees

Add a new fee rule.

Request Body:

json
{
  "gatewayCode": "XENDIT",
  "paymentMethod": "QRIS",
  "feeType": "PERCENTAGE",
  "feeValue": 0.65,
  "applyTo": "CUSTOMER",
  "currency": "IDR",
  "minFee": 0,
  "priority": 0,
  "isActive": true
}

Validation Rules:

FieldValidation
gatewayCodeRequired, valid gateway code
paymentMethodRequired, valid method
feeTypeRequired: PERCENTAGE, FIXED, or COMBO
feeValueRequired (all fee types, including FIXED), @Min(0) — no upper bound
fixedFeeValueRequired for COMBO (added on top of the percentage)
currencyRequired: SAR or IDR
priorityRequired, integer ≥ 0 (resolution order when multiple rules match)
isActiveRequired, boolean
minFeeOptional, minimum fee to apply
maxFeeOptional, cap on the calculated fee
minAmountOptional, minimum transaction amount the rule applies to
maxAmountOptional, maximum transaction amount the rule applies to

Response: 201 Created

json
{
  "id": "019df123-4567-89ab-cdef-0123456789ab",
  "gatewayCode": "XENDIT",
  "paymentMethod": "QRIS",
  "feeType": "PERCENTAGE",
  "feeValue": 0.65,
  "applyTo": "CUSTOMER",
  "currency": "IDR",
  "minFee": 0,
  "priority": 0,
  "isActive": true,
  "createdBy": "admin-uuid",
  "createdAt": "2026-01-28T10:00:00Z",
  "updatedAt": "2026-01-28T10:00:00Z"
}

3. Update Fee Rule ​

Endpoint: PATCH /admin/payment-gateway-fees/:id

Update an existing fee rule.

Request Body:

json
{
  "feeValue": 0.7,
  "minFee": 2000
}

Response: 200 OK

4. Deactivate Fee Rule ​

Endpoint: DELETE /admin/payment-gateway-fees/:id

Soft delete by setting isActive to false.

Response: 200 OK

Fee Calculation Examples ​

Example 1: QRIS Payment (Percentage) ​

Transaction Amount: 100,000 IDR
Fee Rate: 0.65%
─────────────────────────
Fee: 100,000 × 0.0065 = 650 IDR
─────────────────────────
Total: 100,650 IDR

Example 2: Bank Transfer (Fixed) ​

Transaction Amount: 100,000 IDR
Fee: Fixed 4,000 IDR
─────────────────────────
Total: 104,000 IDR

Example 3: E-Wallet (Percentage with Minimum) ​

Transaction Amount: 50,000 IDR
Fee Rate: 1.5%
Calculated Fee: 50,000 × 0.015 = 750 IDR
Minimum Fee: 1,500 IDR
─────────────────────────
Applied Fee: 1,500 IDR (minimum applies)
Total: 51,500 IDR

Example 4: E-Wallet (Percentage with Minimum) ​

Transaction Amount: 200,000 IDR
Fee Rate: 1.5%
Calculated Fee: 200,000 × 0.015 = 3,000 IDR
Minimum Fee: 1,500 IDR
─────────────────────────
Applied Fee: 3,000 IDR (exceeds minimum)
Total: 203,000 IDR

Fee Types ​

TypeDescriptionExample
PERCENTAGEPercentage of transaction amount0.65% = 650 IDR on 100,000 IDR
FIXEDFixed amount regardless of transaction4,000 IDR flat fee
COMBOPercentage + fixed fee0% + 4,000 IDR

ValueDescription

Common Workflows ​

Workflow 1: Create Midtrans Fee Rules ​

Scenario: Configure fees for Midtrans gateway

bash
# QRIS fee
curl -X POST /api/v1/admin/payment-gateway-fees \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "gatewayCode": "MIDTRANS",
    "paymentMethod": "QRIS",
    "feeType": "PERCENTAGE",
    "feeValue": 0.7,
    "applyTo": "CUSTOMER",
    "currency": "IDR",
    "minFee": 0,
    "priority": 0,
    "isActive": true
  }'

# Bank transfer fee
curl -X POST /api/v1/admin/payment-gateway-fees \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "gatewayCode": "MIDTRANS",
    "paymentMethod": "BANK_TRANSFER",
    "feeType": "FIXED",
    "feeValue": 5000,
    "applyTo": "CUSTOMER",
    "currency": "IDR",
    "priority": 0,
    "isActive": true
  }'

Workflow 2: Update Fee Rates ​

Scenario: Increase QRIS fee due to provider rate change

bash
curl -X PATCH /api/v1/admin/payment-gateway-fees/:feeId \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "feeValue": 0.7
  }'

Validation Rules ​

FieldValidation
gatewayCodeMust be valid gateway code (XENDIT, MIDTRANS, STRIPE)
paymentMethodMust be valid method (QRIS, BANK_TRANSFER, EWALLET, CARD)
feeTypeMust be PERCENTAGE, FIXED, or COMBO
feeValueRequired for all fee types, @Min(0) (no upper bound)
fixedFeeValueRequired for COMBO, positive number
currencyMust be SAR or IDR
priorityRequired, integer ≥ 0
isActiveRequired, boolean
minFeeNon-negative number
maxFee / minAmount / maxAmountOptional, non-negative numbers

System Configuration ​

The following system config keys affect fee calculation:

KeyDefaultDescription
PAYMENT_GATEWAY_FEES_ENABLEDfalseMaster switch for fee calculation
FEE_DISPLAY_MODECOMBINEDShow fees combined or separately

Common Issues & Solutions ​

IssueCauseSolution
Fees not being calculatedPAYMENT_GATEWAY_FEES_ENABLED is falseEnable in system config
Wrong fee appliedMultiple rules matchCheck gateway and method combination
Negative feesInvalid inputEnsure feeValue and fixedFeeValue are positive

Need Help? ​

For questions or issues:

  1. Verify the gateway and method combination is unique
  2. Check that fees match payment provider rates
  3. Ensure currency matches gateway (IDR for Indonesian gateways)
  4. Contact technical support for complex fee structures
