Pricing Configuration Guide ​

This guide explains how to configure child and infant pricing percentages for B2B tariff calculations.

Overview ​

The pricing configuration determines how child and infant prices are calculated relative to adult tariff prices. This is a global setting that applies to all B2B tariff calculations.

How It Works ​

When calculating B2B pricing:

Adult Price    = Tariff Price (per adult)
Child Price    = Adult Price × (childPricePercentage / 100)
Infant Price   = Adult Price × (infantPricePercentage / 100)

Example ​

With childPricePercentage: 75 and infantPricePercentage: 0:

Passenger TypeAdult TariffPercentageFinal Price
Adult150 SAR100%150 SAR
Child150 SAR75%112.50 SAR
Infant150 SAR0%0 SAR

Configuration Structure ​

FieldDescriptionExample
idAuto-generated UUIDconfig-abc123
childPricePercentageChild price as % of adult (0-100)75
infantPricePercentageInfant price as % of adult (0-100)0
isActiveWhether this config is currently activetrue
isDefaultTrue if using system defaults (no DB config)false
createdByUser who created the configadmin-123
updatedByUser who last updated the configadmin-456

System Defaults ​

If no configuration exists in the database, the system uses these defaults:

SettingDefault Value
childPricePercentage75%
infantPricePercentage0%

Important: The defaults are only used when no configuration exists. Once you create a configuration, it overrides the defaults.

Get Active Configuration ​

Retrieve the currently active pricing configuration. Returns system defaults if no configuration exists.

http
GET /api/v1/admin/tariff-pricing-config
Authorization: Bearer <token>

json
{

Create Configuration ​

Create a new pricing configuration. If an active configuration exists, it will be deactivated and the new one will become active.

http
POST /api/v1/admin/tariff-pricing-config
Authorization: Bearer <token>
Content-Type: application/json

Request Body ​

json
{
  "childPricePercentage": 80,
  "infantPricePercentage": 10
}
FieldTypeRequiredConstraints
childPricePercentagenumberYes0-100, max 2 decimals
infantPricePercentagenumberYes0-100, max 2 decimals

Response (201 Created) ​

json
{
  "id": "config-new123",
  "childPricePercentage": 80,
  "infantPricePercentage": 10,
  "isActive": true,
  "isDefault": false,
  "createdBy": "admin-123",
  "createdAt": "2026-01-27T10:00:00Z",

Configuration Change Behavior ​

When Creating a New Configuration ​

  1. If an active config exists:

    • The active config is deactivated (isActive: false)
    • The new config becomes active (isActive: true)
    • Old configs are preserved in history

  2. If no config exists:

    • The new config becomes active immediately
    • System defaults are no longer used

Example Timeline ​

Jan 15: Create config (75%, 0%) → Active
Jan 20: Create config (80%, 10%) → Previous deactivated, new active
Jan 25: Update config (85%, 10%) → Active config updated

TypeScript - Manage Configuration ​

typescript
interface CreateConfigDto {
  childPricePercentage: number;
  infantPricePercentage: number;
}

interface UpdateConfigDto {
  childPricePercentage?: number;
  infantPricePercentage?: number;
}

interface PricingConfig {
  id: string | null;
  childPricePercentage: number;
  infantPricePercentage: number;
  isActive: boolean;
  isDefault?: boolean;
  createdBy?: string;
  updatedBy?: string;
  createdAt?: string;
  updatedAt?: string;
}

async function getActiveConfig(adminToken: string): Promise<PricingConfig> {
  const response = await fetch('/api/v1/admin/tariff-pricing-config', {
    headers: { 'Authorization': `Bearer ${adminToken}` },
  });

  if (!response.ok) {
    throw new Error('Failed to get config');
  }

  return await response.json();
}

async function createConfig(
  data: CreateConfigDto,
  adminToken: string
): Promise<PricingConfig> {
  const response = await fetch('/api/v1/admin/tariff-pricing-config', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${adminToken}`,
    },
    body: JSON.stringify(data),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Failed to create config');
  }

  return await response.json();
}

async function updateConfig(
  data: UpdateConfigDto,
  adminToken: string
): Promise<PricingConfig> {
  const response = await fetch('/api/v1/admin/tariff-pricing-config', {
    method: 'PUT',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${adminToken}`,
    },
    body: JSON.stringify(data),
  });

  if (!response.ok) {
    const error = await response.json();
    throw new Error(error.message || 'Failed to update config');
  }

  return await response.json();
}

// Usage: Check if config exists, create if not
async function ensureConfig(adminToken: string) {
  let config = await getActiveConfig(adminToken);

  if (config.isDefault) {
    console.log('Using defaults, creating configuration...');
    config = await createConfig({
      childPricePercentage: 75,
      infantPricePercentage: 0,
    }, adminToken);
    console.log(`Created config: ${config.id}`);
  } else {
    console.log(`Active config: ${config.id}`);
    console.log(`Child: ${config.childPricePercentage}%, Infant: ${config.infantPricePercentage}%`);
  }

  return config;
}

Python - Get History and Compare ​

python
import requests

def get_config_history(admin_token: str, active_only: bool = False):
    """Get pricing configuration history."""
    url = "https://api.example.com/api/v1/admin/tariff-pricing-config/history"
    headers = {"Authorization": f"Bearer {admin_token}"}
    params = {"page": 1, "limit": 50}

    if active_only:
        params["isActive"] = True

    response = requests.get(url, headers=headers, params=params)
    response.raise_for_status()

    data = response.json()

    print(f"Total configurations: {data['meta']['total']}\n")

    for config in data['data']:
        status = "ACTIVE" if config['isActive'] else "INACTIVE"
        print(f"{status} - {config['id']}")
        print(f"  Child: {config['childPricePercentage']}%, "
              f"Infant: {config['infantPricePercentage']}%")
        print(f"  Created: {config['createdAt']}")
        print(f"  Updated: {config['updatedAt']}\n")

    return data

# Example: Get all configuration history
history = get_config_history("your-admin-token")

Best Practices ​

1. Set Configuration Before Creating Tariffs ​

  1. Create pricing configuration first
  2. Then create tariffs
  3. Test B2B search to verify calculations

2. Choose Percentages Based on Business Rules ​

ScenarioRecommended Child %Recommended Infant %
Standard75%0%
Family-friendly50%0%
Full-price children100%0%
Discounted infants75%10%

3. Communicate Changes to Stakeholders ​

  • Price percentage changes apply immediately to all new B2B searches
  • Existing bookings are not affected
  • Notify B2B partners before making changes

4. Use History for Audit ​

  • All configuration changes are preserved in history
  • Track who made changes and when
  • Useful for compliance and dispute resolution

5. Test After Changes ​

After updating configuration:

  1. Run a B2B search with children/infants
  2. Verify calculations are correct
  3. Check pricing in B2B response

Troubleshooting ​

Issue: Cannot update configuration - "No active configuration found" ​

Cause: No configuration exists in the database. You're using system defaults.

Solution:

  1. Use POST to create the first configuration
  2. Then use PUT to update it

Issue: Wrong child price in B2B search ​

Check:

  1. Verify active configuration: GET /api/v1/admin/tariff-pricing-config
  2. Check childPricePercentage value
  3. Verify tariff price is correct
  4. Recalculate manually to verify

Issue: Cannot set percentage above 100 ​

Cause: Validation prevents percentages > 100%.

Solution: Use valid percentage values (0-100).

Issue: Children paying more than adults ​

Cause: childPricePercentage > 100 (should not happen due to validation).

Solution: Set childPricePercentage to <= 100.
