Invoice Management Guide ​

This guide explains how administrators can create and manage invoices in the HHR platform.

Quick Overview ​

FeatureDescription
PurposeCreate manual invoices and manage system invoices
AccessAdmin only (management), Guest (payment)
ScopeAll customer and B2B invoices

Guest Payment Access ​

Guests can pay invoices without authentication by providing their contact information:

  • GET /invoice/:id/available-gateways - Get available payment methods
  • POST /invoice/:id/generate-payment - Generate payment link

Guest endpoints accept guestEmail and/or guestPhone parameters for verification. The contact information must match the booking's guest contact.

Base URL ​

All invoice management endpoints use:

/api/v1

Authentication ​

All invoice endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. Create Manual Invoice ​

Endpoint: POST /admin/invoice

Create a new invoice manually.

Request Body:

json
{
  "userId": "user-uuid",
  "invoiceNumber": "INV-2026-001",
  "currency": "SAR",
  "totalAmount": 500.00,
  "metadata": {
    "description": "Manual invoice for services"
  }
}

Response: 201 Created

json
{
  "id": "invoice-uuid",
  "invoiceNumber": "INV-2026-001",
  "status": "DRAFT",
  "totalAmount": 500.00,
  "currency": "SAR",
  "totalPaid": 0.00,
  "createdAt": "2026-01-31T10:00:00Z"
}

2. Generate Invoice from Booking ​

Endpoint: POST /admin/invoice/generate

Generate an invoice from an existing booking.

Request Body:

json
{
  "bookingId": "booking-uuid"
}

Response: 201 Created

json
{
  "id": "invoice-uuid",
  "invoiceNumber": "INV-2026-002",
  "bookingId": "booking-uuid",
  "status": "PENDING",
  "totalAmount": 450.00,
  "currency": "SAR"
}

3. List All Invoices ​

Endpoint: GET /admin/invoice

Get all invoices with optional filtering.

Query Parameters:

ParameterTypeDescription
statusenumFilter by invoice status
userIdstringFilter by user
organizationIdstringFilter by organization
bookingIdstringFilter by exact booking ID
currencystringFilter by currency (SAR/IDR/USD)
sourceenumFilter by invoice source: BOOKING (regular OTA), CUSTOM_BOOKING (custom booking). Omit for all.
startDateISO-8601Lower bound on issuedAt
endDateISO-8601Upper bound on issuedAt
pagenumberPage number (default 1)
limitnumberItems per page (default 20)

Example:

bash
GET /admin/invoice?status=PENDING&currency=SAR
GET /admin/invoice?source=CUSTOM_BOOKING
GET /admin/invoice?source=BOOKING&status=PAID

source=BOOKING matches invoices with a linked regular OTA Booking. source=CUSTOM_BOOKING matches invoices with a linked CustomBooking. An explicit bookingId takes precedence over source=BOOKING.

Response: 200 OK

json
{
  "data": [
    {
      "id": "invoice-uuid",
      "invoiceNumber": "INV-2026-002",
      "status": "PENDING",
      "totalAmount": 450.00,
      "currency": "SAR"
    }
  ],
  "meta": {
    "total": 1,
    "page": 1
  }
}

4. Get Invoice by ID ​

Endpoint: GET /admin/invoice/:id

Get details of a specific invoice.

Response: 200 OK

json
{
  "id": "invoice-uuid",
  "invoiceNumber": "INV-2026-002",
  "status": "PENDING",
  "totalAmount": 450.00,
  "totalPaid": 0.00,
  "currency": "SAR",
  "items": [...],
  "payments": [...],
  "manualTransfer": null,
  "createdAt": "2026-01-31T10:00:00Z"
}

manualTransfer review block (admin-only, manual-transfer gateway only):

When the invoice's payment uses the MANUAL_TRANSFER gateway and the caller is authenticated as an admin, the response embeds a manualTransfer block so reviewers can act on the proof directly from the invoice detail page without cross-navigating to /admin/manual-transfer/proofs. For all other callers (non-admin, non-manual-transfer, or no proof yet) the field is null.

json
{
  "manualTransfer": {
    "proofId": "proof-uuid",
    "status": "SUBMITTED",
    "retryCount": 1,
    "maxRetryCount": 3,
    "uniqueAmount": 1250037,
    "amountSuffix": 37,
    "senderAccountName": "John Doe",
    "senderBankCode": "BCA",
    "transferredAt": "2026-04-20T09:30:00Z",
    "submittedAt": "2026-04-20T09:35:00Z",
    "reviewedAt": null,
    "reviewerId": null,
    "rejectionReason": null,
    "adminNotes": null,
    "fileId": "file-uuid",
    "fileMimeType": "image/png",
    "fileSizeBytes": 1024,
    "signedDownloadUrl": "https://r2.signed.url/...",
    "bankAccount": {
      "id": "bank-uuid",
      "bankCode": "BCA",
      "bankName": "Bank Central Asia",
      "accountNumber": "1234567890",
      "accountName": "PT Haramain",
      "currency": "IDR",
      "notes": null
    }
  }
}

signedDownloadUrl is a pre-signed R2 URL valid for 24 hours (the underlying file stays stored private — only the signed URL is shareable and still expires). Use approve / reject from the Manual Transfer admin guide to act on the proof.

5. Update Invoice ​

Endpoint: PUT /admin/invoice/:id

Update an existing invoice.

Request Body:

json
{
  "metadata": {
    "notes": "Updated invoice notes"
  }
}

Response: 200 OK

json
{
  "id": "invoice-uuid",
  "metadata": {
    "notes": "Updated invoice notes"
  },
  "updatedAt": "2026-01-31T11:00:00Z"
}

6. Mark Invoice as Paid ​

Endpoint: PUT /admin/invoice/:id/mark-paid

Manually mark an invoice as paid.

Request Body:

json
{
  "paymentMethod": "BANK_TRANSFER",
  "paymentId": "payment-reference-123"
}

Response: 200 OK

json
{
  "id": "invoice-uuid",
  "status": "PAID",
  "totalPaid": 450.00,
  "paidAt": "2026-01-31T11:00:00Z"
}

7. Void Invoice ​

Endpoint: PUT /admin/invoice/:id/void

Void an invoice (cancels it without payment).

Response: 200 OK

json
{
  "id": "invoice-uuid",
  "status": "VOID",
  "voidedAt": "2026-01-31T11:00:00Z"
}

Invoice Statuses ​

StatusDescription
DRAFTInvoice created but not yet sent to customer
PENDINGInvoice sent, awaiting payment
ISSUEDInvoice issued to customer, awaiting payment (manual-transfer and gateway flows)
WAITING_PAYMENT_REVIEWManual-transfer only. Customer submitted a transfer proof; awaiting admin approve/reject. Approve → PAID; reject → back to ISSUED so the customer can re-upload. Xendit and other gateways settle instantly on webhook and never touch this state.
PAIDInvoice fully paid
PARTIALLY_PAIDPartial payment received
OVERPAIDPaid more than required (e.g., duplicate payments)
VOIDInvoice cancelled
OVERDUEPayment deadline passed

Guest Payment Endpoints ​

These endpoints are accessible to guests without authentication for completing payments.

Get Available Gateways (Guest) ​

Endpoint: GET /invoice/:id/available-gateways

Query Parameters:

ParameterTypeRequiredDescription
guestEmailstringYes*Email used in guest booking
guestPhonestringYes*Phone used in guest booking

*At least one is required.

Example:

bash
GET /invoice/inv_123/available-gateways?guestEmail=ahmad@example.com

Response: 200 OK

json
{
  "invoiceId": "inv_123",
  "invoiceNumber": "INV-2026-001",
  "totalAmount": 759.00,
  "remainingAmount": 759.00,
  "currency": "SAR",
  "availableGateways": [
    {
      "code": "XENDIT",
      "name": "Xendit",
      "supportedMethods": ["QRIS", "BANK_TRANSFER", "EWALLET"]
    }
  ]
}

Generate Payment (Guest) ​

Endpoint: POST /invoice/:id/generate-payment

Request Body:

json
{
  "paymentGatewayCode": "XENDIT",
  "paymentMethod": "QRIS",
  "guestEmail": "ahmad@example.com"
}
FieldTypeRequiredDescription
paymentGatewayCodestringYesGateway code from available gateways
paymentMethodstringYesPayment method (QRIS, BANK_TRANSFER, etc.)
metadataobjectNoAdditional payment metadata
guestEmailstringYes*Email for guest verification
guestPhonestringYes*Phone for guest verification

*At least one is required for guest access.

Response: 200 OK

json
{
  "paymentId": "pay_456",
  "externalId": "inv-INV-2026-001-xendit-1",
  "gatewayCode": "XENDIT",
  "paymentMethod": "QRIS",
  "amount": 759.00,
  "currency": "SAR",
  "status": "PENDING",
  "qrString": "00020101021226580016ID.CO.QRIS.WWW0118...",
  "expiresAt": "2026-02-15T12:00:00.000Z",
  "expiryDisplay": {
    "iso": "2026-02-15T12:00:00.000Z",
    "local": "2/15/2026, 3:00:00 PM",
    "minutesRemaining": 60,
    "message": "Payment must be completed within 60 minutes"
  }
}
