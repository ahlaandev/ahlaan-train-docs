Search & Booking Limits Guide ​

This guide explains how an admin configures the group-size and advance-booking limits that gate search and booking creation across the three products: ota (retail), blockseat (wholesale), and custom.

Overview ​

Previously the front-end hardcoded these limits (minimum 10 seated passengers for custom SILVER, 5 for GOLD; a 3-day advance rule for wholesale) and the back-end owned only part of them via environment variables. This module moves them into a small database table an admin can edit, and exposes a public read endpoint so the front-end drives its own validation from the returned numbers instead of hardcoding.

Two dimensions are configurable per product:

FieldMeaning
minSeatedPaxMinimum seated passengers (adults + children; infants sit on a lap and are never counted). null = no floor.
minAdvanceDaysDeparture must be at least n × 24 hours ahead (midnight-UTC anchor). null / 0 = no advance rule. 3 = 72 hours.

The grid (4 cells) ​

Tier only splits custom (GOLD vs everyone-else). ota and blockseat are tier-flat.

producttierdefault minSeatedPaxdefault minAdvanceDays
OTA(base)10
BLOCKSEAT(base)113
CUSTOM(base)100
CUSTOMGOLD50

The table is empty on deploy, so these defaults (seeded from the existing env values) fire and behaviour is identical to before until an admin saves a row.

Search vs booking-creation split ​

A limit violation behaves differently depending on where it is hit:

  • Search endpoints return an empty result (no error) when a limit is violated — the same way OTA's existing 72-hour group rule already behaves.
  • Booking creation and price-calculation throw a 400 Bad Request.

Behaviour change to flag: wholesale (blockseat) search previously threw a 400 for fewer than 11 passengers. It now returns an empty result at search and only throws at calculate / booking-creation. Wholesale search also gains a real server-side <72h advance gate (previously only the supplier rejected <72h). Custom search now enforces the floor for logged-in callers (empty results below the floor); guests can still browse.

Fallback order ​

For each (product, tier) cell the effective value is resolved as:

DB row  →  environment variable  →  built-in default

Fallback is row-level, not field-level: if a DB row exists, its values win as-is, and a null field means "no rule" (the floor is OFF). It does not re-fall-back to the env value — otherwise an admin could never turn a floor off.

Endpoints ​

All admin endpoints require a JWT with role ADMIN and the relevant search-booking-limits:* permission.

GET /api/v1/admin/search-booking-limits ​

Returns the 4-cell grid (DB rows merged over defaults). Each row carries isDefault: true when no DB override exists.

PUT /api/v1/admin/search-booking-limits ​

Bulk-updates the grid. All rows are validated first, then upserted in one transaction — a single invalid row rejects the whole request (400) and nothing is half-saved.

jsonc
{
  "limits": [
    { "product": "OTA",       "tier": null,   "minSeatedPax": 1,  "minAdvanceDays": 0 },
    { "product": "BLOCKSEAT",  "tier": null,   "minSeatedPax": 11, "minAdvanceDays": 3 },
    { "product": "CUSTOM",     "tier": null,   "minSeatedPax": 10, "minAdvanceDays": 0 },
    { "product": "CUSTOM",     "tier": "GOLD", "minSeatedPax": 5,  "minAdvanceDays": 0 }
  ]
}

Validation rules:

  • product must be one of OTA, BLOCKSEAT, CUSTOM.
  • tier must be "GOLD" or null. A GOLD row is only valid for CUSTOM.
  • minSeatedPax / minAdvanceDays are non-negative integers or null.
  • Setting a field to null clears that rule (turns the floor off).

GET /api/v1/admin/search-booking-limits/defaults ​

Returns the env / built-in default matrix (the values used when no DB row exists).

GET /api/v1/admin/search-booking-limits/history ​

Returns the persisted rows with last-editor audit, paginated. The table upserts in place, so this is current state + last editor, not a per-change version trail.

Permissions ​

CodeGrants
search-booking-limits:readView the grid, defaults, and history.
search-booking-limits:updateSave (bulk-update) the grid.
search-booking-limits:*Both.

These are unassigned in the predefined roles by default — grant them to an Access Role as needed (matching how mitra-pricing / tariff-pricing are left unassigned).
