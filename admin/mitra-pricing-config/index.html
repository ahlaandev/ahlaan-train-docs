Mitra Pricing Configuration Guide ​

This guide explains how to configure the child-to-adult ratio held in MitraPricingConfig.childPricePercentage (MITRA-13). It drives two different things, and only one of them is a selling price.

⚠️ This one percentage moves both a price and a cost.

It setsWhereScope
the child sell pricemitra host, silver / gold tiers, ANCHOR_PAX floorthat host only
the child share of the capital (cost) basis on a custom bookingPATCH .../capital-price, PATCH .../source, POST .../recompute-capitalevery custom booking, every host

Raising this percentage therefore raises recorded supplier cost and lowers reported margin on every capital write made afterwards. That coupling is deliberate but easy to miss from this screen, because nothing here is labelled "cost". See Custom Booking → Update Capital Price.

Overview ​

Permission-gated (Access Roles). All routes require the ADMIN role plus a fine permission: reads (active config, history, defaults) need mitra-pricing:read, and create/update need mitra-pricing:update. See Access Roles.

On the mitra host, a child's sell price is a configurable percentage of the adult price (default 70%). This is a global setting applied to silver and gold tiers on both cabins (economy and business).

Where it applies ​

As a sell price:

SurfaceApplies?Why
Mitra host, silver / gold tiersYesPriced via the ANCHOR_PAX floor mode.
Mitra host, baseline (guest) tierNoGuests see the supplier's child price.
Off the mitra host (standard / BlockSeat)NoPriced PER_PAX, unchanged.
AdultNoAdult is the anchor (100%).
InfantNoInfant stays supplier-derived.
Child with no adult on the legNoThe child becomes the anchor and keeps its supplier price.

As the child share of the capital (cost) basis:

SurfaceApplies?Why
Any custom booking, any hostYescapitalPriceTotalSAR = (outboundCap + returnCap) × (adults + children × ratio). Cost does not depend on which website the customer booked from, so this use is deliberately not host-gated — unlike the sell-price use two tables up.
InfantNoExcluded from the basis entirely. There is no infant field on this config, so there is no configured infant ratio to honour.
AdultNoAdult is the unit the per-adult route price is quoted in.

How it works ​

Adult Price (anchor) = supplier-derived adult price (whole riyal)
Child Price          = floor(Adult Anchor × childPricePercentage / 100)
Infant Price         = supplier-derived (unchanged)

The child line's tax split (business cabin) is preserved by the child's own tax ratio, so ZATCA reconciliation (subtotal + tax == line) and VAT-neutrality hold.

Example ​

Real capture — POST /custom-ota/search DMX → JED, 2 adults + 1 child, BUSINESS fare LBT001ORM, gold mitra caller (childPricePercentage: 70):

Passenger TypeAdult AnchorPercentageSell Price
Adult353 SAR100%353 SAR
Child353 SAR70%247 SAR (floor(353 × 0.70))
Infant—(supplier)supplier-derived

The child's 247 SAR is surfaced by rewriting the fare's ptcFareBreakdown CHD row perPassenger — there is no separate top-level child-price field. The whole-booking finalPrice is 2 × 353 + 247 = 953 SAR, so the per-passenger lines re-sum to it.

Configuration structure ​

FieldDescriptionExample
idAuto-generated UUID (default when using defaults)config-abc123
childPricePercentageChild sell price as % of adult (0-100)70
isActiveWhether this config is currently activetrue
isDefaultTrue if using the system default (no DB config)false
createdByUser who created the configadmin-123
updatedByUser who last updated the configadmin-456

There is no infant field — infants remain supplier-derived by policy.

System default ​

If no configuration exists in the database, the system uses:

SettingDefault Value
childPricePercentage70%

The table is intentionally left empty on first deploy, so the 70% default fires until an admin sets a value.

Behavior notes ​

  • Changes apply immediately to new mitra-host searches and bookings, and to the next capital write on any custom booking, on any host.
  • Existing bookings are not repriced — invoices read the stored per-passenger columns captured at booking time.
  • ⚠️ A frozen capital figure is likewise untouched — until somebody calls a capital route on that booking again. At that moment it is re-expanded at the current percentage, including when the call was made for an unrelated reason (today's admin ticket-upload screen sends PATCH .../source ahead of the file; the upload route itself touches no capital). A real example: booking 6FZTDJA, 7 adults / 3 children, same channel and same 200 SAR route price, recomputed at 70% froze 1820; recomputed again at 60% froze 1760, with the per-adult figure unchanged at 200 on both sides. Each capitalPriceHistory entry records the next.childRatio it used, which is how a reader tells a config edit from a genuine cost correction.
  • This setting is independent of the B2B TariffPricingConfig (which governs the separate group-tariff child/infant percentages). Editing one never affects the other. It is not, however, independent of custom-booking cost — see the warning at the top of this page.
  • When the configured child price falls below the supplier-derived share, the charged (booking) path logs a warning for margin visibility; the search path stays silent.
  • The larger margin lever is the cost side and it is silent: raising this percentage raises what every later capital write records as supplier cost, and no warning is logged for that.
