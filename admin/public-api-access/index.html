Public API Access (Admin) ​

This guide explains how administrators control which organizations are allowed to mint and use public API keys, and how to revoke a key during a security incident.

Quick Overview ​

ItemDescription
PurposePer-organization allow-list for the partner public API + incident-response revoke
AuthenticationJWT in Authorization: Bearer … header, ADMIN role
IssuanceSelf-serve only — performed by approved B2B users via POST /api/v1/partner/api-keys. Admin no longer issues keys.
Admin retainsAllow-list toggle, list keys per org, revoke any key

How the allow-list works ​

Organization.publicApiEnabled is a boolean (default false). It must be set to true before any user in the org can mint a public API key. Disabling it does not revoke existing keys — already-issued keys keep working until you DELETE them. To fully cut off an org, toggle enabled: false and revoke all of their keys.

0. Find organizations with access enabled ​

The standard admin org listing exposes the allow-list flag and an active-key count, so you can audit who has access without paging through every B2B org.

http
GET /api/v1/admin/organizations?publicApiEnabled=true&page=1&limit=20
Authorization: Bearer <admin-jwt>
Query paramTypeDescription
publicApiEnabledbooleanOptional. true returns only allow-listed orgs; false only disabled.
isActivebooleanOptional. Existing org-level active flag.
page, limitnumberStandard pagination (defaults 1, 20).

Response (200):

json
{
  "data": [
    {
      "id": "0193…",
      "code": "ACME",
      "name": "Acme Travel",
      "isActive": true,
      "publicApiEnabled": true,
      "userCount": 4,
      "activeApiKeyCount": 2,
      "createdAt": "2026-01-15T08:30:00.000Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}

activeApiKeyCount counts keys that are not revoked and not expired — i.e. keys that would actually authenticate right now. A row with publicApiEnabled: true and activeApiKeyCount: 0 is allow-listed but not yet using the API.

Recipe — fully cut off an org ​

  1. GET /api/v1/admin/organizations?publicApiEnabled=true to find candidates.
  2. For each row where activeApiKeyCount > 0, list the keys with GET /api/v1/admin/organizations/:organizationId/api-keys and revoke each via DELETE …/api-keys/:keyId (see sections 2 and 3 below).
  3. Flip the allow-list with PATCH /api/v1/admin/organizations/:organizationId/public-api/access and body { "enabled": false } (section 1).
  4. Re-list with ?publicApiEnabled=true and confirm the org no longer appears.

1. Toggle public API access for an organization ​

http
PATCH /api/v1/admin/organizations/:organizationId/public-api/access
Authorization: Bearer <admin-jwt>
Content-Type: application/json

{ "enabled": true }

Response (200):

json
{
  "id": "0193…",
  "code": "ACME",
  "name": "Acme Travel",
  "publicApiEnabled": true
}
StatusReason
200Updated
400Body validation failed (e.g. enabled is not a boolean)
401JWT missing/invalid
403Caller is not an admin
404Organization not found

This action is captured by the global admin audit log (AuditLog table).

2. List an organization's keys (incident response / support) ​

http
GET /api/v1/admin/organizations/:organizationId/api-keys?page=1&limit=20
Authorization: Bearer <admin-jwt>

Same response shape as the partner-side list. The plaintext is never returned (only the SHA-256 hash is stored).

3. Revoke a key (incident response) ​

http
DELETE /api/v1/admin/organizations/:organizationId/api-keys/:keyId
Authorization: Bearer <admin-jwt>

204 No Content on success. Use this to revoke a leaked or abused key without waiting for the partner to act. The change propagates to running pods within ~60 seconds (Redis cache TTL).

:keyId must belong to the :organizationId in the same URL — otherwise the endpoint returns 404 Not Found and no key is revoked.

What admin can no longer do ​

The legacy POST /api/v1/admin/organizations/:organizationId/api-keys endpoint has been removed. Admin issuing keys on behalf of partners was an operational anti-pattern — the plaintext can only be shown once and had to be hand-delivered, creating a leak surface. Direct partners to the Partner Public API Keys guide instead.
