Fare Preference Management ​

This guide explains how administrators configure default fare types for each cabin class, which appears in search responses to guide frontend fare selection.

Quick Overview ​

FeatureDescription
EndpointsCRUD operations under /api/v1/admin/ota/fare-preferences
AuthenticationRequired (ADMIN role)
CachingRedis-backed with 1-hour TTL
Unique ConstraintOne preference per cabin class

What are Fare Preferences? ​

Fare preferences allow administrators to specify which fare type should be displayed as the default option for each cabin class in the search results.

How It Works ​

  1. Admin creates a fare preference (e.g., BUSINESS → PROMO)
  2. Search responses include metadata.farePreferences
  3. Frontend uses this to pre-select the default fare type
  4. If the preferred fare type is unavailable, fallback to STANDARD

Example Flow ​

Admin Configuration:
  BUSINESS class → PROMO (default)
  ECONOMY class → STANDARD (default)

Search Response Metadata:
{
  "farePreferences": {
    "preferences": [
      { "cabinClass": "BUSINESS", "defaultFareType": "PROMO" },
      { "cabinClass": "ECONOMY", "defaultFareType": "STANDARD" }
    ]
  }
}

Frontend Behavior:
  - Show BUSINESS class with PROMO fare pre-selected
  - Show ECONOMY class with STANDARD fare pre-selected

Base URL ​

/api/v1

Available Fare Types ​

TypeDescriptionRefundable
SAVERBudget fare, non-refundable, lowest priceNo
PROMODiscounted fare with strikethrough pricingYes
STANDARDRegular fare, fully refundableYes

Available Cabin Classes ​

ClassCodeDescription
BUSINESSCBusiness class (Premium)
ECONOMYYStandard economy class

Endpoints ​

1. Create Fare Preference ​

Create a new fare preference for a cabin class.

http
POST /admin/ota/fare-preferences
Authorization: Bearer <admin-token>
Content-Type: application/json

Request Body:

json
{
  "cabinClass": "BUSINESS",
  "defaultFareType": "PROMO",
  "priority": 0,
  "isActive": true
}

cabinClassstringYesBUSINESS or ECONOMY
defaultFareTypestringYesSAVER, PROMO, or STANDARD
prioritynumberNoSort order (lower = higher priority), default: 0
isActivebooleanNoWhether preference is active, default: true

Update an existing fare preference.

5. Delete (Deactivate) Fare Preference ​

Deactivate a fare preference. This is a soft delete.

http
DELETE /admin/ota/fare-preferences/{id}
Authorization: Bearer <admin-token>

Response (200 OK):

json
{
  "success": true
}

Note: This sets isActive to false. The preference is not deleted from the database.

How Search Responses Use Fare Preferences ​

When a customer searches for trains, the response includes metadata.farePreferences:

json
{
  "metadata": {
    "tripType": "ONE_WAY",
    "totalFlights": 2,
    "passengers": {
      "adults": 2,
      "children": 1,
      "infants": 0
    },
    "farePreferences": {
      "preferences": [
        {
          "cabinClass": "BUSINESS",
          "defaultFareType": "PROMO"
        },
        {
          "cabinClass": "ECONOMY",
          "defaultFareType": "STANDARD"
        }
      ]
    }
  },
  "outboundFlights": [...]
}

Frontend Integration Guide ​

When displaying search results:

  1. Read metadata.farePreferences.preferences
  2. For each cabin class, pre-select the default fare type
  3. If the default fare type is not available, fallback to STANDARD

Example (JavaScript):

javascript
// Get the default fare type for a cabin class
function getDefaultFareType(metadata, cabinClass) {
  const preference = metadata.farePreferences?.preferences?.find(
    p => p.cabinClass === cabinClass
  );
  return preference?.defaultFareType || 'STANDARD';
}

// When rendering flight options
function renderFlightClass(cls) {
  const defaultFareType = getDefaultFareType(metadata, cls.cabinClass);

  // Find the default fare
  const defaultFare = cls.fares.find(f => f.type === defaultFareType);

  // If default fare exists, pre-select it
  if (defaultFare) {
    return renderFareOption(defaultFare, { selected: true });
  }

  // Otherwise, fallback to STANDARD
  const standardFare = cls.fares.find(f => f.type === 'STANDARD');
  return renderFareOption(standardFare, { selected: true });
}

Caching Behavior ​

Fare preferences are cached in Redis for 1 hour to improve performance.

Cache Invalidation ​

The cache is automatically invalidated when:

  • A fare preference is created
  • A fare preference is updated
  • A fare preference is deactivated

Stale Data ​

If you update a fare preference and don't see the change:

  1. Wait up to 1 hour for cache to expire
  2. Or make another update to force cache invalidation

TypeScript Example ​

typescript
interface FarePreference {
  id: string;
  cabinClass: 'BUSINESS' | 'ECONOMY';
  defaultFareType: 'SAVER' | 'PROMO' | 'STANDARD';
  priority: number;
  isActive: boolean;
  createdBy?: string;
  updatedBy?: string;
  createdAt: string;
  updatedAt: string;
}

class FarePreferenceClient {
  constructor(private baseUrl: string, private token: string) {}

  async create(data: {
    cabinClass: 'BUSINESS' | 'ECONOMY';
    defaultFareType: 'SAVER' | 'PROMO' | 'STANDARD';
    priority?: number;
    isActive?: boolean;
  }): Promise<FarePreference> {
    const response = await fetch(`${this.baseUrl}/admin/ota/fare-preferences`, {
      method: 'POST',
      headers: {
        'Authorization': `Bearer ${this.token}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(data),
    });

    if (!response.ok) {
      throw new Error(`Failed to create fare preference: ${response.statusText}`);
    }

    return response.json();
  }

  async list(filters?: {
    isActive?: boolean;
    cabinClass?: 'BUSINESS' | 'ECONOMY';
  }): Promise<{ data: FarePreference[]; meta: { total: number } }> {
    const params = new URLSearchParams();
    if (filters?.isActive !== undefined) params.append('isActive', String(filters.isActive));
    if (filters?.cabinClass) params.append('cabinClass', filters.cabinClass);

    const response = await fetch(
      `${this.baseUrl}/admin/ota/fare-preferences?${params}`,
      {
        headers: {
          'Authorization': `Bearer ${this.token}`,
        },
      }
    );

    if (!response.ok) {
      throw new Error(`Failed to list fare preferences: ${response.statusText}`);
    }

    return response.json();
  }

  async getByCabinClass(cabinClass: 'BUSINESS' | 'ECONOMY'): Promise<FarePreference> {
    const response = await fetch(
      `${this.baseUrl}/admin/ota/fare-preferences/by-cabin-class/${cabinClass}`,
      {
        headers: {
          'Authorization': `Bearer ${this.token}`,
        },
      }
    );

    if (!response.ok) {
      throw new Error(`Failed to get fare preference: ${response.statusText}`);
    }

    return response.json();
  }

  async update(
    id: string,
    data: Partial<{
      defaultFareType: 'SAVER' | 'PROMO' | 'STANDARD';
      priority: number;
      isActive: boolean;
    }>
  ): Promise<FarePreference> {
    const response = await fetch(`${this.baseUrl}/admin/ota/fare-preferences/${id}`, {
      method: 'PUT',
      headers: {
        'Authorization': `Bearer ${this.token}`,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(data),
    });

    if (!response.ok) {
      throw new Error(`Failed to update fare preference: ${response.statusText}`);
    }

    return response.json();
  }

  async deactivate(id: string): Promise<{ success: boolean }> {
    const response = await fetch(`${this.baseUrl}/admin/ota/fare-preferences/${id}`, {
      method: 'DELETE',
      headers: {
        'Authorization': `Bearer ${this.token}`,
      },
    });

    if (!response.ok) {
      throw new Error(`Failed to deactivate fare preference: ${response.statusText}`);
    }

    return response.json();
  }
}

// Usage
const client = new FarePreferenceClient('/api/v1', 'your-admin-token');

// Create a preference
const businessPref = await client.create({
  cabinClass: 'BUSINESS',
  defaultFareType: 'PROMO',
  priority: 0,
  isActive: true,
});

// List all active preferences
const { data: preferences } = await client.list({ isActive: true });

// Update a preference
await client.update(businessPref.id, {
  defaultFareType: 'STANDARD',
});

// Deactivate a preference
await client.deactivate(businessPref.id);

Best Practices ​

1. Always Create Preferences for Both Classes ​

Ensure you have preferences for both BUSINESS and ECONOMY classes to provide consistent guidance to the frontend.

2. Use Meaningful Priorities ​

Set lower priority values for more important preferences:

  • priority: 0 for most important
  • priority: 1 for less important

3. Soft Delete Instead of Hard Delete ​

Use DELETE (deactivate) instead of manually deleting from database. This preserves audit history.

4. Test Changes in Search Response ​

After updating a preference, test the search endpoint to verify the change appears in metadata.farePreferences.

5. Consider Seasonal Changes ​

You may want to update default fare types seasonally (e.g., PROMO in off-peak, STANDARD in peak).

Troubleshooting ​

Changes not appearing in search response ​

Problem: Updated a fare preference but search response still shows old value.

Solutions:

  • Wait for cache to expire (up to 1 hour)
  • Make another update to force cache invalidation
  • Check Redis is running

409 Conflict when creating preference ​

Problem: Getting 409 error when creating a fare preference.

Solution: A preference for this cabin class already exists. Use PUT to update it instead.

No fare preferences in search metadata ​

Problem: metadata.farePreferences is missing or empty.

Solutions:

  • Check that preferences exist with isActive: true
  • Verify Redis cache is working
  • Check server logs for errors
