Managing Railway Stations ​

This guide explains how to manage HHR railway stations. Tariffs and custom route prices reference railway stations by ID, so you must create stations before configuring routes.

The previous endpoints under /api/v1/admin/tariffs/locations are deprecated but still respond with the same payloads. Update clients to the canonical paths under /api/v1/admin/railway-stations documented below.

Access. Admin plus Access Role. Every route (list, detail, create, update, delete) needs railway-stations:manage. See Access Roles.

Overview ​

A railway station represents a single HHR station (e.g. Madinah, Makkah). Stations are referenced by other modules:

  • Tariffs — fixed B2B route pricing
  • Custom Route Prices — manual price overrides
  • Scraper Price — ingest validation by station code

Station Structure ​

FieldDescriptionExample
idAuto-generated UUIDstation-abc123
codeUnique station code (max 10 chars, uppercased on save)DMX, MKX
nameHuman-readable station name (max 100 chars)Madinah
isActiveWhether the station is available for usetrue
createdAt / updatedAtAudit timestamps2026-01-15T10:00:00Z

The underlying database table is Location — the rename is only at the module/API/UI layer to keep existing data and FK relations intact.

Endpoints ​

EndpointMethodDescription
/api/v1/admin/railway-stationsPOSTCreate a new station
/api/v1/admin/railway-stationsGETList stations (paginated, filterable)
/api/v1/admin/railway-stations/:idGETGet a station by ID
/api/v1/admin/railway-stations/:idPUTUpdate a station
/api/v1/admin/railway-stations/:idDELETESoft delete (deactivate) a station

All endpoints require an admin JWT (Authorization: Bearer <token>) and the ADMIN role.

Deprecated aliases ​

The following paths are still served for backward compatibility but will be removed:

  • POST | GET | PUT | DELETE /api/v1/admin/tariffs/locations[/:id]

They proxy to the same handlers and return identical payloads.

Create Station ​

http
POST /api/v1/admin/railway-stations
Authorization: Bearer <token>
Content-Type: application/json

{
  "code": "DMX",
  "name": "Madinah",
  "isActive": true
}

Response (201 Created)

json
{
  "id": "station-abc123",
  "code": "DMX",
  "name": "Madinah",
  "isActive": true,
  "createdAt": "2026-01-15T10:00:00.000Z",
  "updatedAt": "2026-01-15T10:00:00.000Z"
}

Errors

  • 400 Bad Request — invalid input (e.g., code exceeds 10 characters, name exceeds 100 characters, HTML/script content in code or name).
  • 409 Conflict — a station with the same code already exists.

List Stations ​

http
GET /api/v1/admin/railway-stations?code=DM&isActive=true&page=1&limit=20
Authorization: Bearer <token>

Query parameters ​

ParamTypeDefaultNotes
codestring—Case-insensitive contains filter
isActiveboolean—Filter by active flag
pagenumber11-indexed
limitnumber20Max 100

Response (200 OK)

json
{
  "data": [
    {
      "id": "station-abc123",
      "code": "DMX",
      "name": "Madinah",
      "isActive": true,
      "createdAt": "2026-01-15T10:00:00.000Z",
      "updatedAt": "2026-01-15T10:00:00.000Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}

Get Station by ID ​

http
GET /api/v1/admin/railway-stations/:id
Authorization: Bearer <token>

Returns 404 Not Found when the ID does not exist.

Update Station ​

http
PUT /api/v1/admin/railway-stations/:id
Authorization: Bearer <token>
Content-Type: application/json

{
  "name": "Madinah Central",
  "isActive": false
}

All fields are optional. Updating code triggers a uniqueness check; a conflicting code returns 409 Conflict.

Delete Station ​

Soft delete — sets isActive to false. Stations referenced by an active tariff cannot be deleted.

http
DELETE /api/v1/admin/railway-stations/:id
Authorization: Bearer <token>

Response (200 OK)

json
{ "success": true }

Errors

  • 400 Bad Request — Cannot delete location with active tariffs. Deactivate the tariffs first.
  • 404 Not Found — station does not exist.

Best practices ​

  1. Use canonical HHR station codes (DMX, JXD, KCX, MKX). Codes are uppercased on save.
  2. Create all stations before configuring tariffs so route configuration can reference them by ID.
  3. Deactivate before deleting: deactivate the affected tariffs first if you need to retire a station.
  4. Keep names consistent with the public-facing labels used in the booking flow.

Migrating from the deprecated endpoints ​

Replace any caller of /api/v1/admin/tariffs/locations with /api/v1/admin/railway-stations. The request and response shapes are identical — no payload changes are required. Once all clients are updated, the legacy paths will be removed.
