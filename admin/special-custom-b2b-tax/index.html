Special Custom B2B Tax Management Guide ​

This guide explains how administrators configure special custom B2B tax rules — the tax applied to gold (special-B2B) BUSINESS custom-ota / custom-booking fares.

Status: Special custom B2B tax differentiates the BUSINESS tax for a gold customer — a caller whose resolved pricingTier is GOLD (org Organization.pricingTier = GOLD, or a per-user User.pricingTier = GOLD override — including a B2C user), served on the promo host. pricingTier is the source of truth; specialCustomPricingEnabled is a deprecated mirror (GOLD ⇔ true) kept in lockstep. A gold BUSINESS fare resolves its tax from this table; a silver (pricingTier = SILVER) or no-auth BUSINESS fare keeps the base Custom Tax rule. Like base custom tax it is BUSINESS-class only — ECONOMY (and any non-business) class stays sold tax-free. When no special rule matches a gold BUSINESS fare, resolution falls back to the base CustomTaxRule (see Fallback). The tax is broken out on the invoice as the ZATCA tax line (subtotal + tax = total).

Quick Overview ​

FeatureDescription
PurposeConfigure the flat VAT/tax applied to gold (special-B2B) BUSINESS custom bookings, independent of the OTA tax engine
Applies toGold customers only (resolved pricingTier = GOLD; specialCustomPricingEnabled is a deprecated mirror), BUSINESS class, on the promo host
ScopeOptional per-route (originId / destinationId / tripClass / tripType) or global default
Tax TypesPercentage (e.g. 15% VAT) or Fixed amount (always SAR)
SelectionMost route-specific active rule wins; ties broken by priority. Only ONE rule applies (no accumulation)
FallbackNo matching special rule → the base Custom Tax rule is used instead (per-lever)

This mirrors the base Custom Tax configuration exactly — same field structure and resolution — but the rules live in a separate table that only gold BUSINESS fares consult first.

How Special Custom B2B Tax Rules Work ​

┌─────────────────────────────────────────────────────────────────┐
│            SPECIAL CUSTOM B2B TAX RESOLUTION                      │
├─────────────────────────────────────────────────────────────────┤
│  1. Collect all ACTIVE special custom B2B tax rules              │
│                        ↓                                          │
│  2. Keep rules whose route scope matches the request:           │
│     a null scope field is a wildcard (matches anything)         │
│                        ↓                                          │
│  3. Rank survivors:                                             │
│     ├─ most route-specific first (more non-null scope fields)   │
│     └─ then highest priority                                     │
│                        ↓                                          │
│  4. Apply the single top rule on the chosen taxBasis            │
│     BASE_PRICE   → tax on base only                             │
│     FINAL_AMOUNT → tax on base + markup                         │
│     — else fall back to the base CustomTaxRule                  │
└─────────────────────────────────────────────────────────────────┘

A rule with no route scope (all of originId, destinationId, tripClass, tripType omitted) is the global default for gold BUSINESS fares.

Per-lever fallback to base custom tax ​

Tax and markup fall back independently (per lever). For a gold BUSINESS fare:

  • If an active special tax rule matches → it is applied.
  • If no special tax rule matches → the base CustomTaxRule resolution is used for tax.

The markup lever resolves the same way against Special Custom B2B Markup. Silver and no-auth BUSINESS fares skip the special tables entirely and use the base rules only.

Base URL & Authentication ​

/api/v1

All endpoints require a JWT token with the ADMIN role:

http
Authorization: Bearer <admin-token>

Endpoints ​

Create a special custom B2B tax rule ​

http
POST /api/v1/admin/special-custom-b2b-tax/rules
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "name": "Gold Business VAT 15%",
  "description": "Gold-tier BUSINESS tax for custom bookings",
  "originId": "DMX",
  "destinationId": "MKX",
  "tripClass": "BUSINESS",
  "taxType": "PERCENTAGE",
  "taxRate": 15,
  "taxCode": "VAT-SA",
  "taxBasis": "FINAL_AMOUNT",
  "priority": 100,
  "isActive": true
}

Get a single rule ​

http
GET /api/v1/admin/special-custom-b2b-tax/rules/:id
Authorization: Bearer <admin-token>

Response (200): the persisted rule, or 404 if not found.

Update a rule ​

http
PUT /api/v1/admin/special-custom-b2b-tax/rules/:id
Authorization: Bearer <admin-token>
Content-Type: application/json

{
  "taxRate": 5,
  "priority": 200
}

All fields optional. Response (200): the updated rule.

Partial updates respect the PERCENTAGE cap. taxType and taxRate may be sent independently. When taxType is omitted, the 0–100 cap is re-asserted against the persisted rule's type, so { "taxRate": 5000 } on a PERCENTAGE rule is rejected with 400. Flipping a rule to PERCENTAGE when the persisted taxRate already exceeds 100 is likewise rejected — resend a valid taxRate ≤ 100 in the same request.

Deactivate (soft-delete) a rule ​

http
DELETE /api/v1/admin/special-custom-b2b-tax/rules/:id
Authorization: Bearer <admin-token>

Response (200):

json
{ "success": true }

Soft delete — sets isActive = false. Re-enable via PUT { "isActive": true }.
