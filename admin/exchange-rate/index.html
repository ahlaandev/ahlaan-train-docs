Exchange Rate Management Guide ​

This guide explains how administrators can manage currency exchange rates for the HHR platform.

Quick Overview ​

FeatureDescription
PurposeManage IDR to SAR exchange rates (USD uses fixed SAR peg at 3.75)
AccessAdmin only
ScopeAll currency conversions

Base URL ​

All exchange rate endpoints use:

/api/v1

Authentication ​

All exchange rate endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Rate Modes ​

The system supports three rate modes:

ModeDescription
SCHEDULEDAutomatically switches between Mandiri rates (10 AM WIB) and manual rates (2 PM WIB) on business days. Manual rates apply all day on holidays.
FORCE_AUTOMATICAlways uses Mandiri (bank) rates, ignoring the schedule and manual rates.
FORCE_MANUALAlways uses manually entered rates, ignoring the scheduled auto-switch.

Rate Schedule ​

On SCHEDULED mode, the exchange rate system follows this daily cycle:

Time (WIB)Rate SourceCondition
10:00 AMMandiri (bank) rates — auto-fetched from external APIBusiness days only
2:00 PMManual rates — set by adminBusiness days only
All dayManual ratesHolidays (configured via POST /admin/exchange-rate/holidays)

How Exchange Rates Work ​

Exchange Rate Flow ​

┌─────────────────────────────────────────────────────────────────┐
│                    EXCHANGE RATE FLOW                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. System fetches rates from external API                       │
│     - Buy rate: Bank buys IDR from you (lower)                   │
│     - Sell rate: Bank sells IDR to you (higher)                  │
│                        ↓                                         │
│  2. Rates stored directly in database                            │
│                        ↓                                         │
│  3. Wallet top-up uses sell rate:                                │
│                                                                  │
│     Input: 500,000 IDR (QRIS payment)                           │
│     Sell Rate: 4,452 IDR/SAR                                    │
│     ─────────────────────────────────────                        │
│     Gross SAR = 500,000 ÷ 4,452 = 112.31 SAR                    │
│                                                                  │
│  4. Tax calculation:                                             │
│                                                                  │
│     Gross SAR: 112.31                                           │
│     Tax (11%): 12.35 SAR                                        │
│     ─────────────────────────────────────                        │
│     Net SAR (credited): 99.96 SAR                               │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Rate Types ​

TypeDescriptionUsage
Buy RateBank's rate to buy foreign currencyNot currently used
Sell RateBank's rate to sell foreign currencyUsed for wallet top-ups

Rate Sources ​

SourceDescription
BANK_MANDIRIRates fetched from Mandiri bank API
MANUALRates manually entered by admin

Each source acts as a fallback for the other when the scheduled source has no available record.

Automatic Sync ​

The system automatically syncs Mandiri rates from the external API:

SettingValue
FrequencyEvery 1 hour
SourceMandiri bank API
Distributed LockRedis (prevents concurrent syncs)
FallbackFalls back to alternate source if scheduled source has no record

Fallback Behavior ​

If the scheduled source has no available record, the system automatically falls back to the alternate source:

ScenarioScheduled SourceFallback Source
No Mandiri rate availableBANK_MANDIRIMANUAL
No manual rate availableMANUALBANK_MANDIRI

If neither source has a record, the system keeps the current active rate unchanged.

Rate Deduplication ​

Before creating a new BANK_MANDIRI rate, the system compares it with the latest existing BANK_MANDIRI rate. If both buy and sell rates are identical, no new record is created — avoiding redundant entries.

Transactional Activation ​

During automatic hours (when BANK_MANDIRI is the effective source), new rates are atomically activated in a single transaction. This ensures only one active rate exists at any time for SAR currency.

Rate Calculation Examples ​

Example 1: Basic Wallet Top-Up ​

User pays: 500,000 IDR via QRIS
Sell Rate: 4,452 IDR/SAR

Gross SAR = 500,000 ÷ 4,452 = 112.31 SAR
Tax (11%) = 112.31 × 0.11 = 12.35 SAR
────────────────────────────────────
Net Credited = 112.31 - 12.35 = 99.96 SAR

Example 2: Large Top-Up (Tax Exempt) ​

User pays: 10,000,000 IDR
Sell Rate: 4,452 IDR/SAR
Tax Exempt: Yes (verified business)

Gross SAR = 10,000,000 ÷ 4,452 = 2,246.63 SAR
Tax (11%) = 0 SAR (exempt)
────────────────────────────────────
Net Credited = 2,246.63 SAR

Example 3: Rate Change Impact ​

Same payment: 500,000 IDR

Old Rate: 4,300 IDR/SAR
Gross = 500,000 ÷ 4,300 = 116.28 SAR

New Rate: 4,600 IDR/SAR
Gross = 500,000 ÷ 4,600 = 108.70 SAR

Difference: 7.58 SAR less received

Exchange Rate Storage ​

Database Schema ​

sql
ExchangeRate {
  id: UUID (primary key)
  currency: String (e.g., "SAR")
  buyRate: Decimal (IDR per unit)
  sellRate: Decimal (IDR per unit)
  source: Enum (BANK_MANDIRI, MANUAL)
  isActive: Boolean
  fetchedAt: DateTime
}

Active Rate Selection ​

The system always uses the most recent active rate for calculations:

SELECT * FROM ExchangeRate
WHERE currency = 'SAR'
  AND isActive = true
ORDER BY fetchedAt DESC
LIMIT 1
