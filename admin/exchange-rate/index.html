Exchange Rate Management Guide ​

This guide explains how administrators manage IDR to SAR exchange rates for the HHR platform.

Quick Overview ​

FeatureDescription
PurposeManage IDR to SAR exchange rates (USD still uses the fixed SAR peg at 3.75)
AccessAdmin only
ScopeWallet top-up, OTA pricing, invoice conversion, and other SAR conversion flows

Base URL ​

All exchange rate endpoints use:

http
/api/v1

Authentication ​

All exchange rate endpoints require:

  • JWT token in the Authorization header
  • ADMIN role
http
Authorization: Bearer <your-admin-jwt-token>

Rate Modes ​

The system supports three operating modes:

ModeDescription
SCHEDULEDUses the configured weekday toggles plus the configured switch times to decide when Mandiri vs manual rates are effective.
FORCE_AUTOMATICAlways uses the latest scraped BANK_MANDIRI rate, ignoring weekday toggles and switch times.
FORCE_MANUALAlways uses the latest manually entered rate, ignoring weekday toggles and switch times.

Scheduled Mode ​

In SCHEDULED mode, the system now uses only the current day's toggle plus the configured switch times.

Day toggle rules ​

  • If today's toggle is false, the system uses manual rates for the entire day.
  • If today's toggle is true, the system uses the configured time window:
    • before autoSwitchTimeWib: manual
    • from autoSwitchTimeWib until before manualSwitchTimeWib: BANK_MANDIRI
    • from manualSwitchTimeWib onward: manual

Default weekday toggles ​

The default configuration is:

json
{
  "MON": true,
  "TUE": true,
  "WED": true,
  "THU": true,
  "FRI": true,
  "SAT": false,
  "SUN": false
}

This means scheduled switching is enabled by default on Monday through Friday, and disabled on Saturday and Sunday.

Important note ​

Holiday-based switching has been removed. The system no longer has holiday endpoints or holiday-aware rate selection. Only the current day's toggle is used.

How Exchange Rates Work ​

Rate flow ​

text
1. The system scrapes Mandiri rates on the configured sync interval.
2. Rates are stored in the exchange-rate table.
3. Manual rates can be entered by an admin at any time.
4. The active source is resolved from:
   - mode
   - weekday toggle for the current day
   - auto/manual switch times
5. If the preferred source has no record, the system falls back to the other source.

Rate types ​

TypeDescriptionUsage
Buy RateBank's rate to buy foreign currencyStored for audit/history
Sell RateBank's rate to sell foreign currencyUsed for wallet top-ups and current conversion

Rate sources ​

SourceDescription
BANK_MANDIRIRate scraped from Mandiri
MANUALRate entered by admin

Endpoints ​

1. Get Exchange Rate History ​

Endpoint: GET /admin/exchange-rate/history

Get paginated exchange rate history.

Query Parameters:

ParameterTypeDescription
currencystringCurrency filter, default SAR
pagenumberPage number, default 1
limitnumberItems per page, default 20

Example:

http
GET /admin/exchange-rate/history?currency=SAR&page=1&limit=20

Response: 200 OK

json
{
  "data": [
    {
      "id": "rate-uuid",
      "currency": "SAR",
      "buyRate": 4447.65,
      "sellRate": 4452.3,
      "fetchedAt": "2026-01-31T10:00:00Z",
      "source": "BANK_MANDIRI",
      "isActive": true
    }
  ],
  "meta": {
    "total": 1000,
    "page": 1,
    "limit": 20,
    "totalPages": 50
  }
}

2. Manual Sync Exchange Rate ​

Endpoint: POST /admin/exchange-rate/sync

Manually trigger a Mandiri scrape and re-evaluate the active rate.

Use cases:

  • the latest scraped rate looks stale
  • automatic sync failed
  • operations need a fresh Mandiri rate immediately

Response: 200 OK

json
{
  "success": true,
  "message": "Exchange rates synced successfully",
  "activeRate": {
    "id": "rate-uuid",
    "currency": "SAR",
    "buyRate": 4447.65,
    "sellRate": 4452.3,
    "source": "BANK_MANDIRI",
    "fetchedAt": "2026-01-31T12:00:00Z",
    "isActive": true
  }
}

6. Create Manual Exchange Rate ​

Endpoint: POST /admin/exchange-rate/manual-rate

Create a manual exchange rate entry. This is used when:

  • mode is FORCE_MANUAL
  • the current day is disabled in scheduleEnabledDays
  • scheduled mode is active but the current local time is outside the Mandiri window

Request Body:

ParameterTypeDescription
buyRatenumberBuy rate, for example 4447.65
sellRatenumberSell rate, for example 4452.3

Example:

http
POST /admin/exchange-rate/manual-rate
Content-Type: application/json

{
  "buyRate": 4447.65,
  "sellRate": 4452.3
}

Response: 201 Created

{

Automatic Sync ​

The system automatically syncs Mandiri rates from the configured scrape source.

SettingValue
Default scrape frequencyEvery 30 minutes
Default evaluation frequencyEvery 1 minute
SourceMandiri exchange-rate page
Distributed lockRedis
FallbackFalls back to the alternate source if the preferred source has no record

Fallback behavior ​

If the preferred source for the current schedule window has no available record, the system falls back to the opposite source:

ScenarioPreferred SourceFallback Source
No Mandiri rate availableBANK_MANDIRIMANUAL
No manual rate availableMANUALBANK_MANDIRI

If neither source has a record, the system keeps the current active rate unchanged.

Rate deduplication ​

Before creating a new BANK_MANDIRI rate, the system compares it with the latest existing BANK_MANDIRI record. If both buy and sell rates are unchanged, no new record is created.

Transactional activation ​

When the effective source is BANK_MANDIRI, activation is done transactionally so only one active SAR rate exists at a time.

IssueCauseSolution
