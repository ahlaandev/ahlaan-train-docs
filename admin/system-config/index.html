System Configuration Guide ​

This guide explains how administrators manage system-wide settings for the HHR platform via the /admin/system-config API.

Quick Overview ​

FeatureDescription
PurposeConfigure system-wide settings and feature flags
AccessAdmin only
ScopeAffects all users and bookings

Seeded System Configurations ​

The system comes with pre-configured settings:

Payment & Fee Settings ​

KeyValueDescription
FEE_DISPLAY_MODECOMBINEDHow payment gateway fees are displayed: COMBINED (single price) or BREAKDOWN (itemized)
PAYMENT_GATEWAY_FEES_ENABLEDfalseEnable or disable payment gateway fee calculation

Tax Settings ​

KeyValueDescription
TAX_ENABLEDtrueEnable or disable tax calculation on bookings
TAX_INCLUSIVE_PRICINGtrueWhen true, displayed prices include tax. When false, tax is added on top.

Wallet Top-Up Settings ​

KeyValueDescription
WALLET_TOPUP_ENABLEDtrueEnable or disable wallet top-up feature
WALLET_TOPUP_MIN_AMOUNT10000Minimum wallet top-up amount (IDR)
WALLET_TOPUP_MAX_PER_TRANSACTION10000000Maximum wallet top-up per transaction (IDR)
WALLET_TOPUP_MAX_PER_DAY50000000Maximum wallet top-up per day (IDR)
WALLET_TOPUP_DEFAULT_GATEWAYXENDITDefault payment gateway for wallet top-up

Wallet Top-Up Constraints

  • Wallet top-ups currently support IDR and SAR only.
  • USD wallet top-ups are disabled.
  • Top-up AML limits are enforced in IDR.
  • XENDIT remains the default gateway, but it currently accepts BANK_TRANSFER only.

Train Availability Cache Settings ​

KeyValueDescription
TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTES30How often to refresh train availability cache (in minutes)
TRAIN_AVAILABILITY_CACHE_DAYS_AHEAD7How many days ahead to pre-warm cache (1-30)

Xendit Payment Redirect URLs ​

After a successful Xendit payment, the customer is redirected to a success page on the originating frontend. The URL is selected by the invoice's payment source, so each frontend can return its own users to its own callback page:

KeySourceDescription
XENDIT_REDIRECT_URLOTAMain OTA frontend. Used for regular OTA bookings, wallet top-ups, and any invoice without a more specific source.
XENDIT_REDIRECT_URL_CUSTOM_OTACUSTOM_OTACustom-OTA frontend (custom bookings).
XENDIT_REDIRECT_URL_BLOCKSEATBLOCKSEATBlockSeat (wholesale) frontend. BlockSeat bookings are native OTA bookings (bookingVariant=BLOCKSEAT); this key keeps their redirect off the main OTA.
  • Resolution per source: source-specific DB key → source-specific env var → main-OTA DB key (XENDIT_REDIRECT_URL) → main-OTA env var → none. A misconfigured per-frontend source therefore still receives the main-OTA redirect rather than no redirect.
  • Set any of these at runtime via PATCH /admin/system-config (DB value overrides the env default), or seed them through the XENDIT_REDIRECT_URL* environment variables.

Manual Transfer Settings ​

KeyValueDescription
MANUAL_TRANSFER_ENABLE_UNIQUE_SUFFIXfalseWhen true, manual-transfer bills include a random 3-digit suffix (amountSuffix 0–999) appended to the billed amount so admins can reconcile incoming deposits by the last three digits. When false (default), the billed amount equals the raw rounded invoice amount and amountSuffix=0; reconciliation falls back to sender + timestamp + amount. Toggle via the generic PATCH /admin/system-config endpoint with value: "true" or "false".

Manual Transfer Suffix Propagation

  • The toggle takes effect immediately for new payments and re-uploaded proofs handled by the pod that serves the PATCH — other pods converge within the Redis cache TTL (≤5 minutes).
  • Proofs already created on the old setting are unaffected — only new proofs and REJECTED→SUBMITTED flips honour the current live value.
  • When the feature is false, the partial unique index on (bankAccountId, uniqueAmount) relaxes so multiple zero-suffix in-flight proofs on the same bank account can coexist — this is why reconciliation must fall back to sender + timestamp.

Custom Booking Settings ​

KeyValueDescription
CUSTOM_BOOKING_ADMIN_NOTIFICATION_PHONE(unset)Admin WhatsApp number that receives a notification when a custom booking transitions PENDING → UPLOADED_MANIFEST (passenger list submitted). Must be in international format without leading + (e.g. 628111222333). Leave unset to disable the notification.
CUSTOM_BOOKING_AUTO_CONFIRM_ON_MANIFEST(unset → ON)Feature flag for auto-confirming a custom booking on manifest upload. When ON (unset, or any value other than "false"), submitting the passenger list advances the booking straight from UPLOADED_MANIFEST to CONFIRMED — generating the invoice + Xendit payment link and delivering it to the customer — with no admin review. Set to "false" to restore the manual admin-confirm gate (the booking parks at UPLOADED_MANIFEST until an admin confirms via PATCH .../status).

Admin WhatsApp Notification

  • The message is sent only once per booking, on the atomic transition winner.
  • Invalid or unset phone values cause the server to log a warn and skip the notification — the booking update itself never fails.
  • See Custom Booking (Admin) — Side Effect: Passenger Upload, Auto-Confirm & Admin WhatsApp Notification for the exact message format and the auto-confirm flow.

Auto-Confirm on Manifest

  • Default is ON — the flag only needs setting to disable it (value: "false").
  • Auto-confirm is best-effort: if confirmation fails the booking stays at UPLOADED_MANIFEST and the passenger upload still succeeds.
  • It does not set a capital source; capitalPriceTotalSAR stays 0 until an admin calls PATCH /admin/custom-booking/:id/source.
  • Toggle via PATCH /admin/system-config with value: "true" / "false"; changes converge across pods within the Redis cache TTL (≤5 minutes).

Base URL ​

All system configuration endpoints use:

/api/v1

Authentication ​

All system configuration endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

MethodPathDescription
GET/api/v1/admin/system-configGet all system configurations
PATCH/api/v1/admin/system-configSet system configuration
GET/api/v1/admin/system-config/{key}Get system configuration by key
DELETE/api/v1/admin/system-config/{key}Delete system configuration

1. Get All System Configurations ​

Endpoint: GET /api/v1/admin/system-config

Returns all configuration key-value pairs.

Response: 200 OK

json
[
  {
    "id": "019d9faa-879c-76a0-a4f7-ef34a2890bcd",
    "key": "FEE_DISPLAY_MODE",
    "value": "COMBINED",
    "description": "How payment gateway fees are displayed",
    "updatedAt": "2026-01-28T10:00:00.000Z",
    "updatedBy": "019c9105-311a-732f-a1c5-da44758a7e5b"
  }
]

2. Set System Configuration ​

Endpoint: PATCH /api/v1/admin/system-config

Create or update a configuration value. The key is provided in the request body, not the URL.

Request Body:

FieldTypeRequiredDescription
keystringyesConfiguration key (e.g. TAX_ENABLED)
valuestringyesConfiguration value (numbers and booleans are stored as strings)
descriptionstringnoOptional human-readable description
json
{
  "key": "TAX_ENABLED",
  "value": "true",
  "description": "Enable or disable tax calculation on bookings"
}

Response: 200 OK

json
{
  "id": "019d9faa-879c-76a0-a4f7-ef34a2890bcd",
  "key": "TAX_ENABLED",
  "value": "true",
  "updatedAt": "2026-04-18T08:17:26.428Z",
  "updatedBy": "019c9105-311a-732f-a1c5-da44758a7e5b"
}

Example:

bash
curl -X PATCH https://api.example.com/api/v1/admin/system-config \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "key": "CUSTOM_BOOKING_ADMIN_NOTIFICATION_PHONE",
    "value": "628111222333"
  }'

3. Get Configuration by Key ​

Endpoint: GET /api/v1/admin/system-config/{key}

Get a single configuration value by its key.

Response: 200 OK

json
{
  "key": "TAX_ENABLED",
  "value": "true",
  "description": "Enable or disable tax calculation on bookings",
  "updatedAt": "2026-01-28T10:00:00.000Z"
}

4. Delete Configuration ​

Endpoint: DELETE /api/v1/admin/system-config/{key}

Delete a configuration entry.

Response: 200 OK

json
{
  "success": true
}

Configuration Types ​

Boolean Values ​

Keys that accept "true" or "false" (stored as strings):

  • PAYMENT_GATEWAY_FEES_ENABLED
  • TAX_ENABLED
  • TAX_INCLUSIVE_PRICING
  • WALLET_TOPUP_ENABLED
  • MANUAL_TRANSFER_ENABLE_UNIQUE_SUFFIX
  • CUSTOM_BOOKING_AUTO_CONFIRM_ON_MANIFEST (default ON when unset; only "false" disables)

String Values (Enums) ​

Keys that accept specific string values:

  • FEE_DISPLAY_MODE: COMBINED or BREAKDOWN
  • WALLET_TOPUP_DEFAULT_GATEWAY: XENDIT, MIDTRANS, or STRIPE

Numeric Values ​

Keys that accept numeric values (stored as strings):

  • WALLET_TOPUP_MIN_AMOUNT: In IDR
  • WALLET_TOPUP_MAX_PER_TRANSACTION: In IDR
  • WALLET_TOPUP_MAX_PER_DAY: In IDR
  • TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTES: In minutes (1-1440)
  • TRAIN_AVAILABILITY_CACHE_DAYS_AHEAD: In days (1-30)

Validation Rules ​

KeyValidation
FEE_DISPLAY_MODEMust be COMBINED or BREAKDOWN
WALLET_TOPUP_MIN_AMOUNTMust be positive integer
WALLET_TOPUP_MAX_PER_TRANSACTIONMust be >= min amount
WALLET_TOPUP_MAX_PER_DAYMust be >= max per transaction
WALLET_TOPUP_DEFAULT_GATEWAYMust be valid gateway code
TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTESMust be 1-1440 (1 min to 24 hours)
TRAIN_AVAILABILITY_CACHE_DAYS_AHEADMust be 1-30

Important Notes ​

  1. Audit Logging: All configuration changes are logged with the updating admin's user ID.
  2. Cache Refresh: Changes may take up to 5 minutes to propagate due to Redis caching.
  3. Validation: Numeric and boolean values are stored as strings in the database.
