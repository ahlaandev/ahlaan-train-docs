System Configuration Guide ​

This guide explains how administrators can configure system-wide settings for the HHR platform.

Quick Overview ​

FeatureDescription
PurposeConfigure system-wide settings and feature flags
AccessAdmin only
ScopeAffects all users and bookings

Seeded System Configurations ​

The system comes with pre-configured settings:

Payment & Fee Settings ​

KeyValueDescription
FEE_DISPLAY_MODECOMBINEDHow payment gateway fees are displayed: COMBINED (single price) or BREAKDOWN (itemized)
PAYMENT_GATEWAY_FEES_ENABLEDfalseEnable or disable payment gateway fee calculation

Tax Settings ​

KeyValueDescription
TAX_ENABLEDtrueEnable or disable tax calculation on bookings
TAX_INCLUSIVE_PRICINGtrueWhen true, displayed prices include tax. When false, tax is added on top.

Wallet Top-Up Settings ​

KeyValueDescription
WALLET_TOPUP_ENABLEDtrueEnable or disable wallet top-up feature
WALLET_TOPUP_MIN_AMOUNT10000Minimum wallet top-up amount (IDR)
WALLET_TOPUP_MAX_PER_TRANSACTION10000000Maximum wallet top-up per transaction (IDR)
WALLET_TOPUP_MAX_PER_DAY50000000Maximum wallet top-up per day (IDR)
WALLET_TOPUP_DEFAULT_GATEWAYXENDITDefault payment gateway for wallet top-up

Wallet Top-Up Constraints

  • Wallet top-ups currently support IDR and SAR only.
  • USD wallet top-ups are disabled.
  • Top-up AML limits are enforced in IDR.
  • XENDIT remains the default gateway, but it currently accepts BANK_TRANSFER only.

Train Availability Cache Settings ​

KeyValueDescription
TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTES30How often to refresh train availability cache (in minutes)
TRAIN_AVAILABILITY_CACHE_DAYS_AHEAD7How many days ahead to pre-warm cache (1-30)

Base URL ​

All system configuration endpoints use:

/api/v1

Authentication ​

All system configuration endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. List All System Configurations ​

Endpoint: GET /admin/system-config

Get all system configuration key-value pairs.

Response: 200 OK

json
{
  "data": [
    {
      "key": "FEE_DISPLAY_MODE",
      "value": "COMBINED",
      "description": "How payment gateway fees are displayed: COMBINED (single price) or BREAKDOWN (itemized)",
      "updatedAt": "2026-01-28T10:00:00Z"
    }
  ]
}

2. Get Configuration by Key ​

Endpoint: GET /admin/system-config/:key

Get a specific configuration value.

Response: 200 OK

json
{
  "key": "TAX_ENABLED",
  "value": "true",
  "description": "Enable or disable tax calculation on bookings",
  "updatedAt": "2026-01-28T10:00:00Z"
}

3. Update Configuration ​

Endpoint: PATCH /admin/system-config/:key

Update a configuration value.

Request Body:

json
{
  "value": "true",
  "description": "Optional updated description"
}

Response: 200 OK

json
{
  "key": "TAX_ENABLED",
  "value": "true",
  "description": "Enable or disable tax calculation on bookings",
  "updatedAt": "2026-01-28T11:00:00Z"
}

Common Workflows ​

Workflow 1: Enable Payment Gateway Fees ​

Scenario: Start charging customers for payment gateway fees

bash
curl -X PATCH /api/v1/admin/system-config/PAYMENT_GATEWAY_FEES_ENABLED \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "true"
  }'

Workflow 2: Switch to Itemized Fee Display ​

Scenario: Show fees separately instead of combined price

bash
curl -X PATCH /api/v1/admin/system-config/FEE_DISPLAY_MODE \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "BREAKDOWN"
  }'

Workflow 3: Update Wallet Top-Up Limits ​

Scenario: Increase maximum wallet top-up limit

bash
curl -X PATCH /api/v1/admin/system-config/WALLET_TOPUP_MAX_PER_TRANSACTION \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "20000000"
  }'

Workflow 4: Adjust Cache for Peak Season ​

Scenario: Increase cache refresh frequency during high traffic periods

bash
curl -X PATCH /api/v1/admin/system-config/TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTES \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "15"
  }'

Workflow 5: Extend Pre-warm for Longer Booking Window ​

Scenario: Allow users to check availability further in advance

bash
curl -X PATCH /api/v1/admin/system-config/TRAIN_AVAILABILITY_CACHE_DAYS_AHEAD \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "value": "14"
  }'

Configuration Types ​

Boolean Values ​

Keys that accept true or false:

  • PAYMENT_GATEWAY_FEES_ENABLED
  • TAX_ENABLED
  • TAX_INCLUSIVE_PRICING
  • WALLET_TOPUP_ENABLED

String Values (Enums) ​

Keys that accept specific string values:

  • FEE_DISPLAY_MODE: COMBINED or BREAKDOWN
  • WALLET_TOPUP_DEFAULT_GATEWAY: XENDIT, MIDTRANS, or STRIPE

Numeric Values ​

Keys that accept numeric values (stored as strings):

  • WALLET_TOPUP_MIN_AMOUNT: In IDR
  • WALLET_TOPUP_MAX_PER_TRANSACTION: In IDR
  • WALLET_TOPUP_MAX_PER_DAY: In IDR
  • TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTES: In minutes (1-1440)
  • TRAIN_AVAILABILITY_CACHE_DAYS_AHEAD: In days (1-30)

Validation Rules ​

KeyValidation
FEE_DISPLAY_MODEMust be COMBINED or BREAKDOWN
WALLET_TOPUP_MIN_AMOUNTMust be positive integer
WALLET_TOPUP_MAX_PER_TRANSACTIONMust be >= min amount
WALLET_TOPUP_MAX_PER_DAYMust be >= max per transaction
WALLET_TOPUP_DEFAULT_GATEWAYMust be valid gateway code
TRAIN_AVAILABILITY_CACHE_INTERVAL_MINUTESMust be 1-1440 (1 min to 24 hours)
TRAIN_AVAILABILITY_CACHE_DAYS_AHEADMust be 1-30

Common Issues & Solutions ​

IssueCauseSolution
Config not taking effectCaching delayWait for cache refresh (typically 5 minutes)
Invalid value rejectedWrong data typeCheck value format (boolean/string/number)
Cannot change valueProtected keySome keys cannot be modified

Important Notes ​

  1. Audit Logging: All configuration changes should be logged for audit purposes
  2. Cache Refresh: Changes may take up to 5 minutes to propagate due to Redis caching
  3. Protected Keys: Some configuration keys cannot be deleted or may require special permissions
  4. Validation: Numeric values are stored as strings in the database

Need Help? ​

For questions or issues:

  1. Check the configuration key format and allowed values
  2. Verify the change was saved by re-fetching the config
  3. Allow time for cache refresh if changes aren't visible
  4. Contact technical support for critical configuration changes
