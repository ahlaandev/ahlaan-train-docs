Custom Tax Management Guide ​

This guide explains how administrators configure custom tax rules for the custom-ota / custom-booking product line.

Status: Custom tax is wired into custom-ota / custom-booking pricing for BUSINESS class only (owner 2026-06-15). On a BUSINESS-class fare the tax is added on top of raw supplier base + custom markup (per the rule's taxBasis) and is broken out on the invoice as the tax line (ZATCA), with subtotal + tax = total. ECONOMY (and any non-business) class stays sold tax-free — custom tax is never applied to it. The taxBasis choice (BASE_PRICE vs FINAL_AMOUNT) controls whether the percentage is levied on the raw base or the marked-up amount; a FIXED tax amount is always SAR (the rule has no currency column).

Quick Overview ​

FeatureDescription
PurposeConfigure flat VAT/tax rules for custom bookings, independent of the OTA tax engine
ScopeOptional per-route (originId / destinationId / tripClass / tripType) or global default
Tax TypesPercentage (e.g. 15% VAT) or Fixed amount
SelectionMost route-specific active rule wins; ties broken by priority. Only ONE rule applies (no accumulation)

This is separate from the OTA Tax Configuration engine (TaxRule). Custom tax is a deliberately simpler, flat configuration: no date/target conditions and no multi-rule accumulation.

How Custom Tax Rules Work ​

┌─────────────────────────────────────────────────────────────────┐
│                  CUSTOM TAX RESOLUTION                            │
├─────────────────────────────────────────────────────────────────┤
│  1. Collect all ACTIVE custom tax rules                          │
│                        ↓                                          │
│  2. Keep rules whose route scope matches the request:           │
│     a null scope field is a wildcard (matches anything)         │
│                        ↓                                          │
│  3. Rank survivors:                                             │
│     ├─ most route-specific first (more non-null scope fields)   │
│     └─ then highest priority                                     │
│                        ↓                                          │
│  4. Apply the single top rule on the chosen taxBasis            │
│     BASE_PRICE   → tax on base only                             │
│     FINAL_AMOUNT → tax on base + markup                         │
└─────────────────────────────────────────────────────────────────┘

A rule with no route scope (all of originId, destinationId, tripClass, tripType omitted) is the global default.

Base URL & Authentication ​

/api/v1

All endpoints require a JWT token with the ADMIN role:

http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. Create Custom Tax Rule ​

Endpoint: POST /admin/custom-tax/rules

json
{
  "name": "Custom VAT 15%",
  "description": "Flat VAT for custom bookings",
  "taxType": "PERCENTAGE",
  "taxRate": 15,
  "taxCode": "VAT-SA",
  "taxBasis": "FINAL_AMOUNT",
  "priority": 100,
  "isActive": true
}

Response: 201 Created — the persisted rule (including generated id, createdBy, timestamps).

2. List Custom Tax Rules ​

Endpoint: GET /admin/custom-tax/rules

Query ParameterTypeDescription
originIdstringFilter by route origin
destinationIdstringFilter by route destination
isActivebooleanFilter by active status
pagenumberPage number (default: 1)
limitnumberItems per page (default: 20)

Response: 200 OK — { data: [...], meta: { total, page, limit, totalPages } }.

3. Get Custom Tax Rule by ID ​

Endpoint: GET /admin/custom-tax/rules/:id — 200 OK or 404 if not found.

4. Update Custom Tax Rule ​

Endpoint: PUT /admin/custom-tax/rules/:id (all fields optional) — 200 OK.

Partial updates respect the PERCENTAGE cap. taxType and taxRate may be sent independently. When taxType is omitted, the 0–100 cap is re-asserted against the persisted rule's type, so { "taxRate": 5000 } on a PERCENTAGE rule is rejected with 400. Flipping a rule to PERCENTAGE (e.g. { "taxType": "PERCENTAGE" }) when the persisted taxRate already exceeds 100 is likewise rejected — resend a valid taxRate ≤ 100 in the same request.

5. Deactivate Custom Tax Rule ​

Endpoint: DELETE /admin/custom-tax/rules/:id — soft delete (isActive: false). Returns { "success": true }.

Common Workflows ​

Global default VAT ​

bash
curl -X POST /api/v1/admin/custom-tax/rules \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{
    "name": "Custom VAT 15%",
    "taxType": "PERCENTAGE",
    "taxRate": 15,
    "taxCode": "VAT-SA",
    "taxBasis": "FINAL_AMOUNT",
    "priority": 0,
    "isActive": true
  }'

Route-specific tax (overrides the default) ​

bash
curl -X POST /api/v1/admin/custom-tax/rules \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{
    "name": "DMX→MKX Tax",
    "originId": "DMX",
    "destinationId": "MKX",
    "taxType": "PERCENTAGE",
    "taxRate": 5,
    "taxCode": "CUSTOM-VAT",
    "taxBasis": "FINAL_AMOUNT",
    "priority": 100,
    "isActive": true
  }'

A request for DMX → MKX resolves to the route-specific rule (more specific); any other route falls back to the global default.

Cache & Propagation ​

Active rules are cached (custom-tax:rules:active, 15-minute TTL) for fast in-memory resolution. Creating, updating, or deactivating a rule flushes that cache so the change takes effect on the next resolution. This cache is scoped to this module only — it does not touch the OTA search cache, because custom tax is not part of OTA pricing.
