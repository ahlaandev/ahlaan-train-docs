Payment Gateway Management Guide ​

This guide explains how administrators can configure payment gateways for processing bookings and wallet top-ups.

Quick Overview ​

FeatureDescription
PurposeConfigure payment gateways for booking payments and wallet top-ups
Supported GatewaysXendit (primary), Midtrans (backup), Stripe (international)
Payment MethodsQRIS, Bank Transfer, E-Wallet, Credit Card

Current Runtime Restriction

XENDIT remains the default gateway, but it currently accepts BANK_TRANSFER only.

All other Xendit payment methods are rejected at runtime.

Seeded Payment Gateways ​

The system comes with pre-configured payment gateways:

CodeNameStatusSupported Methods
XENDITXendit Payment GatewayACTIVEQRIS, BANK_TRANSFER, EWALLET
MIDTRANSMidtrans Payment GatewayINACTIVEQRIS, BANK_TRANSFER, CARD, EWALLET
STRIPEStripe Payment GatewayINACTIVECARD

Gateway Descriptions ​

Xendit (Primary Gateway)

  • Primary payment gateway for Indonesia
  • Supports QRIS, Bank Transfer, and E-Wallet
  • Low transaction fees with wide coverage
  • Runtime note: only BANK_TRANSFER is currently accepted even though seeded gateway metadata still lists other methods

Midtrans (Backup Gateway)

  • Alternative payment gateway for Indonesia
  • Additional payment method options
  • Can be activated if Xendit has issues

Stripe (International Cards)

  • International payment gateway
  • Primarily for credit card payments
  • For customers outside Indonesia

Base URL ​

All payment gateway endpoints use:

/api/v1

Authentication ​

All payment gateway endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. List Payment Gateways ​

Endpoint: GET /admin/payment/gateways

Get all configured payment gateways.

Response: 200 OK

json
{
  "data": [
    {
      "code": "XENDIT",
      "name": "Xendit Payment Gateway",
      "description": "Primary payment gateway for Indonesia - supports QRIS, Bank Transfer, E-Wallet",
      "status": "ACTIVE",
      "supportedMethods": ["QRIS", "BANK_TRANSFER", "EWALLET"],
      "priority": 0
    }
  ]
}

2. Update Payment Gateway Status ​

Endpoint: PATCH /admin/payment/gateways/:code

Activate or deactivate a payment gateway.

Request Body:

json
{
  "status": "ACTIVE"
}

Response: 200 OK

System Configuration Keys ​

The following system configuration keys control payment gateway behavior:

KeyDefault ValueDescription
FEE_DISPLAY_MODECOMBINEDHow fees are displayed: COMBINED or BREAKDOWN
PAYMENT_GATEWAY_FEES_ENABLEDfalseEnable or disable payment gateway fee calculation
WALLET_TOPUP_ENABLEDtrueEnable or disable wallet top-up feature
WALLET_TOPUP_DEFAULT_GATEWAYXENDITDefault gateway for wallet top-ups

Wallet Top-Up Currency Support

Wallet top-ups currently support IDR and SAR only. USD top-ups are disabled.

Admin Configuration Endpoints ​

These endpoints allow administrators to configure payment gateway credentials dynamically.

Base URL ​

/api/v1/admin/payment-gateway

Authentication ​

All endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

1. Get Xendit Configuration ​

Endpoint: GET /admin/payment-gateway/xendit

Retrieves the current Xendit configuration with masked credentials for security.

Response: 200 OK

json
{
  "secretKey": "xnd_...****",
  "webhookToken": "your...****",
  "updatedAt": "2026-01-20T12:00:00.000Z"
}

Response Fields:

FieldTypeDescription
secretKeystringXendit API secret key (masked for security)
webhookTokenstringXendit webhook verification token (masked for security)
updatedAtDateLast updated timestamp

Notes:

  • If credentials are not configured in the database, returns "Not configured (using env var)"
  • Keys are masked showing only first 4 and last 4 characters

2. Update Xendit Secret Key ​

Endpoint: PATCH /admin/payment-gateway/xendit/secret-key

Updates the Xendit API secret key used for all payment requests.

Request Body:

json
{
  "secretKey": "xnd_development_..."
}

Request Fields:

FieldTypeRequiredDescription
secretKeystringYesXendit API secret key

Response: 200 OK

json
{
  "success": true,
  "message": "Xendit secret key updated successfully"
}

Error Responses:

StatusDescription
400Invalid request body or missing secretKey
401Unauthorized - Invalid or missing JWT token
403Forbidden - User does not have ADMIN role

3. Update Xendit Webhook Token ​

Endpoint: PATCH /admin/payment-gateway/xendit/webhook-token

Updates the Xendit webhook verification token used to validate incoming webhooks.

Request Body:

json
{
  "webhookToken": "your-webhook-verification-token"
}

Request Fields:

FieldTypeRequiredDescription
webhookTokenstringYesXendit webhook verification token

Response: 200 OK

json
{
  "success": true,
  "message": "Xendit webhook token updated successfully"
}

Error Responses:

StatusDescription
400Invalid request body or missing webhookToken
401Unauthorized - Invalid or missing JWT token
403Forbidden - User does not have ADMIN role

Configuration Storage ​

Payment gateway credentials are stored in the system configuration table with the following keys:

Config KeyDescriptionEditable via API
XENDIT_SECRET_KEYXendit API secret keyYes
XENDIT_WEBHOOK_TOKENXendit webhook verification tokenYes

Note: When credentials are set via these API endpoints, they override environment variable values for the application.
