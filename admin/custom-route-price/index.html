Custom Route Pricing Guide ​

This guide explains how administrators can manually set custom capital/selling prices for specific routes, overriding the default OTA or Tariff pricing.

Quick Overview ​

FeatureDescription
PurposeManually set prices per route instead of using OTA/Tariff prices
PriorityCustom Route Price takes precedence over OTA and Tariff
Price SourceEither fixed sellingPrice OR dynamic OTA - priceReducer
OverridesPer-route tax and markup toggles

capitalPrice — No longer the booking cost basis ​

Heads up: As of the 2026-05-04 schema change, CustomBooking's capital basis is no longer sourced from CustomRoutePrice.capitalPrice. The column is retained for historical reasons but is not read by the booking flow.

CustomBooking.capitalPriceTotalSAR and per-leg capitalPriceSAR are now snapshotted at the PENDING → CONFIRMED transition from a separate TicketChannelRoutePrice table keyed by (ticketChannelId, originId, destinationId, tripClass, tripType). This lets the cost basis reflect which channel sourced the ticket (Almosafer, Wego, direct, etc.), which is only known once an admin assigns a channel at confirm time.

  • Per-channel cost basis is managed via POST/GET/PATCH/DELETE /admin/ticket-channels/:channelId/route-prices. See the Ticket Channel admin guide for the CRUD contract.
  • Existing-booking corrections still go through PATCH /admin/custom-booking/:id/capital-price, but now require booking.status === CONFIRMED. See the Custom Booking admin guide.
  • CustomRoutePrice.capitalPrice may still be supplied on this resource for backwards compatibility, but it has no runtime effect. Treat it as deprecated; do not rely on it for margin tracking.

Pricing Decision Flow ​

┌─────────────────────────────────────────────────────────────────┐
│                    PRICING DECISION FLOW                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. Search for active CustomRoutePrice                           │
│     └─ Match: originId, destinationId, tripClass, tripType       │
│                        ↓                                         │
│  2. Determine base price:                                        │
│     ├─ useSellingPrice=true  → base = sellingPrice              │
│     └─ useSellingPrice=false → base = max(0, OTA - priceReducer)│
│                        ↓                                         │
│  3. Apply markup (based on override toggle):                     │
│     ├─ overrideMarkup=false → apply system markup               │
│     └─ overrideMarkup=true  → use route's markupEnabled         │
│                        ↓                                         │
│  4. Apply tax (based on override toggle):                         │
│     ├─ overrideTax=false → apply system tax                     │
│     └─ overrideTax=true  → use route's taxEnabled               │
│                        ↓                                         │
│  5. Return CUSTOM_ROUTE pricing                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

priceReducer in the Custom OTA endpoints. The flow above is the booking pricing path. The /v1/custom-ota/* endpoints consume only priceReducer (never sellingPrice / useSellingPrice): they take the pre-tax base and subtract the reducer once (custom-ota is sold tax-free — tax is excluded from the payable; the tax-inclusive total is kept only as the strikethrough). For a ROUND_TRIP book/calculate, the reducer is resolved per leg — outbound (origin → destination) plus return (destination → origin), each keyed by that leg's cabin class — and the two are summed. See the Custom OTA Guide.

Override Toggle Truth Table ​

overrideTaxtaxEnabledResult

5. Delete (Deactivate) Custom Route Price ​

Endpoint: DELETE /admin/custom-route-prices/:id

Soft deletes the custom route price by setting isActive to false. The data is preserved for historical records.

Response: 200 OK

json
{
  "success": true
}

Common Workflows ​

Workflow 1: Create Fixed Selling Price ​

Scenario: Set a fixed 100 SAR selling price for Mecca-Medina economy route

bash
curl -X POST /api/v1/admin/custom-route-prices \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "<mecca-location-uuid>",
    "destinationId": "<medina-location-uuid>",
    "tripClass": "ECONOMY",
    "tripType": "ONE_WAY",
    "capitalPrice": 80.0,
    "sellingPrice": 100.0,
    "priceReducer": 0,
    "isActive": true,
    "useSellingPrice": true
  }'

Workflow 2: Create OTA-Based Dynamic Pricing ​

Scenario: Always be 10 SAR cheaper than OTA price

bash
curl -X POST /api/v1/admin/custom-route-prices \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "<jeddah-location-uuid>",
    "destinationId": "<cairo-location-uuid>",
    "tripClass": "ECONOMY",
    "tripType": "ONE_WAY",
    "capitalPrice": 50.0,
    "sellingPrice": 100.0,
    "priceReducer": 10.0,
    "isActive": true,
    "useSellingPrice": false
  }'

Workflow 3: Disable Tax for Specific Route ​

Scenario: Create a tax-exempt route (e.g., for certain pilgrim packages)

bash
curl -X POST /api/v1/admin/custom-route-prices \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "<mecca-location-uuid>",
    "destinationId": "<medina-location-uuid>",

    "tripType": "ONE_WAY",
    "capitalPrice": 80.0,
    "sellingPrice": 100.0,
    "priceReducer": 0,
    "isActive": true,
    "useSellingPrice": true,
    "overrideTax": true,
    "taxEnabled": false
  }'

Workflow 4: Disable Markup for Competitive Pricing ​

Scenario: Route-specific pricing without additional markup

bash
curl -X POST /api/v1/admin/custom-route-prices \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "<location-a-uuid>",
    "destinationId": "<location-b-uuid>",
    "tripClass": "BUSINESS",
    "tripType": "ROUND_TRIP",
    "capitalPrice": 200.0,
    "sellingPrice": 300.0,
    "priceReducer": 0,
    "isActive": true,
    "useSellingPrice": true,
    "overrideMarkup": true,
    "markupEnabled": false
  }'

Workflow 5: Create Custom OTA Route (Scraper-Based Pricing) ​

Scenario: Configure a route for custom-ota where base price comes from scraper data, only priceReducer is used to adjust the price

bash
curl -X POST /api/v1/admin/custom-route-prices \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{
    "originId": "<jeddah-location-uuid>",
    "destinationId": "<makkah-location-uuid>",
    "tripClass": "ECONOMY",
    "tripType": "ONE_WAY",
    "priceReducer": 15.0,
    "useSellingPrice": false,
    "isActive": true
  }'

Note: When useSellingPrice=false, the capitalPrice and sellingPrice fields can be omitted. The price will be calculated as scraperMeanPrice - priceReducer. Use capitalPrice optionally for margin tracking.

Pricing Calculation Examples ​

Example 1: Fixed Selling Price with System Markup ​

CustomRoutePrice:
  sellingPrice = 100 SAR
  useSellingPrice = true
  overrideMarkup = false (use system markup)
  overrideTax = false (use system tax)

System Config:
  System Markup = 10%
  System Tax (VAT) = 15%

Calculation:
  Base = sellingPrice = 100 SAR
  After Markup = 100 × 1.10 = 110 SAR
  After Tax = 110 × 1.15 = 126.50 SAR
  ─────────────────────────────
  Final Price = 126.50 SAR

Example 2: Dynamic OTA-Based Price ​

CustomRoutePrice:
  priceReducer = 10 SAR
  useSellingPrice = false
  overrideMarkup = true
  markupEnabled = false (no markup)
  overrideTax = true
  taxEnabled = true (apply tax)

OTA Price = 150 SAR

Calculation:
  Base = max(0, OTA - reducer) = max(0, 150 - 10) = 140 SAR
  After Markup = 140 × 1.00 = 140 SAR (disabled)
  After Tax = 140 × 1.15 = 161 SAR
  ─────────────────────────────
  Final Price = 161 SAR

Example 3: Round Trip Pricing ​

For ROUND_TRIP trips, each leg is calculated independently and then summed:

Outbound: MECCA → MEDINA (Economy)
  Base = 100 SAR
  Final = 126.50 SAR

Return: MEDINA → MECCA (Economy)
  Base = 100 SAR
  Final = 126.50 SAR

Total Round Trip = 253 SAR

Pricing Source in Search Response ​

When custom route pricing is active, the search response will include:

json
{
  "outboundTrips": [
    {
      "selectedOutboundFare": {
        "pricingSource": "CUSTOM_ROUTE",
        "basePrice": 100.0,
        "markupAmount": 10.0,
        "taxAmount": 15.0,
        "totalPrice": 126.50
      }
    }
  ]
}

The pricingSource field will be "CUSTOM_ROUTE" when custom pricing is applied.
