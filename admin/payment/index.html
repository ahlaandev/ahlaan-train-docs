Payment Management Guide ​

This guide explains how administrators can manage payments, process refunds, and reconcile payment issues.

Quick Overview ​

FeatureDescription
PurposeManage payments, refunds, webhooks, and reconciliation
AccessAdmin only
ScopeAll payments across the platform

Base URL ​

All payment management endpoints use:

/api/v1

Authentication ​

All payment endpoints require:

  • JWT Token in Authorization header
  • ADMIN role in user account
http
Authorization: Bearer <your-admin-jwt-token>

Endpoints ​

1. Refund a Payment ​

Endpoint: POST /admin/payment/:id/refund

Process a refund for a payment.

Request Body:

json
{
  "paymentId": "payment-uuid",
  "amount": 100.00,
  "reason": "Customer requested refund"
}

Response: 200 OK

json
{
  "success": true,
  "refundId": "refund-uuid",
  "amount": 100.00,
  "status": "PROCESSING"
}

2. Manual Confirm Payment ​

Endpoint: POST /admin/payment/:id/manual-confirm

Manually confirm a booking payment when webhook failed.

⚠️ Important: For wallet top-ups, use /wallet-topup/:id/reconcile instead.

Response: 200 OK

json
{
  "success": true,
  "payment": {
    "id": "payment-uuid",
    "status": "PAID"
  },
  "booking": {
    "id": "booking-uuid",
    "status": "CONFIRMED"
  }
}

3. List Pending Wallet Top-Ups ​

Endpoint: GET /admin/payment/wallet-topup/pending

List wallet top-up payments that may need reconciliation.

Query Parameters:

limitnumberResults per page (default: 50)

GET /admin/payment/wallet-topup/pending?status=PENDING&limit=20

5. Reconcile Wallet Top-Up ​

Endpoint: POST /admin/payment/wallet-topup/:id/reconcile

Manually process a wallet top-up payment when webhook failed.

This will:

  1. Mark payment as PAID
  2. Mark invoice as PAID
  3. Credit wallet with pre-calculated SAR amount

Parameter: id - Payment ID or externalId

Request Body:

json
{
  "reason": "Webhook failed - verified with bank statement",
  "gatewayReference": "BANK-REF-123",
  "verifiedAmount": 500000
}

Response: 200 OK

json
{
  "success": true,
  "message": "Wallet top-up successfully reconciled",
  "payment": {
    "id": "payment-uuid",
    "externalId": "inv-INV-202601-0042-A3X-xendit-1",
    "status": "PAID"
  },
  "invoice": {
    "id": "invoice-uuid",
    "invoiceNumber": "INV-202601-0042",
    "status": "PAID"
  },
  "walletCredit": {
    "transactionId": "txn-uuid",
    "walletId": "wallet-uuid",
    "netSAR": 463.00,
    "grossSAR": 500.00,
    "taxDeducted": 37.00
  },
  "audit": {
    "reconciledBy": "admin-uuid",
    "reconciledAt": "2026-01-31T12:00:00Z"
  }
}

Webhook Monitoring ​

6. Get Webhook Logs ​

Endpoint: GET /admin/payment/webhooks/logs

View webhook processing logs for debugging.

Query Parameters:

ParameterTypeDescription
statusenumFilter: PAYMENT_NOT_FOUND, FAILED, SUCCESS
webhookTypeenumFilter: Invoice, PaymentRequest
externalIdstringSearch by external ID (partial match)
limitnumberResults per page (default: 50)

bash
GET /admin/payment/webhooks/logs?status=FAILED&limit=20

Wallet Top-Up Reconciliation Workflow ​

When webhook processing fails for wallet top-ups:

1. Check pending payments
   GET /admin/payment/wallet-topup/pending?status=PENDING

2. Verify payment details
   GET /admin/payment/wallet-topup/:id

3. Reconcile after verification
   POST /admin/payment/wallet-topup/:id/reconcile
   {
     "reason": "Verified with gateway",
     "gatewayReference": "REF-123"
   }

Common Issues & Solutions ​

IssueCauseSolution
Payment stuck in PENDINGWebhook failedUse manual confirm or reconcile
Wallet not creditedWebhook processing failedUse reconcile endpoint for wallet top-ups
Booking not confirmedPayment webhook failedUse manual confirm endpoint
Payment not foundExternal ID mismatchCheck webhook logs for details
