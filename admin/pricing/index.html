Pricing & Markup Management Guide ​

This guide explains how administrators can configure pricing markups and discounts for bookings.

Quick Overview ​

FeatureDescription
PurposeConfigure markups/discounts applied on top of base prices
Applied ToB2B and B2C booking calculations
Markup TypesPercentage-based (e.g., 10% markup) or Fixed amount (SAR/IDR/USD)
FlexibilitySupport for route-specific, seasonal, volume-based, and customer-type rules

How Pricing Rules Work ​

Pricing Calculation Flow ​

┌─────────────────────────────────────────────────────────────────┐
│                    PRICING CALCULATION FLOW                    │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. Get base price from OTA or Tariff                          │
│                        ↓                                         │
│  2. Search for applicable pricing rules:                        │
│     ├─ Filter by target (ALL/B2B/B2C/ORGANIZATION)              │
│     ├─ Filter by route (origin/destination match)                │
│     ├─ Filter by date range (startDate/endDate)                  │
│     ├─ Filter by passenger type (ADULT/CHILD/INFANT)            │
│     ├─ Filter by cabin class (targetClass: ECONOMY/BUSINESS)    │
│     ├─ Filter by volume (minBookings/maxBookings)               │
│     └─ Sort by priority (higher = applied first)                 │
│                        ↓                                         │
│  3. Apply matching rules sequentially:                           │
│                                                                  │
│     Positive markupValue:  Add to price (e.g., 10% markup)     │
│     Negative markupValue: Subtract (e.g., -5% discount)        │
│     Fixed: Add fixed amount in SAR, IDR, or USD                   │
│                        ↓                                         │
│  4. Calculate final price with all markups applied              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘

Rule Selection Priority ​

When multiple rules match, the system selects the single highest priority rule within each target category. For BASE_MARKUP type, the following logic applies:

Target Priority (for BASE_MARKUP) ​

B2B Flow:  ORGANIZATION → B2B → ALL (fallback)
B2C Flow:  B2C → ALL (fallback)

Route-Specific vs Global Rules ​

Route-specific rules (those with origin or destination set) always take precedence over global rules (with no route specified), regardless of priority value:

Example:
  - Global Rule (priority=100): 10% for all routes
  - JED→CGK Rule (priority=50): 15% for JED→CGK route

  → For JED→CGK searches: 15% applied (route-specific wins)
  → For JED→RUH searches: 10% applied (fallback to global)

Date Range Filtering ​

Rules with startDate and endDate set are only applied when the departure date falls within the range. Rules without date restrictions (both null) are evergreen and match all departures:

Example:
  - Hajj Season Rule: 20% markup, valid Jun-Aug 2026
  - Global Rule: 10% markup, no date restrictions (evergreen)

  → Booking in July 2026: 20% applied (within range, higher priority)
  → Booking in October 2026: 10% applied (Hajj rule inactive, evergreen fallback)

Selection Flow ​

1. Filter rules by:
   - isActive = true
   - Matching target (B2B/B2C/ALL/ORGANIZATION)
   - Origin matches (or is null/global)
   - Destination matches (or is null/global)
   - Departure date within startDate/endDate range (or rule has no date restrictions)
   - Cabin class matches (if rule.targetClass is set)

2. Within matching rules:
   - Route-specific rules (+10000 priority boost) win over global rules
   - Among route-specific: highest original priority wins
   - Among global rules: highest priority wins

3. Return single winning rule's markup

Cabin Class Filtering (targetClass) ​

Rules can optionally specify a targetClass to apply only to specific cabin classes:

Rule's targetClassSearch cabinClassRule Applied?
null (all)ECONOMY or BUSINESS✅ Yes
null (all)not provided✅ Yes
ECONOMYECONOMY✅ Yes
ECONOMYBUSINESS❌ No
BUSINESSBUSINESS✅ Yes
BUSINESSECONOMY❌ No
ECONOMYnot provided❌ No (requires specific class)

Example:

Rules Available:
  - Economy Markup (targetClass=ECONOMY, priority=50): 10%
  - Business Markup (targetClass=BUSINESS, priority=50): 15%
  - Global Markup (targetClass=null, priority=10): 8%

Search (ECONOMY cabin):
  → Economy Markup applied (10%) - class-specific matches

Search (BUSINESS cabin):
  → Business Markup applied (15%) - class-specific matches

Search (no cabin class specified):
  → Global Markup applied (8%) - only null targetClass matches

Rule Type Options ​

ValueDescriptionUse Case
BASE_MARKUPSingle markup rule per route/targetStandard margin (returns highest priority match)
ROUTE_SPECIFICMarkup for specific routesHigh-demand routes
DATE_RANGETime-based pricing (peak hours, seasons)Surge pricing
VOLUME_DISCOUNTDiscount for large bookingsGroup bookings
PASSENGER_TYPEDifferent markup by passenger typeChild/infant pricing

BASE_MARKUP Selection

BASE_MARKUP rules select a single highest-priority rule (not multiple). Route-specific rules always win over global rules, even if the global rule has a higher priority value.

Target Options ​

B2BB2B agents onlyB2B-specific margin
B2CRegular customers onlyB2C markup

Route-Specific BASE_MARKUP Behavior

Route-specific BASE_MARKUP rules always take precedence over global BASE_MARKUP rules, regardless of priority value. This allows you to define a global fallback (e.g., 10%) while overriding specific routes with different rates.

Pricing Calculation Examples ​

Example 1: Simple Percentage Markup ​

Base Price (OTA): 100 SAR
─────────────────────────
Base Markup (10%): 100 × 0.10 = 10 SAR
─────────────────────────
Final Price: 110 SAR

Example 2: FIXED Markup ​

Base Price (OTA): 100 SAR
─────────────────────────
Fixed Markup (50 SAR): 100 + 50 = 150 SAR
─────────────────────────
Final Price: 150 SAR

Note: FIXED markup is ADDED to base price (not multiplied)

Example 3: Route-Specific vs Global Rule ​

Scenario: Searching JED→CGK on June 15, 2026

Rules Available:
  - Global B2B Rule (priority=100): 10% for all routes
  - JED→CGK Route Rule (priority=50): 15% for JED→CGK

Result: 15% markup applied (route-specific wins)

Scenario: Searching JED→RUH on June 15, 2026

Result: 10% markup applied (no route-specific rule, falls back to global)

Example 4: Date Range Filtering ​

Scenario: Booking on July 15, 2026

Rules Available:
  - Hajj Season Rule (priority=100): 20%, valid Jun 1 - Aug 31, 2026
  - Global Rule (priority=50): 10%, no date restrictions (evergreen)

Result: 20% markup applied (within Hajj season range, higher priority)

Scenario: Booking on October 15, 2026

Result: 10% markup applied (Hajj rule inactive, evergreen fallback)
