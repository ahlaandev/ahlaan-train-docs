API Endpoints ​

Complete reference for WhatsApp management API endpoints.

Authentication ​

GET /login ​

Initiate QR code login flow.

How It Works:

  • If no device ID is configured: Uses GoWA legacy mode (no X-Device-Id header)
  • If device ID is configured: Sends X-Device-Id header with request

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "QR code generated successfully",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-abc123.png",
    "qr_duration": 30
  }
}

Already Logged In:

json
{
  "status": 200,
  "code": "ALREADY_LOGGED_IN",
  "message": "Already logged in - session is active"
}

Auto-Update Behavior:

  • After successful QR scan, system fetches device status to get real phone number
  • Device ID automatically saved to database if not already configured
  • Check server logs for confirmation: [WhatsAppService] Updating device ID from {none} to {real}

GET /login-with-code ​

Generate a pairing code for phone number login (alternative to QR code).

Query Parameters:

ParameterTypeRequiredDescription
phonestringYesPhone number for pairing (e.g., 628123456789)

Example:

bash
GET /admin/whatsapp/login-with-code?phone=628123456789

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Auto-Update Behavior:

  • After successful pairing, system fetches device status to get real phone number
  • Device ID automatically saved to database if not already configured

GET /status ​

Get the current connection and authentication status.

How It Works:

  1. If device ID is configured: Sends X-Device-Id header with request
  2. If no device ID is configured:
    • Automatically registers a new device with GoWA (POST /devices)
    • Saves the new device ID to database
    • Returns status with the new device ID

Response (Before Login):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": false,
    "is_logged_in": false
  }
}

Response (After Login):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Fields:

FieldTypeDescription
is_connectedbooleanWhether the device is connected to GoWA service
is_logged_inbooleanWhether the device is logged into WhatsApp
device_idstringThe device ID (included when configured)

POST /logout ​

Logout from WhatsApp and clear the session.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Logged out successfully"
}

Important: After logout, the device ID is automatically cleared from the database. The next call to GET /status will auto-register a new device and return a fresh device ID ready for login.

POST /reconnect ​

Attempt to reconnect to the WhatsApp service.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Reconnection initiated"
}

Device Configuration ​

GET /config/device-id ​

Get the current device ID configuration.

Response (No Device ID - Legacy Mode):

json
{
  "deviceId": "",
  "source": "none",
  "isConfigured": false
}

Response (Device ID Set - After Login):

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Fields:

FieldTypeDescription
deviceIdstringThe current device ID (empty if not configured)
sourcestringSource of configuration: database, environment, or none
isConfiguredbooleanWhether a device ID is configured

PUT /config/device-id ​

Manually set or update the device ID in the database (optional - auto-detection is default).

Request Body:

json
{
  "deviceId": "628123456789@s.whatsapp.net"
}

Validation Rules:

  • Device ID must end with @s.whatsapp.net
  • Cannot be empty or null
  • Must be a string

Response:

json
{
  "success": true,
  "message": "Device ID updated successfully",
  "deviceId": "628123456789@s.whatsapp.net"
}

Error Response (400):

json
{
  "statusCode": 400,
  "message": "Device ID must end with @s.whatsapp.net",
  "error": "Bad Request"
}

DELETE /config/device-id ​

Clear the device ID from the database. The service will fall back to:

  1. Environment variable (WHATSAPP_DEVICE_ID)
  2. GoWA legacy mode (no device ID)

Response:

json
{
  "success": true,
  "message": "Device ID cleared from database"
}

Device ID Formats ​

No Device ID (Legacy Mode) ​

When no device ID is configured, the system uses GoWA's legacy mode:

  • No X-Device-Id header sent to GoWA
  • GoWA uses its default device for /app/* endpoints
  • After login, device ID is automatically set to phone number

Real Device ID (Phone Number) ​

Format: {phone_number}@s.whatsapp.net

Example: 628123456789@s.whatsapp.net

  • Phone Number: 10-15 digits, country code + number
  • Suffix: Must end with @s.whatsapp.net
  • Persistent: Stored in database after login
  • Used: Sent as X-Device-Id header for all subsequent API calls

Priority Order ​

Device ID resolution follows this priority:

  1. Database Cache (1-minute TTL)
  2. Database (SystemConfiguration table)
  3. Environment Variable (WHATSAPP_DEVICE_ID)
  4. None (GoWA legacy mode - no device ID)
