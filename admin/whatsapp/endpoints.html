API Endpoints ​

Complete reference for all WhatsApp management API endpoints.

Authentication & Configuration ​

GET /login ​

Initiate QR code login flow. Uses GoWA legacy mode (no device ID required) or configured device ID.

How It Works:

  • If no device ID is configured: Uses GoWA legacy mode (no X-Device-Id header)
  • If device ID is configured: Sends X-Device-Id header with request

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "QR code generated successfully",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-abc123.png",
    "qr_duration": 30
  }
}

Already Logged In:

json
{
  "status": 200,
  "code": "ALREADY_LOGGED_IN",
  "message": "Already logged in - session is active"
}

Auto-Update Behavior:

  • After successful QR scan, system fetches device status to get real phone number
  • Device ID automatically saved to database if not already configured
  • Check server logs for confirmation: [WhatsAppService] Updating device ID from {none} to {real}

GET /login-with-code ​

Generate a pairing code for phone number login (alternative to QR code).

Query Parameters:

ParameterTypeRequiredDescription
phonestringYesPhone number for pairing (e.g., 628123456789)

Example:

bash
GET /admin/whatsapp/login-with-code?phone=628123456789

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Auto-Update Behavior:

  • After successful pairing, system fetches device status to get real phone number
  • Device ID automatically saved to database if not already configured

GET /status ​

Get the current connection and authentication status.

How It Works:

  1. If device ID is configured: Sends X-Device-Id header with request
  2. If no device ID is configured:
    • Automatically registers a new device with GoWA (POST /devices)
    • Saves the new device ID to database
    • Returns status with the new device ID

Response (After Logout - Auto-registered New Device):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "device_id": "628123456789@s.whatsapp.net",
    "is_connected": true,
    "is_logged_in": false
  }
}

Response (After Login - Device Active):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Fields:

FieldTypeDescription
is_connectedbooleanWhether the device is connected to GoWA service
is_logged_inbooleanWhether the device is logged into WhatsApp
device_idstringThe device ID (always included after auto-registration)

POST /logout ​

Logout from WhatsApp and clear the session.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Logged out successfully"
}

Important: After logout, the device ID is automatically cleared from the database. The next call to GET /status will auto-register a new device and return a fresh device ID ready for login.

POST /reconnect ​

Attempt to reconnect to the WhatsApp service.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Reconnection initiated"
}

Device Configuration ​

GET /config/device-id ​

Get the current device ID configuration.

Response (No Device ID - Legacy Mode):

json
{
  "deviceId": "",
  "source": "none",
  "isConfigured": false
}

Response (Device ID Set - After Login):

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Fields:

FieldTypeDescription
deviceIdstringThe current device ID (empty if not configured)
sourcestringSource of configuration: database, environment, or none
isConfiguredbooleanWhether a device ID is configured

Possible Device ID Formats:

  • Empty: Using GoWA legacy mode (no device ID)
  • Phone number: 628123456789@s.whatsapp.net (after login or manual configuration)

PUT /config/device-id ​

Manually set or update the device ID in the database (optional - auto-detection is default).

Request Body:

json
{
  "deviceId": "628123456789@s.whatsapp.net"
}

Validation Rules:

  • Device ID must end with @s.whatsapp.net
  • Cannot be empty or null
  • Must be a string

Response:

json
{
  "success": true,
  "message": "Device ID updated successfully",
  "deviceId": "628123456789@s.whatsapp.net"
}

Error Response (400):

json
{
  "statusCode": 400,
  "message": "Device ID must end with @s.whatsapp.net",
  "error": "Bad Request"
}

DELETE /config/device-id ​

Clear the device ID from the database. The service will fall back to:

  1. Environment variable (WHATSAPP_DEVICE_ID)
  2. GoWA legacy mode (no device ID)

Response:

json
{
  "success": true,
  "message": "Device ID cleared from database"
}

Multi-Device Management (GoWA v8) ​

These endpoints provide advanced multi-device management capabilities. Most users won't need these - the simplified login flow with auto-detection is recommended.

GET /devices ​

List all registered WhatsApp devices from the GoWA service.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Devices retrieved successfully",
  "data": [
    {
      "id": "628123456789@s.whatsapp.net",
      "phone_number": "628123456789",
      "state": "logged_in",
      "connected": true,
      "loggedIn": true
    }
  ]
}

When GoWA is unavailable:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "No devices registered or GoWA service not available",
  "data": []
}

POST /devices ​

Add a new WhatsApp device to the GoWA service (advanced - usually not needed).

Request Body:

json
{
  "device_id": "my-custom-device-id"
}

Note: device_id is optional. If not provided, GoWA will generate one.

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Device created successfully",
  "device_id": "628123456789@s.whatsapp.net",
  "phone_number": "628123456789"
}

When GoWA is unavailable (503):

json
{
  "statusCode": 503,
  "message": "GoWA service is not available or does not support device management",
  "error": "Service Unavailable"
}

Understanding Legacy vs Multi-Device Modes ​

Legacy Mode (/app/* endpoints) ​

Characteristics:

  • No X-Device-Id header required
  • GoWA uses its default device
  • Simpler setup for single-device scenarios
  • Auto-detection works seamlessly

When to Use:

  • Initial setup (no device ID configured yet)
  • Single-device deployments
  • Simplified workflows

Endpoints:

  • GET /admin/whatsapp/login
  • GET /admin/whatsapp/status
  • POST /admin/whatsapp/logout
  • POST /admin/whatsapp/reconnect

Multi-Device Mode (/devices/{id}/* endpoints) ​

Characteristics:

  • Requires X-Device-Id header
  • Device must be registered via POST /devices first
  • Supports multiple WhatsApp devices
  • More complex setup

When to Use:

  • Multiple device management
  • Explicit device selection
  • Advanced multi-device scenarios

Endpoints:

  • GET /admin/whatsapp/devices
  • POST /admin/whatsapp/devices
  • GET /admin/whatsapp/devices/:id
  • GET /admin/whatsapp/devices/:id/login
  • POST /admin/whatsapp/devices/:id/logout

Automatic Mode Selection ​

The system automatically selects the appropriate mode based on device ID configuration:

┌─────────────────────┐
│ Device ID Configured?│
└──────────┬──────────┘
           │
     ┌─────┴─────┐
     │           │
    NO          YES
     │           │
     ▼           ▼
┌─────────┐  ┌─────────────┐
│ Legacy  │  │ Multi-Device│
│ Mode    │  │ Mode        │
│(/app/*) │  │(/devices/*) │
└─────────┘  └─────────────┘

URL Encoding Notes ​

When using device IDs in URLs, always URL encode special characters:

CharacterEncoded
@%40

Examples:

  • Raw: 628123456789@s.whatsapp.net
  • Encoded: 628123456789%40s.whatsapp.net

Usage:

bash
# Correct (URL encoded)
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789%40s.whatsapp.net/status"

# Incorrect (not encoded)
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789@s.whatsapp.net/status"

Legacy vs Multi-Device Error Example ​

404 with Legacy Endpoint (Expected):

bash
GET /admin/whatsapp/status
# Works fine - no device ID required

404 with Multi-Device Endpoint (Error):

bash
GET /admin/whatsapp/devices/unregistered-id/status
# Error: DEVICE_NOT_FOUND - device not registered

Solution: For simplified setup, use legacy endpoints (/app/*) instead of multi-device endpoints (/devices/{id}/*).
