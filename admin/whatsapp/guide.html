Usage Guide ​

Common workflows and examples for managing WhatsApp devices with simplified auto-detection.

Complete Workflow: Zero-Config Setup ​

The simplified workflow requires no manual device management - just start and scan!

Step 1: Start the Server ​

The server automatically uses GoWA legacy mode when no device ID is configured.

Expected Server Startup Logs:

[WhatsAppInitializer] Initializing WhatsApp device...
[WhatsAppService] No device configured. Using GoWA legacy mode (no device ID required for /app/* endpoints).
[WhatsAppService] Device ID will be automatically set to phone number after successful login.
[WhatsAppService] WhatsApp service initialized

Step 2: Get QR Code ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "QR code generated successfully",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-abc123.png",
    "qr_duration": 30
  }
}

Step 3: Scan QR Code ​

On your WhatsApp phone:

  1. Open Settings
  2. Tap Linked Devices
  3. Tap Link a Device
  4. Scan the QR code from qr_link

Step 4: Automatic Device ID Detection ​

After successful login, the system automatically fetches and stores your phone number.

Server Logs After Login:

[WhatsAppService] Updating device ID from (none) to 628123456789@s.whatsapp.net
[WhatsAppDeviceService] Device ID updated in database: 628123456789@s.whatsapp.net

Step 5: Verify Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response:

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Step 6: Check Connection Status ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Step 7: Send Messages ​

Now you can send messages:

bash
curl -X POST http://localhost:3000/api/v1/whatsapp/send/message \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "message": "Hello from HHR API!"
  }'

  -H "Authorization: Bearer YOUR_TOKEN"

Response:

  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Step 2: Enter Pairing Code ​

On your WhatsApp phone:

  1. Open Settings
  2. Tap Linked Devices
  3. Tap Link with phone number instead
  4. Enter the pairing code: K241-9XYZ

Step 3: Automatic Device ID Detection ​

Same as QR code flow - device ID automatically detected and stored.

Manual Device ID Management (Optional) ​

While automatic detection is the default, you can still manage device IDs manually:

Check Current Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Possible Responses:

No Device ID (Legacy Mode - Before Login):

json
{
  "deviceId": "",
  "source": "none",
  "isConfigured": false
}

Device ID Set (After Login):

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Environment Variable:

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "environment",
  "isConfigured": true
}

Set Device ID Manually ​

bash
curl -X PUT http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "628123456789@s.whatsapp.net"
  }'

Validation Rules:

  • Must end with @s.whatsapp.net
  • Cannot be empty or null
  • Must be a string

Response:

json
{
  "success": true,
  "message": "Device ID updated successfully",
  "deviceId": "628123456789@s.whatsapp.net"
}

Error Response (Invalid Format):

json
{
  "statusCode": 400,
  "message": "Device ID must end with @s.whatsapp.net",
  "error": "Bad Request"
}

Clear Device ID ​

To remove the device ID from the database (falls back to environment variable or legacy mode):

bash
curl -X DELETE http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "success": true,
  "message": "Device ID cleared from database"
}

Logout and Reconnect ​

Logout ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/logout \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Logged out successfully"
}

Important: After logout, the device ID is automatically cleared from the database.

Automatic Device Re-registration ​

When you call GET /status after logout, the system will:

  1. Auto-register a new device with GoWA (calls POST /devices)
  2. Save the new device ID to the database
  3. Return the new device ID in the status response

Example Status Response After Logout:

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"
json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "device_id": "628123456789@s.whatsapp.net",
    "is_connected": true,
    "is_logged_in": false
  }
}

Server Logs:

[WhatsAppService] No device ID found. Auto-registering a new device...
[WhatsAppService] Device added: 628123456789@s.whatsapp.net
[WhatsAppDeviceService] Device ID updated in database: 628123456789@s.whatsapp.net

This new device ID is now ready for login. Simply call GET /login to generate a QR code for this device.

Reconnect ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/reconnect \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Reconnection initiated"
}

Troubleshooting ​

Status Returns 404 DEVICE_NOT_FOUND ​

Error:

json
{
  "code": "DEVICE_NOT_FOUND",
  "message": "device not found; create a device first from /api/devices or provide a valid X-Device-Id"
}

Cause: This error occurs when using GoWA multi-device endpoints (/devices/*) with an unregistered device ID.

Solution: For simplified setup, use legacy endpoints (/app/*) instead:

  • ✅ Use: GET /admin/whatsapp/login
  • ✅ Use: GET /admin/whatsapp/status
  • ❌ Avoid: GET /admin/whatsapp/devices/{id}/login (requires device registration)

Status Shows Not Logged In ​

Response:

json
{
  "results": {
    "is_connected": false,
    "is_logged_in": false
  }
}

Solution: Complete the login flow:

  1. Get QR code: GET /admin/whatsapp/login
  2. Scan with WhatsApp phone
  3. Check status again after 10 seconds

Device ID Not Updating After Login ​

Check 1: Verify Login Success

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response (After Login):

json
{
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Check 2: Check Database Configuration

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Solution: If device_id is empty or status shows device_id, try:

  1. Logout and login again
  2. Check server logs for errors during device ID update
  3. Verify database connection is working

QR Code Not Working ​

Common Issues:

  1. QR Code Expired: QR codes expire after 30 seconds. Request a new one.
  2. Already Logged In: Check if device is already logged in.
  3. GoWA Service Down: Verify GoWA service is running.

Solution:

bash
# Check if already logged in
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

# If not logged in, request new QR code
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

503 Service Unavailable ​

This means the GoWA service is not running or not accessible:

Check 1: GoWA Service Status

bash
# Check if GoWA is running
docker ps | grep whatsapp

# Or check service health
curl http://localhost:3000/app/status

Check 2: Environment Variables

bash
# Check WHATSAPP_BASE_URL
echo $WHATSAPP_BASE_URL

Expected: http://whatsapp:3000 (or your GoWA service URL)

Check 3: Network Connectivity

bash
# Test connectivity to GoWA
curl http://localhost:3000/app/status

401 Unauthorized ​

Check that:

  1. Your JWT token is valid
  2. Token has not expired
  3. User has admin role

Verify Token:

bash
# Decode JWT token (requires jq)
echo YOUR_TOKEN | jq -R 'split(".") | .[1] | @base64d | fromjson'

Check User Role:

json
{
  "sub": "user-id",
  "role": "ADMIN",
  "exp": 1738363200
}

Device Not Sending Messages ​

Check 1: Connection Status

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected:

json
{
  "results": {
    "is_connected": true,
    "is_logged_in": true
  }
}

Check 2: Phone Number Format Ensure phone numbers are in international format without + or 00:

  • ✅ Correct: 628123456789
  • ❌ Wrong: +628123456789
  • ❌ Wrong: 00628123456789
  • ❌ Wrong: 08123456789

Check 3: GoWA Logs

bash
# Check GoWA service logs
docker logs whatsapp

Understanding GoWA Modes ​

Legacy Mode (No Device ID) ​

  • When: No device ID configured (database or environment)
  • Behavior: No X-Device-Id header sent to GoWA
  • Endpoints: Uses /app/* endpoints
  • Use Case: Initial setup, single-device scenarios

Multi-Device Mode (With Device ID) ​

  • When: Device ID is configured in database or environment
  • Behavior: X-Device-Id header sent with all requests
  • Endpoints: Can use both /app/* and /devices/{id}/* endpoints
  • Use Case: Multiple devices, explicit device selection

Mode Transition ​

┌──────────────────┐
│ Legacy Mode      │
│ (No Device ID)   │
└────────┬─────────┘
         │ Login + Scan
         ▼
┌──────────────────┐
│ Auto Detection   │
│ (Fetch Phone #)  │
└────────┬─────────┘
         │ Device ID Set
         ▼
┌──────────────────┐
│ Multi-Device     │
│ (With Device ID) │
└────────┬─────────┘
         │ Logout
         ▼
┌──────────────────┐
│ Legacy Mode      │
│ (No Device ID)   │
└────────┬─────────┘
         │ GET /status
         ▼
┌──────────────────┐
│ Auto-Register    │
│ (New Device ID)  │
└────────┬─────────┘
         │ Device ID Set
         ▼
┌──────────────────┐
│ Multi-Device     │
│ (With Device ID) │
└──────────────────┘

Key Points:

  • After logout, the system returns to Legacy Mode
  • Calling GET /status auto-registers a new device
  • The cycle repeats with a fresh device ID for each logout/login sequence

Best Practices ​

  1. Use Auto-Detection: Let the system auto-detect device ID. Only manually configure if you have a specific reason.

  2. Check Status Before Sending: Verify connection status before sending messages to avoid failures.

  3. Handle Legacy Mode: Your code should handle both legacy mode (no device ID) and multi-device mode (with device ID).

  4. Use Database Storage: Device IDs are automatically stored in the database for persistence across restarts.

  5. Monitor Server Logs: Watch for auto-detection logs to confirm device ID transitions:

    [WhatsAppService] Updating device ID from {none/temp} to {real}

  6. URL Encode Device IDs: When using device IDs in URLs, always URL encode the @ symbol:

    • Raw: 628123456789@s.whatsapp.net
    • Encoded: 628123456789%40s.whatsapp.net

  7. Clear Configuration After Testing: Use DELETE to clean up test data when switching between test and production environments.

  8. Graceful Error Handling: Always handle 503 errors gracefully, as GoWA may be temporarily unavailable.

  9. Prefer Legacy Endpoints: For single-device setups, use /app/* endpoints instead of /devices/{id}/* to avoid device registration complexity.

  10. Test After Login: Always test message sending after completing the login flow to verify everything works.

  11. Auto-Registration After Logout: After logout, the system automatically registers a new device on the next status check. No manual device registration is required.

  12. Fresh Device Per Session: Each logout/login cycle creates a new device registration, ensuring clean session isolation.
