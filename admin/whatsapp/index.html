WhatsApp Management API ​

Admin API documentation for managing WhatsApp devices.

Overview ​

The WhatsApp Management API provides a simplified experience for sending WhatsApp messages:

  • Zero Configuration: No manual device setup required - uses GoWA legacy mode
  • QR Code Login: Simple scan-and-go authentication flow
  • Auto Phone Number Detection: Device ID automatically updates to your phone number after login
  • Message Sending: Send text, images, files, audio, and video messages
  • Database Persistence: Device configuration survives server restarts

Architecture ​

┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Admin Client  │────▶│   HHR API        │────▶│   GoWA Service  │
│                 │     │  (NestJS)        │     │  (WhatsApp)     │
└─────────────────┘     └──────────────────┘     └─────────────────┘
                               │
                               ▼
                        ┌──────────────┐
                        │   Database   │
                        │ (Device ID)  │
                        └──────────────┘

Authentication ​

All endpoints require:

  • Admin Role: UserRole.ADMIN
  • JWT Token: Valid Bearer token in Authorization header
http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Base URL ​

/api/v1/admin/whatsapp

Quick Start ​

The simplified workflow requires no manual device ID management:

1. Start the Server ​

The server starts in GoWA legacy mode - no device ID required.

Server Log:

[WhatsAppService] No device configured. Using GoWA legacy mode (no device ID required).
[WhatsAppService] Device ID will be automatically set to phone number after successful login.

2. Get QR Code ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "QR code generated",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-b0b7bb43-9a22-455a-814f-5a225c743310.png",
    "qr_duration": 30
  }
}

3. Scan QR Code ​

Open WhatsApp on your phone:

  1. Go to Settings → Linked Devices
  2. Tap Link a Device
  3. Scan the QR code from the response

4. Auto Device ID Update ​

After successful login, the system automatically:

  • Fetches your actual phone number from WhatsApp status
  • Updates the device ID to your phone number
  • Persists the change in the database

Server Log:

[WhatsAppService] Updating device ID from (none) to 628123456789@s.whatsapp.net
[WhatsAppDeviceService] Device ID updated in database: 628123456789@s.whatsapp.net

5. Send Messages ​

bash
curl -X POST http://localhost:3000/api/v1/whatsapp/send/message \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "message": "Hello from HHR API!"
  }'

Device ID Formats ​

No Device ID (Legacy Mode) ​

When no device ID is configured, the system uses GoWA's legacy mode:

  • No X-Device-Id header sent to GoWA
  • GoWA uses its default device
  • After login, device ID is automatically set to phone number

Real Device ID (Phone Number) ​

Format: {phone_number}@s.whatsapp.net

Example: 628123456789@s.whatsapp.net

  • Phone Number: 10-15 digits, country code + number
  • Suffix: Must end with @s.whatsapp.net
  • Persistent: Stored in database after login
  • Used: Sent as X-Device-Id header for all subsequent API calls

Priority Order ​

Device ID resolution follows this priority:

  1. Database Cache (1-minute TTL)
  2. Database (SystemConfiguration table)
  3. Environment Variable (WHATSAPP_DEVICE_ID)
  4. None (GoWA legacy mode - no device ID)

How It Works ​

Initial State (No Device ID) ​

┌─────────────────────────────────────┐
│ Database: Empty                     │
│ Environment: Not set                │
│ Mode: GoWA Legacy (no X-Device-Id)  │
└─────────────────────────────────────┘

After Login (Device ID Set) ​

┌─────────────────────────────────────┐
│ Database: 628123456789@s.whatsapp.net│
│ X-Device-Id: Sent with all requests │
│ Mode: Multi-device (explicit)       │
└─────────────────────────────────────┘

Manual Device ID Configuration (Optional) ​

While automatic detection is the default, you can still manually configure the device ID:

Check Current Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Possible Responses:

No Device ID (Legacy Mode):

json
{
  "deviceId": "",
  "source": "none",
  "isConfigured": false
}

Device ID Set (After Login):

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Set Device ID Manually ​

bash
curl -X PUT http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "628123456789@s.whatsapp.net"
  }'

Response:

json
{
  "success": true,
  "message": "Device ID updated successfully",
  "deviceId": "628123456789@s.whatsapp.net"
}

Validation Rules:

  • Must end with @s.whatsapp.net
  • Cannot be empty or null
  • Must be a string

Clear Device ID ​

bash
curl -X DELETE http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "success": true,
  "message": "Device ID cleared from database"
}

Pairing Code Login (Alternative to QR) ​

If you prefer to use a pairing code instead of QR code:

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/login-with-code?phone=628123456789" \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Then on your phone:

  1. Open WhatsApp
  2. Go to Settings → Linked Devices
  3. Tap Link with phone number instead
  4. Enter the pairing code

Connection Status ​

Check the current connection status:

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Response (Before Login - Legacy Mode):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": false,
    "is_logged_in": false
  }
}

Response (After Login - Device ID Set):

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Logout and Reconnect ​

Logout ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/logout \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Logged out successfully"
}

Important: After logout, the device ID is automatically cleared from the database. The next call to GET /status will auto-register a new device and return a fresh device ID ready for login.

Reconnect ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/reconnect \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Reconnection initiated"
}
