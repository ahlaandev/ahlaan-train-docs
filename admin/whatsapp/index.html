WhatsApp Management API ​

Admin API documentation for managing WhatsApp devices.

Overview ​

The WhatsApp Management API provides a simplified experience for sending WhatsApp messages:

  • Zero Configuration: No manual device setup required - uses GoWA legacy mode
  • QR Code Login: Simple scan-and-go authentication flow
  • Environment-Configured Device ID: Device ID is read from the WHATSAPP_DEVICE_ID environment variable
  • Message Sending: Send text, images, files, audio, and video messages

Architecture ​

┌─────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│   Admin Client  │────▶│   HHR API        │────▶│   GoWA Service  │
│                 │     │  (NestJS)        │     │  (WhatsApp)     │
└─────────────────┘     └──────────────────┘     └─────────────────┘
                               │
                               ▼
                        ┌──────────────────────┐
                        │   Environment        │
                        │ (WHATSAPP_DEVICE_ID) │
                        └──────────────────────┘

Authentication ​

All endpoints require:

  • Admin Role: UserRole.ADMIN
  • JWT Token: Valid Bearer token in Authorization header
http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

Base URL ​

/api/v1/admin/whatsapp

Quick Start ​

The simplified workflow requires no manual device ID management:

1. Start the Server ​

The server starts in GoWA legacy mode - no device ID required.

Server Log:

[WhatsAppService] No device configured. Using GoWA legacy mode (no device ID required).
[WhatsAppService] Device ID will be automatically set to phone number after successful login.

2. Get QR Code ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "code": "SUCCESS",
  "message": "QR code generated",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-b0b7bb43-9a22-455a-814f-5a225c743310.png",
    "qr_duration": 30
  }
}

3. Scan QR Code ​

Open WhatsApp on your phone:

  1. Go to Settings → Linked Devices
  2. Tap Link a Device
  3. Scan the QR code from the response

4. Send Messages ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/sandbox/send-message \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "message": "Hello from HHR API!"
  }'

Device ID Formats ​

No Device ID (Legacy Mode) ​

When no device ID is configured, the system uses GoWA's legacy mode:

  • No X-Device-Id header sent to GoWA
  • GoWA uses its default device
  • After login, device ID is automatically set to phone number

Real Device ID (Phone Number) ​

Format: {phone_number}@s.whatsapp.net

Example: 628123456789@s.whatsapp.net

  • Phone Number: 10-15 digits, country code + number
  • Suffix: Must end with @s.whatsapp.net
  • Configured via: WHATSAPP_DEVICE_ID environment variable
  • Used: Sent as X-Device-Id header for all subsequent API calls

Device ID Source ​

The device ID is read from the WHATSAPP_DEVICE_ID environment variable only. There is no database or cache layer — the value is resolved directly from the environment at request time and is read-only via GET /config/device-id.

How It Works ​

No Device ID Configured (Legacy Mode) ​

┌─────────────────────────────────────┐
│ Environment: WHATSAPP_DEVICE_ID unset│
│ Mode: GoWA Legacy (no X-Device-Id)  │
└─────────────────────────────────────┘

Device ID Configured (Environment) ​

┌─────────────────────────────────────┐
│ Environment: WHATSAPP_DEVICE_ID set  │
│ X-Device-Id: Sent with all requests │
│ Mode: Multi-device (explicit)       │
└─────────────────────────────────────┘

Device ID Configuration (Read-Only) ​

The device ID is configured via the WHATSAPP_DEVICE_ID environment variable. It cannot be changed through the API — you can only read the current value:

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "deviceId": "ahlaan-train",
  "source": "environment",
  "isConfigured": true
}

The source is always environment. To change the device ID, update the WHATSAPP_DEVICE_ID environment variable and restart the service.

Pairing Code Login (Alternative to QR) ​

If you prefer to use a pairing code instead of QR code:

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/login-with-code?phone=628123456789" \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Then on your phone:

  1. Open WhatsApp
  2. Go to Settings → Linked Devices
  3. Tap Link with phone number instead
  4. Enter the pairing code

Connection Status ​

Check the current connection status:

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Response (Before Login - Legacy Mode):

json
{
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": false,
    "is_logged_in": false
  }
}

Response (After Login - Device ID Set):

json
{
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Logout and Reconnect ​

Logout ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/logout \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "code": "SUCCESS",
  "message": "Logged out successfully"
}

Reconnect ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/reconnect \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "code": "SUCCESS",
  "message": "Reconnection initiated"
}
