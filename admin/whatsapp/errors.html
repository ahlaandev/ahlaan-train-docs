Error Codes ​

Reference for error responses and troubleshooting.

HTTP Status Codes ​

StatusDescription
200Success
201Resource created
400Bad Request - Invalid input
401Unauthorized - Missing or invalid token
403Forbidden - Insufficient permissions
404Not Found - Resource doesn't exist
422Unprocessable Entity - Validation failed
500Internal Server Error
503Service Unavailable - GoWA service not reachable

Error Response Format ​

All errors follow this format:

json
{
  "statusCode": 400,
  "message": "Detailed error message",
  "error": "Bad Request"
}

Common Errors ​

400 Bad Request ​

json
{
  "statusCode": 400,
  "message": "Detailed validation message",
  "error": "Bad Request"
}

Cause: Request body validation failed (e.g. invalid phone or message on a sandbox send endpoint).

Solution: Ensure the request body matches the expected schema.

401 Unauthorized ​

json
{
  "statusCode": 401,
  "message": "Unauthorized",
  "error": "Unauthorized"
}

Cause: Missing or invalid JWT token.

Solution:

  1. Include Authorization: Bearer <token> header
  2. Verify token is valid and not expired
  3. Check token format

403 Forbidden ​

json
{
  "statusCode": 403,
  "message": "Forbidden resource",
  "error": "Forbidden"
}

Cause: User doesn't have admin role.

Solution:

  1. Verify user has UserRole.ADMIN
  2. Check role assignments in database

404 Not Found ​

json
{
  "statusCode": 404,
  "message": "Device not found",
  "error": "Not Found"
}

Cause: Device doesn't exist in GoWA service.

Solution:

  1. Verify device ID is correct
  2. Check if device was removed
  3. List all devices to find correct ID

422 Unprocessable Entity ​

json
{
  "statusCode": 422,
  "message": "Validation failed",
  "error": "Unprocessable Entity"
}

Cause: Request body validation failed.

Solution: Check request body matches expected schema.

500 Internal Server Error ​

json
{
  "statusCode": 500,
  "message": "Internal server error",
  "error": "Internal Server Error"
}

Cause: Unexpected server error.

Solution:

  1. Check server logs for details
  2. Verify database connection
  3. Check GoWA service status

503 Service Unavailable ​

json
{
  "statusCode": 503,
  "message": "GoWA service is not available or does not support device management",
  "error": "Service Unavailable"
}

Cause: GoWA service is not running or not accessible.

Solution:

  1. Check if GoWA service is running
  2. Verify WHATSAPP_BASE_URL environment variable
  3. Test network connectivity to GoWA
  4. Check GoWA service logs

WhatsApp-Specific Error Codes ​

DEVICE_ID_REQUIRED ​

json
{
  "statusCode": 400,
  "code": "DEVICE_ID_REQUIRED",
  "message": "Device ID is required for this operation"
}

Cause: Operation requires a configured device ID.

Solution: Set the WHATSAPP_DEVICE_ID environment variable and restart the service. The device ID is environment-configured only and read-only via GET /config/device-id.

ALREADY_LOGGED_IN ​

json
{
  "code": "ALREADY_LOGGED_IN",
  "message": "Already logged in - session is active"
}

Note: This is informational, not an error. The device is already logged in.

DEVICE_NOT_FOUND ​

json
{
  "statusCode": 404,
  "code": "DEVICE_NOT_FOUND",
  "message": "Device not found in GoWA service"
}

Cause: Device ID doesn't exist in GoWA.

Solution: Verify device ID or add device to GoWA first.

Troubleshooting Steps ​

1. Check Authentication ​

bash
# Test token validity
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

2. Verify Configuration ​

bash
# Check current device ID configuration
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

3. Test GoWA Connectivity ​

GET /admin/whatsapp/devices is an internal endpoint (excluded from the public API docs) that can be used to test GoWA connectivity:

bash
# List devices to test GoWA connection (internal endpoint)
curl http://localhost:3000/api/v1/admin/whatsapp/devices \
  -H "Authorization: Bearer YOUR_TOKEN"

4. Check Server Logs ​

bash
# View recent server logs
tail -50 server-log.txt | grep -i whatsapp

5. Verify Environment Variables ​

bash
# Check WhatsApp configuration
grep WHATSAPP .env

Expected variables:

  • WHATSAPP_BASE_URL
  • WHATSAPP_BASIC_AUTH
  • WHATSAPP_DEVICE_ID (optional)

Error Prevention ​

  1. URL Encode Device IDs: Always encode @ as %40
  2. Validate Format: Check device ID format before sending
  3. Check Permissions: Verify admin role before testing
  4. Test GoWA First: Ensure GoWA is running before device operations
  5. Handle 503: Always handle service unavailable gracefully

Getting Help ​

If you encounter an error not listed here:

  1. Check server logs for detailed error messages
  2. Verify all prerequisites are met
  3. Test with feature tests: bun test feature-tests/whatsapp-management/
  4. Check GoWA service documentation
  5. Review environment configuration
