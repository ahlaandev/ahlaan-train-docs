Bank Exchange Rate (Kurs Scraper) ​

The kurs scraper reads bank exchange rates and pushes them to this endpoint. The API records them in the BankExchangeRateQuote table. Admins can read the recorded rates (see Admin read endpoints).

The landing search prices IDR from one of these series when its pricing configuration chooses BANK_RATE. Bookings and invoices keep using the rates of the Exchange Rate module.

Quick Overview ​

FeatureDescription
PurposeRecord bank rates pushed by the kurs scraper
Authenticationx-api-key header, checked against SCRAPER_ACCESS_API_KEY
EndpointPOST /api/v1/scraper/bank-exchange-rates
Admin readGET /api/v1/admin/bank-exchange-rates/series and GET /api/v1/admin/bank-exchange-rates
Batch size1 to 50 rates per request
Rate Limit100 req/min
StoragebuyRate and sellRate as DECIMAL(15,6)

Authentication ​

http
x-api-key: <scraper-access-key>

A missing or wrong key gets 401 Unauthorized. When SCRAPER_ACCESS_API_KEY is not set on the server, every request gets 401.

Series ​

Each (bankCode, rateType, baseCcy, quoteCcy) is its own series, recorded separately from the others.

Request ​

Endpoint: POST /api/v1/scraper/bank-exchange-rates

The body is an array:

json
[
  {
    "bankCode": "CIMB",
    "rateType": "E_RATE",
    "baseCcy": "SAR",
    "quoteCcy": "IDR",
    "buy": 4784,
    "sell": 4801,
    "bankAsOf": "2026-10-21T12:45:00+07:00",
    "scrapedAt": "2026-10-21T06:01:47.119Z",
    "sourceUrl": "https://bank.example.com/kurs"
  }
]
FieldRequiredRule
bankCodeYes^[A-Z0-9_]{2,32}$
rateTypeYes^[A-Z0-9_]{2,32}$
baseCcyYes^[A-Z]{3}$
quoteCcyYes^[A-Z]{3}$; rates are quoteCcy units per 1 baseCcy
buyYesNumber greater than 0, at most 6 decimal places, at most 999999999.999999
sellYesSame rule as buy
bankAsOfNoISO 8601 date-time with a time zone (Z or +07:00), the time the bank states for the rate
scrapedAtYesISO 8601 date-time with a time zone (Z or +07:00), the time the scraper read the rate
sourceUrlNohttp or https URL, at most 2048 characters

Unknown fields are removed, not rejected.

What the API does with each item ​

Items are handled in array order.

  1. sell below buy: skipped with reason sell must be greater than or equal to buy. The other items are still handled.
  2. buy and sell equal the latest recorded rate of the same series: skipped with reason Same buy and sell as the previous recorded rate. That recorded row's lastScrapedAt moves to this item's scrapedAt, but only forward: an older push that arrives late does not move it back.
  3. Otherwise: recorded as a new row, with lastScrapedAt equal to scrapedAt.

A rate recorded earlier in the same request counts as the latest rate of its series, so a repeat later in the same array is skipped.

Two requests that arrive at the same time can both record the same rate.

Response ​

201 Created

json
{
  "created": [
    {
      "id": "0199f0a2-7c3e-7b1a-9f00-000000000001",
      "bankCode": "CIMB",
      "rateType": "E_RATE",
      "baseCcy": "SAR",
      "quoteCcy": "IDR",
      "buy": 4784,
      "sell": 4801,
      "bankAsOf": "2026-10-21T05:45:00.000Z",
      "scrapedAt": "2026-10-21T06:01:47.119Z",
      "lastScrapedAt": "2026-10-21T06:01:47.119Z",
      "sourceUrl": "https://bank.example.com/kurs",
      "createdAt": "2026-10-21T06:01:48.002Z"
    }
  ],
  "skipped": [
    {
      "index": 1,
      "bankCode": "CIMB",
      "rateType": "TT_COUNTER",
      "baseCcy": "SAR",
      "quoteCcy": "IDR",
      "reason": "Same buy and sell as the previous recorded rate"
    }
  ]
}

index is the item's position in the request array. bankAsOf and sourceUrl are left out of a created row when the item did not send them.

Errors

StatusWhen
400The body is not an array (Validation failed (parsable array expected)), the array is empty, it has more than 50 items, or an item breaks a field rule. One invalid item rejects the whole request, and the message does not say which index failed.
401Missing or wrong x-api-key
429More than 100 requests in a minute, where rate limiting is enabled

Admin read endpoints ​

Admin + Access Role: either exchange-rates:read or landing-route-price:read is enough. Bearer token, like the other admin endpoints.

Latest rate of each series ​

Endpoint: GET /api/v1/admin/bank-exchange-rates/series?baseCcy=SAR&quoteCcy=IDR

Query ParameterRequiredRule
baseCcyNo^[A-Z]{3}$
quoteCcyNo^[A-Z]{3}$

Response: 200 OK, an array with the newest recorded row of each series, ordered by bankCode, rateType, baseCcy, quoteCcy. Each item has the shape of an item in created above. Without a query, every series is listed.

Rows of one series ​

Endpoint: GET /api/v1/admin/bank-exchange-rates?bankCode=BCA&rateType=E_RATE&page=1&limit=20

Query ParameterRequiredRule
bankCodeYes^[A-Z0-9_]{2,32}$
rateTypeYes^[A-Z0-9_]{2,32}$
baseCcyNo^[A-Z]{3}$, default SAR
quoteCcyNo^[A-Z]{3}$, default IDR
pageNoWhole number from 1, default 1
limitNoWhole number from 1 to 100, default 20

Response: 200 OK, newest first:

json
{
  "data": [
    {
      "id": "0199f0a2-7c3e-7b1a-9f00-000000000002",
      "bankCode": "BCA",
      "rateType": "E_RATE",
      "baseCcy": "SAR",
      "quoteCcy": "IDR",
      "buy": 4784,
      "sell": 4801,
      "scrapedAt": "2026-10-21T06:01:47.119Z",
      "lastScrapedAt": "2026-10-21T07:01:47.119Z",
      "createdAt": "2026-10-21T06:01:48.002Z"
    }
  ],
  "meta": { "total": 1, "page": 1, "limit": 20, "totalPages": 1 }
}

A series with no row returns an empty data and "total": 0, not 404.

Errors

StatusWhen
400A query value breaks its rule, or bankCode or rateType is missing on the rows endpoint
401Missing or invalid token
403Not an admin, or neither permission
