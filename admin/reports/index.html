Admin Financial Reports ​

Hub index for the admin-facing reporting endpoints. There is no unified /admin/reports controller in this API — reporting is split across the per-domain admin controllers and is documented here as a single index for discoverability.

Overview ​

The platform currently exposes two admin report endpoints, one per actively used financial domain:

DomainEndpointDetail Doc
PaymentGET /api/v1/admin/payment/reportsdocs/admin/payment
InvoiceGET /api/v1/admin/invoice/reportsdocs/admin/invoice

B2B organization self-service reports. Separately, B2B organization users can pull reports scoped to their own organization under GET /api/v1/reports/organization/* (dashboard, revenue, transactions, wallets, refunds, tax). These are role B2B, not ADMIN, and are not part of this admin hub — see Organization Reports.

Future / not yet in use. The codebase also ships GET /api/v1/admin/wallet/reports (wallet balance + activity aggregates) and GET /api/v1/admin/refunds/reports (refund volume + policy breakdown). Wallets and refunds are not part of the current operational surface, so these endpoints are intentionally omitted from this hub. When those features are turned on, document them here using the same template as Payment and Invoice below; sources to start from are src/modules/wallet/admin-wallet.controller.ts + src/modules/wallet/dto/wallet-report.dto.ts and src/modules/refund/admin-refund.controller.ts + src/modules/refund/dto/refund-report.dto.ts. The refund controller is versioned (@Controller({ path: 'admin/refunds', version: '1' })), so its routes live under /api/v1/ like the rest of the API.

Authentication ​

Both endpoints share the same auth contract:

  • JWT bearer token in the Authorization header
  • ADMIN role on the user (@Roles(UserRole.ADMIN) + RolesGuard)
http
Authorization: Bearer <admin-jwt>

Non-admin tokens receive 403 Forbidden. Missing/expired tokens receive 401 Unauthorized.

Common Query Parameters ​

Both report endpoints accept the same date-range and grouping parameters:

ParameterTypeDefaultDescription
presetenumTHIS_MONTHOne of TODAY, YESTERDAY, LAST_7_DAYS, LAST_30_DAYS, THIS_MONTH, LAST_MONTH, CUSTOM
fromISO date—Start date (YYYY-MM-DD). Required when preset=CUSTOM.
toISO date—End date (YYYY-MM-DD). Required when preset=CUSTOM.
groupByenumdayChart bucket size: day, week, month

Preset semantics (computed in getDateRange() on each controller):

PresetRange
TODAY[start of today, now]
YESTERDAY[start of yesterday, start of today]
LAST_7_DAYS[today − 7 days, now]
LAST_30_DAYS[today − 30 days, now]
THIS_MONTH[1st of this month, now]
LAST_MONTH[1st of last month, last day of last month]
CUSTOM[from, to]

When preset=CUSTOM is supplied without both from and to, the controller silently falls back to the default THIS_MONTH window — supply both dates explicitly.

Common Response Envelope ​

Both responses share this top-level shape:

json
{
  "periodFrom": "2026-04-01",
  "periodTo": "2026-04-30",
  "summary": { /* domain-specific KPIs */ },
  "chartData": [ /* time-series buckets, one per groupBy unit */ ],
  /* domain-specific breakdowns (byMethod, byStatus, ...) */
}

periodFrom and periodTo are formatted as YYYY-MM-DD (the date portion of the resolved range). All monetary fields are reported in SAR unless the per-domain doc says otherwise.

These endpoints do not paginate — they always return the full aggregate for the requested window.

Payment Report ​

http
GET /api/v1/admin/payment/reports?preset=THIS_MONTH&groupBy=day

Source: src/modules/payment/admin-payment.controller.ts (getPaymentReports)

Extra filters:

ParameterTypeDescription
paymentMethodstringFilter by method (e.g. QRIS, WALLET, BANK_TRANSFER); exact match
statusstringFilter by status (e.g. PAID, PENDING, FAILED, EXPIRED); exact match
sourceenumFilter by related service: BOOKING (any OTA-derived — STANDARD + BLOCKSEAT), STANDARD (native ota/* only — the "OTA" service bucket), BLOCKSEAT (blockseat-* wholesale only), or CUSTOM_BOOKING. Omit for all. Does not affect webhookStats.

Response highlights:

  • summary — totalPayments, totalAmount, successRate, avgAmount, plus a webhookStats block (total, success, failed, paymentNotFound, successRate). webhookStats is gateway-level and is not narrowed by source.
  • chartData[] — { date, count, amount, successCount } per bucket
  • byMethod[] — { method, count, amount, successRate }
  • byStatus[] — { status, count, amount }

Use this for payment-gateway performance, webhook delivery health, and method-mix analysis. Full schema and curl examples live in docs/admin/payment/index.md → Reports.

Invoice Report ​

http
GET /api/v1/admin/invoice/reports?preset=THIS_MONTH&groupBy=day

Source: src/modules/invoice/admin-invoice.controller.ts (getInvoiceReports)

Extra filters:

ParameterTypeDescription
organizationIdUUIDRestrict to a single organization's invoices (max 36 chars)
statusenumFilter by invoice status (InvoiceStatus: PAID, ISSUED, OVERDUE, VOID, …); exact match, validated against the enum — an invalid value returns 400, not 500
sourceenumFilter by related service: BOOKING (any OTA-derived — STANDARD + BLOCKSEAT), STANDARD (native ota/* only — the "OTA" service bucket), BLOCKSEAT (blockseat-* wholesale only), or CUSTOM_BOOKING. Omit for all. Standalone invoices (e.g. wallet top-ups) appear only when source is omitted.
partnerIdstringRestrict to a single partner's invoices (via the booking relation). Composes with a variant source filter (STANDARD/BLOCKSEAT) instead of overriding it.

Response highlights:

  • summary — totalInvoices, totalAmount, paidAmount, pendingAmount (ISSUED + OVERDUE), voidedAmount, avgPaymentTimeDays, collectionRate
  • chartData[] — { date, count, amount, paidAmount } per bucket
  • byStatus[] — { status, count, amount }

Currency note: invoices are dual-currency. Reports aggregate the SAR source-of-truth fields (baseTotalAmountSAR, totalPaidSAR) so totals stay comparable across mixed-currency invoices. Full schema and curl examples live in docs/admin/invoice/index.md → Reports.

Error Responses ​

json
// 400 — invalid date string (fails @IsDateString validation)
{
  "statusCode": 400,
  "message": ["from must be a valid ISO 8601 date string"],
  "error": "Bad Request"
}
json
// 401 — missing or invalid JWT
{ "statusCode": 401, "message": "Unauthorized" }
json
// 403 — token is valid but the user is not an admin
{ "statusCode": 403, "message": "Forbidden resource", "error": "Forbidden" }

Examples ​

Today's payments, grouped by day ​

bash
curl -X GET "https://<host>/api/v1/admin/payment/reports?preset=TODAY" \
  -H "Authorization: Bearer <admin-jwt>"

Last 30 days of QRIS payments ​

bash
curl -X GET "https://<host>/api/v1/admin/payment/reports?preset=LAST_30_DAYS&paymentMethod=QRIS" \
  -H "Authorization: Bearer <admin-jwt>"

OTA-only payments this month ​

bash
curl -X GET "https://<host>/api/v1/admin/payment/reports?preset=THIS_MONTH&source=BOOKING" \
  -H "Authorization: Bearer <admin-jwt>"

Custom-booking-only invoices this month ​

bash
curl -X GET "https://<host>/api/v1/admin/invoice/reports?preset=THIS_MONTH&source=CUSTOM_BOOKING" \
  -H "Authorization: Bearer <admin-jwt>"

One organization's invoices for the month ​

bash
curl -X GET "https://<host>/api/v1/admin/invoice/reports?preset=THIS_MONTH&organizationId=<org-uuid>" \
  -H "Authorization: Bearer <admin-jwt>"

Custom date range ​

bash
curl -X GET "https://<host>/api/v1/admin/invoice/reports?preset=CUSTOM&from=2026-01-01&to=2026-04-30&groupBy=month" \
  -H "Authorization: Bearer <admin-jwt>"
