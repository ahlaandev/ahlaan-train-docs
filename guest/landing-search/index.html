Landing Search (WhatsApp Landing Page) ​

Public train search for the WhatsApp landing page. No login.

  • Train times and free seats come from the live supplier search.
  • The adult price per seat of each class comes only from the admin-set landing route prices. Child and infant prices are an admin-set percentage of it.
  • Nothing in the answer can be used to book. The customer orders over WhatsApp, using the number in whatsapp.

Endpoint ​

POST /api/v1/landing/search — no Authorization header. Limited to 20 requests per minute when the server's rate limiting is on.

Request ​

json
{
  "origin": "MKX",
  "destination": "DMX",
  "departureDate": "2026-11-01",
  "tripType": "ROUND_TRIP",
  "returnDate": "2026-11-03",
  "passengerQuantities": { "adults": 2, "children": 1, "infants": 0 }
}
FieldTypeRequiredDescription
originstring✅DMX, MKX, JED, JXD or KCX
destinationstring✅Same list, different from origin
departureDatestring✅YYYY-MM-DD, not in the past
tripTypeenum✅ONE_WAY or ROUND_TRIP
returnDatestringROUND_TRIP onlyYYYY-MM-DD, on or after departureDate. Ignored for ONE_WAY
passengerQuantitiesobject✅{ adults, children, infants }, whole numbers, same shape as ota/search

Passenger rules:

  • adults at least 1; children and infants at least 0.
  • infants cannot be more than adults.
  • No maximum group size.
  • Infants take no seat. A class needs adults + children free seats.

FieldDescription
whatsapp.phoneNumber to show
whatsapp.phoneDigitsDigits only, for a https://wa.me/<phoneDigits> link
passengersThe passengerQuantities from the request
outbound / returnTrains for each leg. return is null for ONE_WAY
departureDateTime / arrivalDateTimeThe supplier's value, passed through unchanged, for example 2026-11-01T08:00:00.000+03:00
durationMinutesMinutes between departure and arrival; null if the supplier times cannot be read
pricePerSeat.SARThe admin-set adult price
pricePerSeat.IDRSAR × the SAR to IDR sell rate chosen for the landing page (a bank rate or the global rate, see IDR rate source), rounded the same way as ota/search; 0 when no rate is set
pricePerSeat.USDSAR converted the same way as ota/search
ptcFareBreakdownSame shape as ota/search: one row per passenger type (ADT, CHD, INF) whose quantity is above 0. perPassenger is the price of one passenger, subtotal is perPassenger.SAR × quantity; IDR and USD are each converted from their SAR figure. Tax is always 0
finalPricePrice for the group on this leg: the sum of the subtotal.SAR rows, then converted to IDR and USD from that SAR total, like finalPrice in ota/search. A round trip costs the outbound finalPrice plus the return finalPrice

Child and infant prices ​

  • Adult: the admin-set priceSAR, unchanged.
  • Child: priceSAR × childPricePercentage / 100, rounded down to a whole riyal.
  • Infant: priceSAR × infantPricePercentage / 100, rounded down to a whole riyal.
  • With no landing pricing configuration, child is 70% and infant is 0%.

Example: adult 99.50 SAR, child 75%, infant 10% → child 74 SAR (74.625 rounded down), infant 9 SAR (9.95 rounded down).

What is left out ​

  • A class with no active admin price for that direction.
  • A class with fewer free seats than adults + children.
  • A train with no class left after the two rules above.

An empty outbound list means no train can be offered for that day. It is still 200 OK:

json
{
  "whatsapp": { "phone": "+62 811 8809 1910", "phoneDigits": "6281188091910" },
  "passengers": { "adults": 1, "children": 0, "infants": 1 },
  "outbound": [],
  "return": null
}

Errors ​

StatusWhen
400Unknown station, same origin and destination, bad or past date, ROUND_TRIP without returnDate, missing or invalid passengerQuantities, more infants than adults
429More than 20 searches a minute (when rate limiting is on)
502The supplier search failed. Try again shortly

Field errors are listed in message and again, with the field path, in context.fields. Example, a past date and adults: 0:

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": ["departureDate should not be in the past", "adults must not be less than 1"],
  "code": "INPUT_VALIDATION",
  "category": "VALIDATION",
  "retryable": false,
  "context": {
    "fields": [
      { "path": "departureDate", "constraint": "isNotPastDate", "message": "departureDate should not be in the past" },
      { "path": "passengerQuantities.adults", "constraint": "min", "message": "adults must not be less than 1" }
    ]
  }
}

Other message values from the same kind of error:

Requestmessage
No passengerQuantities["passengerQuantities should not be null or undefined"]
ROUND_TRIP without returnDate["returnDate is required for a ROUND_TRIP search", "returnDate must be a valid ISO 8601 date string", "returnDate must be YYYY-MM-DD"]

More infants than adults is checked after the fields, so message is a single string and there is no context:

json
{
  "statusCode": 400,
  "error": "Bad Request",
  "message": "Number of infants cannot exceed number of adults",
  "code": "UNCODED",
  "category": "VALIDATION",
  "retryable": false
}

502 carries the message "Train schedules are unavailable right now. Please try again shortly.".

Exchange rate ​

GET /api/v1/landing/exchange-rate — no body, no Authorization header. Limited to 60 requests per minute when the server's rate limiting is on.

Returns the SAR to IDR rate the search above prices IDR with right now. A widget that shows the rate of the day ("Kurs hari ini") should read this endpoint, not GET /api/v1/exchange-rate/current, so it shows the rate behind pricePerSeat.IDR.

Response — 200 OK ​

FieldTypeDescription
currencystringAlways SAR: the rate is IDR per 1 SAR
IDRnumber | nullThe sell rate the landing search uses now; null when no rate exists at all
sourceenumBANK_RATE or GLOBAL_RATE: the rate actually used. A BANK_RATE setting whose bank series has no recorded rate reports GLOBAL_RATE
bankCodestring | nullThe bank series, for example BCA; null with GLOBAL_RATE
rateTypestring | nullThe bank series rate type, for example E_RATE; null with GLOBAL_RATE
asOfstring | nullISO 8601 time. BANK_RATE: the time the bank states for the rate, or when it was scraped if the bank states none. GLOBAL_RATE: when the global rate was fetched. null when no rate exists

With the BCA e-rate sell rate chosen:

json
{
  "currency": "SAR",
  "IDR": 4841.42,
  "source": "BANK_RATE",
  "bankCode": "BCA",
  "rateType": "E_RATE",
  "asOf": "2026-10-21T09:25:00.000Z"
}

A seat of 220 SAR then shows pricePerSeat.IDR 1065113: 220 × 4841.42 = 1065112.4, rounded up.

pricePerSeat.IDR is SAR × IDR rounded up to a whole rupiah, so pricePerSeat.IDR / pricePerSeat.SAR is not exactly IDR. The rate and the search are separate requests: a new rate between the two calls can make them differ for that moment.

Errors ​

StatusWhen
429More than 60 calls a minute (when rate limiting is on)

Freshness ​

Train times and seats are cached for up to 120 seconds per route, dates and trip type, whatever the passenger counts; an empty supplier answer is not cached. Prices, the child and infant percentages, and the exchange rate are read on every request, so an admin change shows on the next search.
