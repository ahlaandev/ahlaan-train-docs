Usage Guide ​

Common workflows and examples for managing WhatsApp devices.

Complete Workflow: Configure and Test Device ​

Follow these steps to configure a new WhatsApp device:

Step 1: Add Device to GoWA ​

bash
curl -X POST http://localhost:3000/api/v1/admin/whatsapp/devices \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "device_id": "628123456789@s.whatsapp.net"
}

Step 2: Configure Device ID in Database ​

bash
curl -X PUT http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "628123456789@s.whatsapp.net"
  }'

Step 3: Verify Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response:

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Step 4: Check Device Status ​

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789%40s.whatsapp.net/status" \
  -H "Authorization: Bearer YOUR_TOKEN"

Step 5: Login Device (QR Code) ​

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789%40s.whatsapp.net/login" \
  -H "Authorization: Bearer YOUR_TOKEN"

Step 6: Verify Login Status ​

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789%40s.whatsapp.net/status" \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response:

json
{
  "connected": true,
  "loggedIn": true
}

Switch Between Devices ​

To switch from one device to another:

bash
# Switch to different device
curl -X PUT http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "628987654321@s.whatsapp.net"
  }'

The system will immediately use the new device for all WhatsApp operations.

Clear Device Configuration ​

To remove the device ID from the database (falls back to environment variable):

bash
curl -X DELETE http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

List All Devices ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/devices \
  -H "Authorization: Bearer YOUR_TOKEN"

Remove a Device ​

bash
curl -X POST "http://localhost:3000/api/v1/admin/whatsapp/devices/628123456789%40s.whatsapp.net/remove" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json"

Using with Postman ​

Environment Setup ​

Create a Postman environment with these variables:

VariableValue
base_urlhttp://localhost:3000/api/v1
admin_tokenYour JWT token

Example Requests ​

Set Device ID:

PUT {{base_url}}/admin/whatsapp/config/device-id
Authorization: Bearer {{admin_token}}
Content-Type: application/json

{
  "deviceId": "628123456789@s.whatsapp.net"
}

Get Device Status:

GET {{base_url}}/admin/whatsapp/devices/628123456789%40s.whatsapp.net/status
Authorization: Bearer {{admin_token}}

Troubleshooting ​

Device ID Not Working ​

  1. Check Format: Ensure device ID ends with @s.whatsapp.net
  2. Check Configuration: Verify the device ID is set correctly
  3. Check Source: Determine if the ID is from database or environment
bash
# Check current configuration
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Device Not Connecting ​

  1. Verify GoWA Service: Ensure GoWA is running and accessible
  2. Check Device Status: Use the status endpoint to see current state
  3. Reconnect: Try the reconnect endpoint
bash
# Check status
curl "http://localhost:3000/api/v1/admin/whatsapp/devices/DEVICE_ID/status" \
  -H "Authorization: Bearer YOUR_TOKEN"

# Reconnect
curl -X POST "http://localhost:3000/api/v1/admin/whatsapp/devices/DEVICE_ID/reconnect" \
  -H "Authorization: Bearer YOUR_TOKEN"

503 Service Unavailable ​

This means the GoWA service is not running or not accessible:

  1. Check GoWA service status
  2. Verify WHATSAPP_BASE_URL in environment variables
  3. Check network connectivity to GoWA service

401 Unauthorized ​

Check that:

  1. Your JWT token is valid
  2. Token has not expired
  3. User has admin role
bash
# Verify token
echo YOUR_TOKEN | jq -R 'split(".") | .[1] | @base64d | fromjson'

Best Practices ​

  1. Always URL Encode Device IDs: Device IDs contain @ which must be encoded as %40
  2. Clear Configuration After Testing: Use DELETE to clean up test data
  3. Check Status Before Operations: Verify device state before login/logout
  4. Handle 503 Gracefully: GoWA may be temporarily unavailable
  5. Use Database Storage: Prefer database over environment variable for production
