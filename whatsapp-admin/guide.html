Usage Guide ​

Common workflows and examples for managing WhatsApp devices with simplified auto-generated device IDs.

Complete Workflow: Auto-Setup and Login ​

The simplified workflow requires no manual device management:

Step 1: Start the Server ​

The server automatically generates a temporary device ID on startup if none is configured.

Server Startup Logs:

[WhatsAppInitializer] Initializing WhatsApp device...
[WhatsAppDeviceService] No device configured. Auto-generated temporary device ID: 01912345-6789-4abc-9def-0123456789ab@device.local
[WhatsAppService] Device configured from none: 01912345-6789-4abc-9def-0123456789ab@device.local

Step 2: Get QR Code ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "QR code generated successfully",
  "results": {
    "qr_link": "http://localhost:3000/statics/images/qrcode/scan-qr-abc123.png",
    "qr_duration": 30
  }
}

Step 3: Scan QR Code ​

On your WhatsApp phone:

  1. Open Settings
  2. Tap Linked Devices
  3. Tap Link a Device
  4. Scan the QR code from qr_link

Step 4: Automatic Device ID Update ​

After successful login, the system automatically updates the device ID:

Server Logs After Login:

[WhatsAppService] Updating device ID from 01912345-6789-4abc-9def-0123456789ab@device.local to 628123456789@s.whatsapp.net
[WhatsAppDeviceService] Device ID updated in database: 628123456789@s.whatsapp.net

Step 5: Verify Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Step 6: Check Connection Status ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Connection status retrieved",
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Pairing Code Login (Alternative) ​

If you prefer to use a pairing code instead of scanning a QR code:

Step 1: Request Pairing Code ​

bash
curl "http://localhost:3000/api/v1/admin/whatsapp/login-with-code?phone=628123456789" \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "status": 200,
  "code": "SUCCESS",
  "message": "Pairing code generated",
  "results": {
    "pairing_code": "K241-9XYZ"
  }
}

Step 2: Enter Pairing Code ​

On your WhatsApp phone:

  1. Open Settings
  2. Tap Linked Devices
  3. Tap Link with phone number instead
  4. Enter the pairing code: K241-9XYZ

Step 3: Automatic Device ID Update ​

Same as QR code flow - device ID automatically updates to your phone number.

Sending Messages ​

Once logged in, you can send various types of messages:

Text Message ​

bash
curl -X POST http://localhost:3000/api/v1/whatsapp/send/message \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "message": "Hello from HHR API!"
  }'

Image Message ​

bash
curl -X POST http://localhost:3000/api/v1/whatsapp/send/image \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "image": "https://example.com/image.jpg",
    "caption": "Check this out!"
  }'

File Message ​

bash
curl -X POST http://localhost:3000/api/v1/whatsapp/send/file \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "628987654321",
    "file": "https://example.com/document.pdf",
    "filename": "Document.pdf"
  }'

Manual Device ID Management (Optional) ​

While auto-generation is the default, you can still manage device IDs manually:

Check Current Configuration ​

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Possible Responses:

Temporary Device ID (Not Logged In):

json
{
  "deviceId": "01912345-6789-4abc-9def-0123456789ab@device.local",
  "source": "database",
  "isConfigured": true
}

Real Device ID (Logged In):

json
{
  "deviceId": "628123456789@s.whatsapp.net",
  "source": "database",
  "isConfigured": true
}

Not Configured:

json
{
  "deviceId": "",
  "source": "none",
  "isConfigured": false
}

Set Device ID Manually ​

bash
curl -X PUT http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "deviceId": "628123456789@s.whatsapp.net"
  }'

Validation Rules:

  • Must end with @s.whatsapp.net
  • Cannot be empty or null
  • Must be a string

Response:

json
{
  "success": true,
  "message": "Device ID updated successfully",
  "deviceId": "628123456789@s.whatsapp.net"
}

Error Response (Invalid Format):

json
{
  "statusCode": 400,
  "message": "Device ID must end with @s.whatsapp.net",
  "error": "Bad Request"
}

Clear Device ID ​

To remove the device ID from the database (falls back to environment variable or auto-generates new one):

bash
curl -X DELETE http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Response:

json
{
  "success": true,
  "message": "Device ID cleared from database"
}

Troubleshooting ​

Server Starts with Temporary Device ID ​

Log:

[WhatsAppService] No device configured. Auto-generated temporary device ID: 01912345-6789-4abc-9def-0123456789ab@device.local

Solution: This is expected behavior. The temporary device ID will be automatically replaced with your phone number after you scan the QR code or enter the pairing code.

Device ID Not Updating After Login ​

Check 1: Verify Login Success

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected Response:

json
{
  "results": {
    "is_connected": true,
    "is_logged_in": true,
    "device_id": "628123456789@s.whatsapp.net"
  }
}

Check 2: Check Database Configuration

bash
curl http://localhost:3000/api/v1/admin/whatsapp/config/device-id \
  -H "Authorization: Bearer YOUR_TOKEN"

Solution: If device_id still shows @device.local, try:

  1. Logout and login again
  2. Check server logs for errors during device ID update
  3. Verify database connection is working

QR Code Not Working ​

Common Issues:

  1. QR Code Expired: QR codes expire after 30 seconds. Request a new one.
  2. Already Logged In: Check if device is already logged in.
  3. GoWA Service Down: Verify GoWA service is running.

Solution:

bash
# Check if already logged in
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

# If not logged in, request new QR code
curl http://localhost:3000/api/v1/admin/whatsapp/login \
  -H "Authorization: Bearer YOUR_TOKEN"

503 Service Unavailable ​

This means the GoWA service is not running or not accessible:

Check 1: GoWA Service Status

bash
# Check if GoWA is running
docker ps | grep whatsapp

# Or check service health
curl http://localhost:3000/app/status

Check 2: Environment Variables

bash
# Check WHATSAPP_BASE_URL
echo $WHATSAPP_BASE_URL

Expected: http://whatsapp:3000 (or your GoWA service URL)

Check 3: Network Connectivity

bash
# Test connectivity to GoWA
curl http://localhost:3000/app/status

401 Unauthorized ​

Check that:

  1. Your JWT token is valid
  2. Token has not expired
  3. User has admin role

Verify Token:

bash
# Decode JWT token (requires jq)
echo YOUR_TOKEN | jq -R 'split(".") | .[1] | @base64d | fromjson'

Check User Role:

json
{
  "sub": "user-id",
  "role": "ADMIN",
  "exp": 1738363200
}

Device Not Sending Messages ​

Check 1: Connection Status

bash
curl http://localhost:3000/api/v1/admin/whatsapp/status \
  -H "Authorization: Bearer YOUR_TOKEN"

Expected:

json
{
  "results": {
    "is_connected": true,
    "is_logged_in": true
  }
}

Check 2: Phone Number Format Ensure phone numbers are in international format without + or 00:

  • ✅ Correct: 628123456789
  • ❌ Wrong: +628123456789
  • ❌ Wrong: 00628123456789
  • ❌ Wrong: 08123456789

Check 3: GoWA Logs

bash
# Check GoWA service logs
docker logs whatsapp

Best Practices ​

  1. Use Auto-Generation: Let the system auto-generate device IDs. Only manually configure if you have a specific reason.

  2. Check Status Before Sending: Verify connection status before sending messages to avoid failures.

  3. Handle Temporary Device IDs: Your code should handle both temporary (@device.local) and real (@s.whatsapp.net) device IDs gracefully.

  4. Use Database Storage: Device IDs are automatically stored in the database for persistence across restarts.

  5. Monitor Server Logs: Watch for auto-update logs to confirm device ID transitions:

    [WhatsAppService] Updating device ID from {temp} to {real}

  6. URL Encode Device IDs: When using device IDs in URLs, always URL encode the @ symbol:

    • Raw: 628123456789@s.whatsapp.net
    • Encoded: 628123456789%40s.whatsapp.net

  7. Clear Configuration After Testing: Use DELETE to clean up test data when switching between test and production environments.

  8. Graceful Error Handling: Always handle 503 errors gracefully, as GoWA may be temporarily unavailable.
